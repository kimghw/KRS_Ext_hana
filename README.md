# KRS WORKSPACE (크롬·엣지 확장)

eclass 회의실 현황을 사이드 패널에서 **시간 단위**로 보고, 빈 칸을 끌어서 범위를 고른 뒤 바로 예약합니다.

## 설치

누가 쓰든 절차가 같습니다. **코드에 고칠 개인 값은 없습니다** — 아래 [사람마다 다른 것](#사람마다-다른-것--따로-설정하지-않습니다) 참고.

1. 받기 — `git clone https://github.com/kimghw/meeting_room` (또는 ZIP 으로 받아 풀기)
2. 주소창에 크롬은 `chrome://extensions`, 엣지는 `edge://extensions` → 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드** → 받은 폴더 선택
4. 같은 브라우저에서 **eclass 에 로그인** — 확장은 이 브라우저의 로그인을 그대로 씁니다
5. 툴바의 확장 아이콘을 누르면 사이드 패널이 열립니다

크롬과 엣지 어느 쪽이든 같은 폴더를 그대로 불러옵니다. 확장 코드는 두 브라우저에 공통이고,
다른 것은 아래 다리 등록에서 레지스트리 키 위치와 브라우저를 완전히 끄는 방법뿐입니다.

2번의 "압축해제된 확장 로드" 클릭은 프로그램으로 대신할 수 없습니다. 크로미엄이 일부러 막아 둔 자리라
(기본 프로필은 디버그 포트를 받지 않고, 명령줄이나 CDP 로 올린 확장은 그 세션에만 남습니다) 사람이 한 번 눌러야 합니다.
클릭 없이 쓰고 싶으면 엣지 한정으로 `/bridge shortcut` 이 전용 프로필을 `--load-extension` 으로 띄우는
바로가기를 만들어 줍니다. 대신 그 프로필에서 eclass 에 따로 로그인해야 합니다.

여기까지면 조회·예약·취소·수정·차량 신청이 다 됩니다. **말로 찾기만 추가 설정이 필요합니다** —
아래 [로컬 CLI 연결](#로컬-cli-연결-권장-키-불필요)을 하거나 `설정 및 연결` 에 API 키를 넣으세요.

### 사람마다 다른 것 — 따로 설정하지 않습니다

| 무엇 | 어디서 오나 |
|---|---|
| 로그인한 사람 | 각자 브라우저의 eclass 로그인 |
| 예약자·운전자 이름, 부서, 사번 | 사이트가 신청 폼에 로그인한 사람으로 미리 채워 둔 값을 읽습니다 (`readFormWho`) |
| `내 이름` (내 예약 찾기용) | 이 확장으로 처음 예약할 때 자동으로 기억합니다. `설정 및 연결` 에서 직접 넣어도 됩니다 |
| 확장 ID | 받은 폴더 경로에서 브라우저가 정합니다(크롬·엣지 같은 값). 다리를 등록할 때만 필요합니다 |
| Claude | 각자 PC 에 로그인된 `claude`, 또는 각자의 API 키 |

설정과 활동 로그는 브라우저 프로필마다 따로 저장돼 다른 사람과 섞이지 않습니다.
크롬과 엣지에 둘 다 불러오면 프로필이 달라 설정도 따로 갑니다.

## 사용

- 위쪽에서 날짜를 고르거나 `◀ ▶` 로 하루씩 이동합니다.
- `시간 08 ~ 20` 으로 화면에 보여줄 업무 시간대를 조절합니다(설정은 저장됩니다).
- 격자에서 **연한 초록 = 예약 가능**, **회색 = 사용 중**입니다. 칸에 마우스를 올리면 누가 쓰는지 보입니다.
- 빈 칸을 **클릭하거나 끌어서** 1시간 단위로 범위를 고릅니다. **여러 번 클릭하면 선택이 쌓여** 여러 건을 한꺼번에 예약할 수 있고, 고른 칸을 다시 누르면 빠집니다.
- 아래 예약 폼에 회의주제를 넣고 **예약하기**를 누릅니다.
- `↻` 로 새로고침, `자동` 을 켜면 60초마다 다시 조회합니다. 마지막 조회 시각이 오른쪽에 표시됩니다.
- 왼쪽 위 **지역 버튼**(부산/서울)을 누르면 지역이 바뀝니다. 회의실 목록이 지역별로 다릅니다.
- 회의실 이름 옆 배지는 좌석 수입니다. **내 예약**은 칸 아래 노란 밑줄로 표시됩니다.
- 줄 차례는 사이트 드롭다운이 아니라 **자주 쓰는 순서**입니다 — `제1~제5회의실`, `미팅룸1·2`,
  나머지 순이고, `부산지부 · 스마트홀 · 오션홀` 은 맨 아래에 **접혀** 있습니다.
  접힌 줄의 손잡이를 누르면 펼쳐지고, 그 상태는 저장됩니다(`src/roomorder.js`).
- `회의실 현황` 옆에는 **지금 보고 있는 날짜**와 그날 예약 건수가 붙습니다(회의실 수가 아닙니다 — 날짜가 바뀌어도 그대로라 배지로 쓸모가 없었습니다).
- 상단 **내 예약** 탭에서 내가 예약한 회의실·차량을 한 목록으로 봅니다(아래 참고).
- 패널을 열지 않아도 **e-Class 홈 맨 위에 "WORKSPACE" 카드**가 붙습니다 — 내 회의실·차량 예약과 출장·외근·휴가(아래 [홈 화면의 WORKSPACE 카드](#홈-화면의-workspace-카드)).
- **오늘부터 한 달치를 회의실·차량 모두 하루에 한 번 미리 훑어 둡니다**(아래 참고). 그날 처음 패널을
  열 때 훑고, 그 뒤로는 닫았다 열어도 다시 훑지 않습니다.
  상태줄 아래 가는 막대가 진행 상황이고, 다 되면 `한 달 준비됨 · 9/16~10/15 · 동기화 09:12` 로 바뀝니다.
  막대를 누르면 처음부터 다시 훑습니다.

### 차량 이용

상단 **차량** 탭에서 날짜별 차량 이용 현황을 보고, **신청·취소·수정까지** 합니다.
회의실과 똑같이 빈 칸을 끌어 고르고 아래 폼을 채워 보냅니다.

차량 폼은 회의실과 요구하는 것이 다릅니다. **행선지가 필수이고 사용목적은 아닙니다**
(사이트의 `fnSaveCheck()` 가 실제로 그렇게 막습니다 — 목록 페이지에 죽은 채 남아 있는
`fnSave()` 는 사용목적도 요구하지만 진짜 신청 폼은 보지 않습니다). 사이트보다 엄격하게
막으면 사이트에서는 되는 일이 이 확장에서만 안 되므로, 사이트가 막는 것만 막습니다.

신청 폼은 목록이 아니라 **팝업 페이지**(`Admin_View_New.aspx?CARIDX=..&SDATE=..`)에 있고,
**차량은 폼에서 고르는 게 아니라 주소가 정합니다**(`DDL_CARNAME` 옵션이 하나뿐입니다).

**사이트가 예약 버튼에서 막는 차량은 확장도 보내지 않습니다.** 목록의 예약 버튼은 `fnview(주소, 차량번호, 날짜, checkAuth, checkAuth2)` 를 부르고,
그 함수가 폼을 열기 전에 가릅니다 — 화면의 스크립트에 적힌 `exceptCarSeqNp`(임원용·사전 협의 차량)는 `checkAuth` 가 `False` 면
"…에게 문의 바랍니다" 를 띄우고 **폼을 열지 않고**, `exceptCarSeqNp2`(서울본부 공용 차량)는 `checkAuth2` 가 `False` 면 같습니다.
확장은 그 버튼을 거치지 않고 신청 폼 주소를 바로 열기 때문에, 이 막음을 따로 읽어 두지 않으면 **사이트에서는 안 되는 신청이 확장에서는 나갑니다**
(2026-10-03 검토에서 찾았습니다 — 폼 주소는 막힌 차량도 그대로 열립니다). 그래서 목록을 읽을 때마다 두 목록과 줄마다의 권한 값을 같이 읽어
차량에 `blocked`(사이트의 문구)를 달고(`src/rentcar.js` 의 `parseCarGate`), 신청(`reserveCar`)은 막힌 차량이면 폼을 열지도 않고 그 말을 돌려줍니다.
차량 옆의 안내(`[임원용 차량]` · `[서울본부 전용 차량]` …)도 `note` 로 읽습니다. 막는 목록을 못 읽는 화면이면 막지 않습니다(없는 것을 지어내지 않습니다).

격자에서 고르는 칸은 하루 안의 시간입니다. **여러 날에 걸친 신청** 은 근태 탭의 출장 폼에서 `차량 조회` 로 찾은
빈 차량을 눌렀을 때 나갑니다 — 차량 탭으로 오지 않고 근태 폼에서 바로 신청하며, 종료 날짜를 같이 보냅니다
(아래 [근태 탭](#근태-탭)의 "차량 조회").

차량 표는 로그인해야 볼 수 있어 컬럼 위치를 박아두지 않고, **행 내용을 보고**
어느 칸이 시간이고 어느 칸이 차량인지 찾아냅니다(`src/grid.js`).
이 감지기는 회의실 실제 페이지로 검증했습니다 — 지역·회의실·시간·상태 네 컬럼을
정확히 찾아냅니다. 차량 화면에서 못 찾으면 **확인 불가**로 표시되고,
그때는 차량 탭에서 `설정 및 연결 → 페이지 구조 캡처`를 눌러 전달해 주시면 맞추겠습니다.

### 예약 수정

사이트에는 **예약을 옮기는 기능이 없습니다.** 그래서 이 확장의 수정은
**기존 건을 취소하고 새 시간으로 다시 넣는 것**이고, 실패하면 되돌립니다.
현황 탭에서 `수정` 을 누르면 그 날짜로 이동하고, 격자에서 새 시간을 고르면 실행됩니다.

되돌리기에는 규칙이 있습니다(`src/modify.js`).

| 어디서 실패했나 | 무엇을 하나 |
|---|---|
| 취소가 실패 | 기존 예약을 건드리지 않았으므로 그대로 둡니다. 새 예약을 **시도하지 않습니다.** |
| 취소 성공 → 새 예약 성공 | 끝. |
| 취소 성공 → 새 예약이 **제출조차 못 됨** | 원래 시간으로 되살립니다. |
| 취소 성공 → 새 예약이 **제출은 됐는데 확인이 안 됨** | **되돌리지 않습니다.** |

마지막 칸이 중요합니다. 저장이 실제로 됐을 수도 있어서, 원래 예약을 되살리면 **이중 예약**이
됩니다. 사람이 한 번 보면 끝나는 일이지만, 이중 예약은 남이 못 쓰는 칸을 말없이 하나 더
만듭니다. 그래서 이때는 "모르겠으니 사이트에서 확인해 달라"고 말합니다.

차량을 수정할 때는 **행선지를 다시 입력**해야 합니다. 차량 목록의 상세 행에는 사용목적만
남고 행선지가 없어서, 되돌릴 때 쓸 값을 읽어올 데가 없습니다. 화면에도 그렇게 적어 둡니다.

`이어붙이기`(내 예약 옆 빈 칸을 골라 시간을 늘리는 것)도 같은 엔진을 씁니다. **회의실에서만** 됩니다 —
차량은 되살릴 값(행선지·원래 구간)을 다 알 수 없어 버튼이 뜨지 않습니다.

수정·취소가 사이트로 가는 길은 **그 건의 종류가 정합니다**(`src/runners.js`). 일을 시작할 때 실행자 하나를 집어
끝까지 그것만 쓰므로, 도는 중에 탭을 옮겨도 남은 단계가 다른 종류의 사이트로 가지 않습니다. 그리고

- **여러 날에 걸친 차량 이용은 여기서 수정하지 않습니다.** 다시 넣는 길이 하루 안의 시간만 다뤄서, 되살릴 때
  원래 기간을 잃습니다. 사이트에서 고쳐 달라고 말합니다(취소는 됩니다).
- **차량은 방금 다시 읽은 화면에서 그 건을 찾았을 때만 취소를 보냅니다.** 차량의 취소 버튼은 행 자리로 지은
  이름이라, 미리 담아 둔 것을 쓰면 그 사이 신청이 늘거나 줄었을 때 다른 건을 가리킬 수 있습니다.
  회의실은 예약 번호로 지우므로 담아 둔 것을 써도 같은 건입니다.

### 현황 (WORKSPACE 현황)

탭 이름은 **현황** 입니다(예전의 "내 예약"). 내 회의실·차량 예약에 더해 **근태(출장·휴가·외근 …)도 같은 목록에 카드로** 섞여 날짜순으로 보입니다.
근태 카드는 HR 문서함에서 읽은 것 가운데 결재요청·결재완료인 건이고(임시저장·반려·회수는 뺌), 누르면 근태 탭으로 갑니다 —
취소·변경은 거기서 합니다. 예약처럼 **하루에 한 번** 읽어 두고, ↻ 를 누르거나 근태 탭에서 무엇인가 올린 뒤에 다시 읽습니다.
HR 을 읽지 못해도 예약 목록은 그대로 보이고, 한 줄 요약에 "근태는 읽지 못했습니다"라고 적습니다.


상단 **현황** 탭은 고른 날부터 며칠간(7·14·21일 / **한 달**, 기본값)을 훑어 **내가 예약한
회의실과 차량을 한 목록으로** 보여줍니다. 한 줄을 누르면 그 날짜의 회의실/차량 화면으로 갑니다.
지역은 가리지 않습니다 — 부산·서울 예약이 모두 나옵니다.

한 달은 하루에 한 번 미리 훑어 두므로 보통은 기다릴 것이 없습니다. 아직 훑는 중이면
**담기는 대로 목록이 차오릅니다** — 서른 날을 다 기다린 뒤에야 첫 줄이 보이면
아무것도 안 하는 것처럼 보이기 때문입니다.

**훑기는 하루에 한 번뿐입니다.** 오늘 읽어 둔 날은 탭을 옮기거나 패널을 닫았다 열어도 다시 읽지
않고, 상태줄 오른쪽에 `동기화 09:12` 처럼 **언제 읽은 것인지**를 적습니다(기간 안에서 가장 오래전에
읽은 날 기준). 회의실·차량 탭에서 조회한 날과 이 확장으로 예약·취소한 날은 그때 새로 담기므로
목록에 바로 반영됩니다. 사이트에서 직접 바꾼 것처럼 그 밖의 변화는 **`↻` 를 눌러야** 다시 훑습니다.

내 것인지 어떻게 아느냐가 문제입니다. **사이트는 로그인한 사람이 누구인지 화면 어디에도
적어주지 않습니다**(숨은 입력칸에도 없습니다). 그래서 신호 셋을 합쳐 보고, 항목 오른쪽에
무엇을 보고 그렇게 판단했는지 적어 둡니다.

| 근거 | 뜻 |
|---|---|
| (표시 없음) | 사이트가 그 줄에 **수정·삭제 버튼**을 붙였습니다. 본인 건에만 붙으므로 가장 확실합니다. |
| `이름 일치` | 예약자 이름이 `설정 및 연결` 에 넣어둔 **내 이름**과 같습니다. |
| `내가 넣음` | 이 확장으로 넣어 **확인까지 끝난** 예약 기록과 겹칩니다. |

이름은 이 확장으로 예약이 확인되면 그 줄의 예약자 이름으로 **자동으로 채워집니다**
(같은 회의주제일 때만 — 제출 사이에 남이 같은 칸을 채간 경우와 섞이면 안 되므로).
직접 넣어도 됩니다. 이름을 알면 회의실·차량 격자의 **내 예약 밑줄**도 같이 정확해집니다.

훑는 동안 못 읽은 날은 **결과에서 빼고 몇 일이 빠졌는지 말합니다.** 못 읽은 날을 조용히
넘기면 "내 예약이 없다"는 거짓말이 되기 때문입니다. 아무것도 못 찾았을 때도
"없습니다"가 아니라 **왜 못 찾았을 수 있는지**를 함께 보여줍니다.

훑기는 **하루에 요청 한 번**입니다. `loadDay` 는 날짜마다 페이지를 새로 받지만,
`src/site.js` 의 `scanDays` 와 `src/rentcar.js` 의 `scanCarDays` 는 **한 번 연 화면을 들고
날짜만 옮깁니다.** 월 달력에 0건이라고 찍힌 날은 아예 옮기지 않고 건너뜁니다 —
사이트가 스스로 센 숫자라 믿을 수 있습니다. 단 **건수가 찍히는 건 펼쳐 놓은 달의 칸뿐**입니다.
달력이 앞뒤 줄을 채우려고 같이 그리는 이웃 달 칸(9월 화면의 10/1~10)에는 건수가 없으므로
그 날은 "모름"이지 0건이 아니고, 반드시 옮겨서 읽습니다. 옮길 때는 달력이 펼칠 달(`CAL_MAIN_AD`
초점일)도 같이 보내 다음 달 달력이 따라오게 합니다 — 그래야 10월 날짜도 건수와 대조할 수 있습니다.

### 홈 화면의 WORKSPACE 카드

e-Class 홈(`eClassVer4/Home/Index`)을 열면 **맨 위, Popup Notice 카드 바로 위에 "WORKSPACE" 카드**가
붙습니다(예전 이름은 "내 예약"). 쓸지 말지는 패널 머리(새로고침 버튼 옆)의 **`홈에 WORKSPACE` 체크박스**로 정합니다(기본 켬).
끄면 열려 있는 홈에서도 카드가 곧바로 사라지고, 훑던 중이면 다음 날짜로 넘어가기 전에 멈춥니다.
다시 켜면 홈을 새로고침하지 않아도 카드가 돌아옵니다. 패널을 열지 않아도 **오늘부터** 한 달(패널 현황 탭의 기간 설정과 같은 값) 안의
내 회의실·차량 예약과 **근태(출장·외근·휴가)** 가 한 목록에 날짜순으로 보입니다. 출장만은 **다녀온 뒤 4주까지** 남아 `다녀온 출장` 이라고
적힙니다 — 다녀온 출장의 여비를 정산해야 해서 눈에 띄어야 합니다(패널 현황 탭도 같은 규칙입니다). 남는 것은 **여비 정산이 덜 끝난 출장만**입니다
(2026-10-04 사용자 지정, `src/settling.js`) — **사후정산을 완료했거나 증빙을 담당자에게 보낸 출장은 올리지 않고**, 몇 주까지 남길지(**4주 · 8주 · 안 봄**)는
근태 탭 신청 내역의 달력 버튼에서 고른 값을 따릅니다(고르면 열려 있는 홈에도 곧 반영됩니다). 여비계산서가 어느 단계인지 알면 옆에 적습니다
(`다녀온 출장 · 사전정산 완료`). 단계는 eclass 의 여비계산서 목록에서 읽는데, **다녀온 출장이 남아 있을 때만, 하루에 한 번** 읽어 담아 둡니다
(`tripStages` — 근태 탭이 목록을 읽으면 거기에 덧대므로 패널에서 정산을 마치면 카드도 따라옵니다). 못 읽으면 그 출장은 그대로 보입니다 — 모르는 것을 끝났다고 가리지 않습니다.
그 밖에 더 볼 일이 없는 출장은 그 줄 끝의
**눈 아이콘**으로 한 건씩 숨기고(숨긴 것은 기억됩니다), 숨긴 것이 있으면 머리 줄에 **전체 보기** 눈 아이콘이 나옵니다 — 켜면 숨긴 출장까지 흐리게 보이고
(다시 누르면 가립니다), 그 줄의 눈 아이콘으로 그 출장을 다시 늘 보이게 합니다. 한 건을 누르면 사이드 패널이
**그 날짜·종류로** 열리고(근태 건은 근태 탭으로), 머리 줄 오른쪽의 패널 아이콘(`예약 패널 열기`)은 그냥 패널을
엽니다. 예약·취소·수정과 근태 올리기·거둬들이기는 패널에서 합니다 — 카드는 보기 전용입니다.

콘텐츠 스크립트(`home.js` → `src/home.js`)가 페이지 안에서 직접 훑습니다. 훑기와 내 예약 판정은 패널과
같은 모듈(`src/site.js`·`src/rentcar.js`·`src/mine.js`)이고, 페이지와 같은 출처라 쿠키가 그냥 실립니다.

겉모습은 홈에 같이 뜨는 **R&D ERP 현황 카드와 같은 모양**입니다(`src/homecard.js` — 접수 미확인 공문 카드와 공용).
위쪽 남색 띠와 옅은 남색 머리 줄, 굵은 남색 제목, 건수 칩(`회의실 1` `차량 0` `출장 1` `외근 0` `휴가 2` — 0 보다
크면 파랗게), 점이 붙은 읽은 때, 오른쪽의 아이콘 버튼(새로고침 · 예약 패널 열기)입니다. 버튼이 무엇인지는 툴팁이 말합니다.
머리 줄에는 **건수와 읽은 때만** 둡니다 — "없습니다·찾지 못했습니다" 같은 말은 적지 않고 칩이 0 이라고 말합니다.
아직 못 읽었으면 칩은 숫자 대신 줄표(`–`)입니다(예약은 한 날도 못 읽었을 때, 근태는 HR 을 못 읽었을 때).

**근태 건**은 예약과 같은 모양의 한 칸입니다 — 종류 딱지(출장·외근·교육·연차·체력단련), 날짜와 시각(시각이 없는
휴가는 전일·오전·오후), 결재 상태(결재요청·결재완료), 내용 한 줄. 칩은 셋으로 묶어 셉니다(`src/attend.js` 의
`PLAN_GROUPS`): **출장**(국내·해외출장), **외근**(외근과 같은 신청서로 올리는 교육), **휴가**(연차·체력단련).
외출·건강검진·유연근무는 홈 카드에 올리지 않습니다(패널의 현황 탭에는 다 보입니다). 올려 두었거나 결재가 끝난
건만이고, 임시저장·반려·회수는 잡힌 일정이 아니라 뺍니다.

근태는 HR(`hr.krs.co.kr`, 다른 출처)에 있어 콘텐츠 스크립트가 직접 읽지 못합니다. 카드는 **배경(서비스 워커)에게
읽어 달라고** 하고(`hrPlans` 메시지), 배경은 패널의 현황 탭과 같은 길(`src/plans.js` → `src/hr.js` 의 문서함 조회)로
읽어 같은 자리(`chrome.storage` 의 `hrPlans`)에 담습니다. 그래서 **하루에 한 번**이고, 패널이 오늘 읽어 두었으면
홈은 HR 을 열지 않습니다(반대도 같습니다). 읽을 때는 뒷전에 HR 작업 탭이 잠깐 열렸다 닫힙니다 — 패널이 쓰던
작업 탭이 있으면 그것을 빌려 쓰고 닫지 않습니다. 패널에서 근태를 올리거나 거둬들이면 패널이 담아 둔 것을 지우고,
열려 있는 홈은 그것을 보고 근태만 다시 읽습니다(예약은 다시 훑지 않습니다). HR 을 읽지 못하면 예약 목록은 그대로
보이고, 경고 줄에 "근태(출장·외근·휴가)는 읽지 못했습니다"와 까닭을 적습니다.

홈은 하루에도 여러 번 여는 화면이라 그때마다 서른 날을 두드리지 않습니다. 훑은 결과는 `chrome.storage`
(`homeMine`)에 담기고, 카드 머리에 **`9/17~10/16 · 3분 전 읽음`** 처럼 언제 읽은 것인지 늘 적습니다.
다시 훑는 때는 **셋뿐**입니다.

- **하루에 한 번** — 오늘 읽어 둔 것이 없을 때. 오늘 읽은 것이 있으면 몇 시간이 지났어도 그대로 보여줍니다.
  일부를 못 읽은 결과도 마찬가지라, 그때는 경고 줄을 보고 `새로고침` 을 누릅니다.
- **이 확장으로 예약이 바뀌었을 때** — 패널에서 예약·취소·수정이 끝나면(성공이든 실패든) 패널이 이 캐시를
  지우고, 열려 있는 홈 탭은 그것을 보고 다시 훑습니다. 탭이 안 보이면 다시 보일 때.
- **`새로고침` 을 눌렀을 때** — 담아 둔 것을 먼저 보여준 채 다시 훑어 바꿔 끼웁니다. 근태도 HR 에서 다시 읽습니다.

패널의 `내 이름`·기간 설정을 바꾸면 담아 둔 것이 그 조건과 맞지 않게 되므로 이때도 다시 훑습니다.
사이트에서 직접 넣거나 지운 예약은 다음 날, 또는 `새로고침` 을 눌러야 반영됩니다.

예약도 근태도 경고도 없으면 카드는 **머리 한 줄**로 접힙니다 — 제목, 건수 칩, 읽은 때, 아이콘 버튼 둘이 한 줄에
놓입니다. 예약·근태가 있거나 못 읽은 것이 있으면 그 아래로 목록·경고 줄이 펼쳐집니다.

목록이 있을 때는 **머리 줄이나 오른쪽 끝의 화살표 버튼을 눌러 접고 폅니다**(접수 미확인 공문 카드와 같은 버튼). 접어도 건수 칩과
경고는 보이고, **접어 둔 것은 기억합니다** — 다음에 홈을 열어도 접힌 채이고, 다시 펴면 그것도 기억합니다(`chrome.storage` 의 `homeFolded`).

못 읽은 날은 패널과 똑같이 **결과에서 빼고 몇 일이 빠졌는지 적습니다.** 홈 화면 markup(`#divPopupInfo`)을 못 알아보면
카드를 붙이지 않습니다 — 엉뚱한 자리에 띄우느니 안 띄웁니다.

### 홈 화면의 접수 미확인 공문 카드

e-Class 홈의 **WORKSPACE 카드 바로 위에 "접수 미확인 공문" 카드**가 붙습니다. DOC Cruiser Monitoring 의

제목을 누르면 사이트의 목록에서 제목을 누른 것과 같은 **문서 창**(860×800)이 열립니다. 문서 번호·접수일·보낸

`설정 및 연결 → 홈에 접수 미확인 공문 카드` 로 정합니다(기본 켬, `homeUncfm`). 끄면 열려 있는 홈에서도 곧바로

콘텐츠 스크립트(`home.js` → `src/unconfirmed.js`)가 하는 요청은 **목록 하나뿐**입니다.

- 목록은 `…/DORSY/Rcv/Rcv_Not_Confirm_List.aspx` 입니다. 사이트는 `User_ID`·`User_Name_E`·`Dept_Code` 를 붙여
  열지만 매개변수 없이 불러도 로그인한 사람 것이 옵니다(2026-10-02 확인). 미회람 목록과 같은 표(`RadGridDOC`)이고,
  제목 링크는 `ViewRcvDoc_Ex(R_ID, S_ID)` 입니다.
- 문서 창은 `DOCCruiser/Popup/RfReceivePrefer_View.aspx?R_ID=…`(S_ID 가 비면 `RfReceivePreferOffLine_View.aspx`)
  이고, **사람이 눌렀을 때만** 열립니다. 미회람 문서처럼 받기만 해도 기록이 남는 화면일 수 있어 확장이 대신
  열어 보지 않습니다. 접수 확인은 그 창의 `Save` 로 합니다.
- 요청 한 번(25KB)이라 담아 두지 않고 **홈을 열 때마다** 받습니다. 문서 창에서 접수 확인을 하고 홈으로
  돌아오면(창에 초점이 돌아오거나 탭이 다시 보이면) 다시 받아 그 건이 빠집니다 — 받은 지 10초가 안 됐으면
  건너뜁니다. 새로고침 아이콘 버튼으로도 다시 받습니다.

공문이 없으면 칩이 `미확인 0` 이라고만 하고(따로 "없습니다"라고 적지 않습니다) 펼치는 화살표도 두지 않습니다.
목록을 못 읽었을 때는 칩을 0 이 아니라 줄표(`–`)로 두고 **왜 못 읽었는지** 적으며(로그인이 풀렸으면 그렇다고),
먼저 읽어 둔 목록이 있으면 그대로 둡니다.
사이트가 센 건수(`2 results`)와 읽어 낸 건수가 다르면 그것도 적습니다. 이런 경고는 **접혀 있어도 보입니다.**

사진의 `copyToClipboard('<id>')`, Task 버튼의 `titleMouseOver(event, this, '<id>', …)`. 사내 메일은
`<id>@krs.co.kr` 이라(KR Directory 의 실제 이메일과 표본 9/9 일치) 그것으로 링크를 만듭니다. 사진이 없어
자리표시자(`00000.gif`)로 바뀐 카드는 다른 자리에서 ID 를 찾고, **어디서도 못 찾으면 버튼을 붙이지 않습니다**
— 엉뚱한 사람에게 이어지는 버튼보다 없는 것이 낫습니다.

콘텐츠 스크립트(`people.js` → `src/people.js`)는 경로가 아니라 **카드가 있는지**(`.search_info_btn`)로 붙일
화면을 고릅니다. 검색 결과 말고도 같은 카드가 뜨는 화면(부서 페이지 등)을 한 번에 덮고, 켜져 있는 동안
나중에 나타난 카드(`메인 / 파견·겸무` 전환)에도 붙입니다.

### DOC-Cruiser 미회람 문서 자동 열람

DOC-Cruiser 의 미회람 문서(`Management → Non-circular documents`)를 **e-Class 홈을 열 때 하루에 한 번**,
화면을 띄우지 않고 전부 열어 회람 처리합니다. 홈의 WORKSPACE 카드가 아침에 한 번 훑는 그 자리에서 같이 돕니다.

**기본은 꺼져 있습니다.** 패널의 `설정 및 연결 → DOC-Cruiser 미회람 문서 자동 열람` 을 켠 브라우저에서만 돕니다.
읽지 않은 공문을 읽은 것으로 바꾸는 일이고 **되돌릴 수 없으며**, 문서 내용을 읽어 주지도 않습니다.
켜면 열려 있는 홈에서 곧바로 시작하고(오늘 이미 돈 날이어도 한 번 더), 끄면 도는 중이라도 다음 문서로
넘어가기 전에 멈춥니다. 홈 카드(`홈에 WORKSPACE`)를 꺼 두어도 이 설정은 따로 돕니다.

하는 일은 사람이 목록에서 제목을 하나씩 눌러 여는 것과 같습니다(`src/circulate.js`).

1. 미회람 목록 `…/DORSY/Circulation/Not_Circulation_List.aspx` 를 받습니다. 매개변수 없이 부르면 로그인한
   사람 것이고, 쪽 나눔 없이 전부 한 화면에 옵니다.
2. 제목 링크 `ViewCirculationDoc(R_ID, RC_ID, …)` 가 여는 주소 `DOCCruiser/Popup/RfCirculation_View.aspx?R_ID=…&RC_ID=…`
   를 건마다 한 번씩 받습니다(한꺼번에 3건까지). **이 주소를 받기만 해도 서버가 읽은 시각을 적습니다** —
   2026-10-01 에 한 건으로 확인했습니다(목록 425 → 424건, 그 문서의 회람 표에 그 시각으로 `O`).
3. 다 연 뒤 **목록을 다시 받아 확인합니다.** 못 연 건, 열었는데 목록에 남은 건, 사이트가 센 건수와 뽑은
   건수가 다른 것은 "다 했다"로 넘기지 않고 그대로 말합니다.

목록에는 `Set the all document circulation state` 버튼(전부 오늘 날짜로 회람 처리)도 있지만 쓰지 않습니다.
사이트가 스스로 "정상 회람을 권한다"며 확인을 받는 길이고, 남는 기록이 연 것과 같은지 알 수 없습니다.

결과는 `활동 로그` 에 `[회람]` 으로 남고, 설정의 체크박스 아래에 **마지막으로 언제 무엇을 했는지** 한 줄로
보입니다(도는 중이면 `열람 중 37/424...`). 열 것이 없던 날이 이어지면 같은 줄을 날마다 쌓지 않습니다.

- **하루에 한 번** — 오늘 끝낸 기록(`docCirculateState`)이 있으면 홈을 다시 열어도 돌지 않습니다.
- 로그인이 풀려 목록조차 못 읽은 날은 끝낸 날로 치지 않습니다. 다음에 홈을 열 때 다시 시도합니다.
- 홈 탭을 여러 개 열어도 겹쳐 돌지 않습니다. 돌던 탭이 닫혀 표식이 1분 넘게 묵었으면 다음에 여는 홈이
  이어받습니다(이미 연 문서는 목록에서 빠져 있으니 남은 것만 엽니다).
- 처음 켜면 밀린 문서를 한꺼번에 엽니다. 수백 건이면 몇 분 걸리니 그동안 홈 탭을 열어 두세요.

목록 화면인지는 **표와 건수 라벨이 있는지**로 가립니다. 미인증이면 목록 대신
`alert("올바른 로그인 정보가 없습니다…다시 로그인하여 주시기 바랍니다!")` 한 줄이 200 으로 오는데, 공문 제목에도
"다시 로그인" 같은 말이 들어갈 수 있어 `src/net.js` 의 문구 판정(`siteFetch`)을 쓰지 않고 직접 요청으로 받습니다.

### 한 달 미리 훑기

패널이 열리면 보고 있는 탭을 먼저 띄운 다음, **오늘부터 30일을 회의실·차량 두 벌로 한 번
훑어 `src/monthcache.js` 의 보관소에 담습니다.** 세 탭이 이 한 벌을 나눠 씁니다.
보관소는 `chrome.storage` 에도 하루치씩(`day|room|2026-10-02`) 적어 두어, **훑기는 하루에 한 번**이고
패널을 닫았다 열면 오늘 읽은 것을 불러와 씁니다. 어제 읽은 것은 불러올 때 지웁니다.

- **내 예약** 은 직접 훑지 않고 보관소에서 그 기간을 꺼내 씁니다. 훑기는 한 번에 하나만 돌아서,
  현황 탭으로 열려도 미리 훑기와 겹쳐 두 배로 두드리는 일이 없습니다.
- **회의실·차량** 은 날짜를 옮기면 담아 둔 것으로 **격자를 먼저 그립니다.** 그래서 ◀▶ 를
  눌러도 빈 화면을 보지 않습니다. 예약 목록만으로는 빈 회의실을 알 수 없어서,
  훑을 때 **회의실(차량) 목록도 함께 담아 둡니다.**

담아 둔 화면은 **보기 전용**입니다. 예약·취소는 사이트 화면의 ViewState 손잡이가 있어야 하는데
훑기는 그것을 남기지 않습니다. 그래서 살아 있는 조회가 끝날 때까지 격자는 흐리게 잠겨 있고,
그 사이에 예약 버튼을 누르면 "잠시 뒤 다시" 라고 말합니다.

담긴 값에는 **언제 읽었는지**가 붙습니다. 캐시로 그린 화면에는 `미리 훑어 둔 현황(3시간 전)`
처럼 함께 적습니다. 묵은 현황을 지금 것처럼 보여주면 이미 찬 칸을 "예약 가능"으로 칠하게 되는데,
이 앱에서 가장 나쁜 실패입니다. 그래서 회의실·차량 격자는 담아 둔 것을 먼저 그리더라도 **늘 살아 있는
조회로 확인**하고, 그때 읽은 하루가 보관소에도 새로 담깁니다.

담아 둔 날을 다시 읽는 때는 정해져 있습니다.

- **날이 바뀌었을 때** — 오늘 읽은 것이 아니면 묵은 것입니다.
- **이 확장으로 예약·취소·수정했을 때** — 그 날을 보관소에서 버려 다음에 볼 때 다시 읽습니다.
  여러 날에 걸친 차량 예약은 걸친 날을 모두 버립니다.
- **`↻`(현황 탭) 나 한 달 막대를 눌렀을 때** — 그 기간을 버리고 다시 훑습니다.
- **확인 불가로 읽힌 날**은 10분 뒤에 다시 읽어 봅니다. 잠깐의 실패가 하루 종일 남지 않게 하려는 것입니다.

패널을 여러 창에 띄워 두어도 한쪽이 담거나 버린 날을 다른 쪽이 따라갑니다(`storage.onChanged`).

지역을 바꿔도 담아 둔 예약은 그대로 씁니다 — 예약 목록에는 전 지역이 들어 있고,
지역마다 다른 것은 **회의실 목록뿐**이라 그것만 따로 기억해 둡니다.

탭 줄 맨 앞의 **근태** 는 HR(`hr.krs.co.kr`)에 근태 신청서를 올리고, 올린 것을 고치거나 무릅니다.

| 종류 | HR 신청서 | 넣는 것 |
|---|---|---|
| 출장 | 출장 신청 › 국내출장 | 출발일 · **며칠간** · 출발(기본 07:00) · 도착(기본 20:00) · 목적 · **여비계산서 사전정산**(켜면 출장지 · 근무지 · 교통편 — 증빙은 신청할 때 묻지 않고 신청 내역의 출장 카드에서 넣는다) · 그 옆의 **차량 조회** (출장경비는 묻지 않고 **선급 예산**으로 보냄) |

| 유연(유연근무) | 유연근무 신청(Daily **또는 Weekly**) | 기간(당일·주간·전체) — 당일: 날짜 · 출근시간 · 사유 / 주간: 월~금 요일마다의 출근시간 / 전체: 월~금에 넣을 출근시간 하나 |
| 외출 | 기타근태 신청 › 외출 | 날짜 · 시작(30분 단위) · **몇 시간** · 사유 |
| 휴가 | 휴가/공가 신청 › 연차 **또는 체력관리** | 종류(연차·체력단련) · 시작일 · **며칠간** · 구분(전일·오전·오후 — 하루짜리 연차만) |

여섯 종류가 **두 글자 이름으로 한 줄에 다** 보입니다(출장·외근·유연·외출·휴가·건강). 풀 이름은 폼 제목과 풍선말에 나옵니다.
말로 채울 때는 "자율출퇴근"·"유연근무" 어느 쪽으로 말해도 유연근무로 알아듣습니다.

- **며칠간** 은 좁은 칩 `1D`~`5D`(하루부터 닷새)와 그 오른쪽 한 줄의 달력입니다. 칩을 누르면 달력의 끝나는 날이 따라 바뀌고
  (출발일 10/20 에 `3D` → 10/22), 달력에서 끝나는 날을 고르면 그만큼의 날 수가 됩니다. 닷새보다 길면 달력에서 고릅니다(최대 31일).
- **날짜·시각 칸은 이름이 칸 안에** 있습니다(`출발일 10/02/2026`, `출발 07:00`). 이 칸들과 며칠간은 늘 채워져 있어 "필수"를 달지 않습니다.
- **시각은 목록에서 고릅니다.** 외근·외출·건강검진은 30분 간격(00:00, 00:30 … 23:30)이고 **시작의 기본값은 09:00** 입니다.
  출장·교육은 HR 신청서가 분 칸을 잠가 두어(옵션은 00·30 이지만 고를 수 없다 — 2026-10-02 화면 소스 확인) 정시 목록입니다.
- **몇 시간** — 하루 안에서 끝나는 종류(외근·교육·외출·부서소통회·시간으로 올리는 건강검진)는 종료 시각을 따로 묻지 않습니다.
  날짜와 시작 시각(30분 간격 목록, 기본 09:00)을 넣고 `1H`~`8H` 칩(1~8시간, 한 줄)을 누르면 종료 시각이 거기서 나오고, 칩 아래에 `14:00 ~ 16:30` 처럼 적힙니다.
  오른쪽의 초록 **`+30분`** 칩은 따로 켜고 끕니다(`2H` + `+30분` = 2시간 30분, 그것만 켜면 30분). 교육은 정시 단위라 `+30분` 이 없습니다.
  시작 시각을 옮기면 고른 시간만큼 종료가 따라가고, 말로 "2시부터 4시까지"라고 하면 2시간으로 바꿔 읽습니다. 그 날 안에 끝나야 합니다.
- **종류 안의 갈래** — 외근에 들어가서 교육·소통을, 휴가에 들어가서 연차·체력단련을 칩으로 고릅니다. 체력단련은 HR 의 "체력관리"입니다.
  소통(부서소통회)은 HR 에 따로 있는 신청서가 아니라 외근으로 올라가며, 고르면 13:00~14:00 과 목적이 깔립니다(고칠 수 있습니다).
  다른 갈래로 돌아가면 깔아 준 값 가운데 손대지 않은 것은 걷힙니다.
- **휴가의 구분** 은 기본이 전일이고, 오전·오후는 하루짜리 연차에만 있습니다(체력단련은 HR 이 전일로 잠급니다).
  말로 채울 때 시각으로 말하면 **끝이 13시 이전이면 오전, 시작이 13시 이후면 오후** 로 읽습니다("오전 반차"·"오후 반차"도 됩니다).
  국내출장·교육·외근은 HR 이 근태구분을 "시간"으로 잠가 두어 전일·오전·오후가 없습니다 — 출발·도착 시각이 그 몫을 합니다.
- **유연근무의 기간** 은 칩 셋입니다 — **당일**(그 날 하루), **주간**(월~금 요일마다), **전체**(월~금 모두 같은 시간).
  출근시간은 퇴근과 한 묶음입니다: `07:00~16:00` `08:00~17:00` `08:30~17:30` `09:00~18:00` `09:30~18:30` `10:00~19:00` `11:00~20:00`.
  목록은 늘 일곱 가지를 다 보여줍니다. **07:00·11:00 출근은 월·금요일에만** 있어서, 주간의 화·수·목 칸과 전체,
  그리고 날짜가 화~목인 당일에서는 그 둘만 흐리게 잠겨 있습니다(날짜를 옮기면 잠금이 따라갑니다).
  HR 신청서의 기간구분은 Daily·Weekly 둘이라 주간과 전체는 같은 Weekly 로 올라갑니다 — 날짜도 사유도 받지 않고,
  **결재되면 다음 주 월요일부터 반영**됩니다(신청서의 안내문). 주간을 고르면 빈 요일 칸에 지금 근무시간표가 채워져 바꿀 요일만 고치면 됩니다.
  말로는 "전체 9시 출근"·"주간, 월요일 7시 금요일 11시" 처럼 채웁니다(Claude 가 없으면 기간과 시각 하나만 읽습니다).
  신청 내역에는 주간 문서가 `유연근무 주간` 으로 보이고, 수정·변경으로 불러오면 다섯 요일이 같을 때 전체로, 다를 때 주간으로 돌아옵니다.
- **반차는 그 날 출근시간이 정시일 때 씁니다.** 오전·오후를 고르면 HR 에서 주간 근무시간표와 그 날짜로 올려 둔 유연근무를 읽어
  구분 칸 아래에 적습니다. 08:00 출근이면 오전 반차 08:00~12:00 · 오후 반차 13:00~17:00 입니다.

  **날짜 칸에 직접** 적어 `조회` 합니다 — 그때는 근태 날짜가 그 기간에 걸친 것 전부이고 4주·8주는 꺼집니다(누르면 기본 보기로 돌아옵니다).
  머리 줄의 기간 글은 올해 밖에 걸치면 해를 붙입니다(`25/10/4 ~ 26/10/4`). 줄 왼쪽의 딱지는 **근태의 결재 상태** 입니다 —
  올려 둔 것(결재대기·결재요청)은 `신청`, 결재완료는 `승인` 이고 임시저장·반려·회수는 HR 의 이름 그대로입니다(2026-10-04 사용자 지정, 색으로 가립니다). 이미 지난 승인 건은 딱지가 회색입니다.
  HR 문서함은 신청일로만 거를 수 있어서, 보여줄 기간보다 여섯 달 앞에 신청한 것부터 읽어 근태 날짜로 고릅니다.

  | 상태 | 버튼 | 하는 일 |
  |---|---|---|
  | 임시저장 | 수정 · 상신 · 삭제 | 폼으로 불러와 고침 / 그대로 결재요청 / 문서함에서 지움 |
  | 결재요청(승인 전) | **변경** · 회수 | 변경: 회수하고 같은 내용을 폼에 불러옴 → 시간을 고쳐 다시 결재요청 / 회수: 거둬들이기만 |
  | 결재완료 | **변경** · 취소신청 | 변경: 사유를 적어 취소신청서를 올리고 같은 내용을 폼에 불러옴 / 취소신청: 올리기만. 유연근무는 취소신청서가 없음 |
  | 회수 | 삭제 | 회수한 문서를 지움. HR 문서함 화면은 임시저장에만 삭제 버튼을 보여 주므로, 서버가 받지 않으면 목록에 그대로 남고 그렇게 알려 줌 |
  | 모두 | **↗** | ↗(버튼 줄 끝의 아이콘): HR 웹페이지에서 그 문서를 엶. 같은 내용으로 새 신청서를 쓰는 "복사" 버튼은 뺐습니다(2026-10-03) |

  **↗** 는 HR 을 새 탭으로 앞에 열고, 결재문서함에서 줄을 두 번 누른 것과 같은 길로 그 문서를 HR 의 탭에 띄웁니다
  (결재선·결재 상태까지 그 화면에서 봅니다). 읽기만 하는 일이라 한 번만 누르면 됩니다.

  HR 에는 올린 문서를 고치는 버튼이 없습니다. 그래서 **변경** 은 "거둬들이기 + 새 신청서"를 이어서 합니다 —
  내용을 먼저 읽어 두고(읽지 못하면 거둬들이지 않습니다), 거둬들인 것이 목록에서 확인되면 폼에 불러옵니다.
  결재완료 건은 취소신청서가 결재되어야 원 문서가 무효가 됩니다.

### HR 과 말하는 방법

HR 은 eclass 와 다른 시스템이고 화면이 `X-Frame-Options: SAMEORIGIN` 이라 패널 안에 넣을 수 없습니다.
그래서 **HR 작업 탭**을 뒷전에 하나 엽니다 — eclass 홈의 "HR System" 링크와 같은 SSO 주소입니다.
패널을 닫으면 그 탭도 닫습니다. eclass 로그인이 풀려 있으면 SSO 를 열지 않고 만료라고 말합니다.

값을 넣고 올리는 일은 **요청을 흉내 내지 않습니다.** 작업 탭의 숨은 iframe 에 신청서 화면을 띄우고
그 화면의 자기 함수(`saveTrav100`·`apprRequest`·`apprReqCancel` …)를 부릅니다. 결재선·문서번호·숨은 칸은
사이트가 스스로 채우므로, 사람이 그 화면에서 버튼을 누른 것과 같은 요청이 나갑니다.

- **넣는 순서가 정해져 있습니다**(`src/attend.js` 의 `buildJob`). 종류를 바꾸면 사이트가 날짜를 오늘로 되돌리고,
  시작일을 넣으면 시각을 초기화합니다. 그래서 종류 → 시작일 → 종료일 → 시 → 분 → 글 순서로 넣습니다.
- **누르기 전에 다시 읽습니다.** 종류·구분·날짜·내용과 **사이트가 계산한 합계시간**이 기대와 같아야 버튼 함수를 부릅니다.
  하나라도 어긋나면 누르지 않고 멈춥니다 — 빈 신청서가 결재선에 올라가는 것이 가장 나쁜 실패입니다.
- **사이트의 알림·확인 창은 그 프레임 안에서만 가로챕니다.** "저장/결재요청/회수 하시겠습니까" 셋에만 답하고,
  그 밖의 물음(결재선 확인 등)에는 답하지 않고 멈춥니다. 성공은 사이트가 "저장 되었습니다 / 결재 요청되었습니다 /
  회수되었습니다" 라고 한 뒤 **신청 내역을 다시 읽어 그 문서의 상태가 바뀐 것**까지 봐야 성공으로 적습니다.

2026-10-02 에 실제 HR 화면에서 여섯 종류의 값 넣기·사이트 검증 함수 통과, 임시저장 문서 열어 고치기, 취소신청 줄 넣기,
회수 관문을 확인했습니다. **실제로 문서를 만드는 저장·결재요청·삭제·회수·취소신청 요청은 시험으로 보내지 않았습니다** —
아래 [아직 확인이 필요한 것](#아직-확인이-필요한-것) 참고.

## 말로 찾는 회의실/차량

맨 아래 입력칸에 이렇게 적으면 됩니다. **회의실 탭과 차량 탭에서 모두** 씁니다 —
보고 있는 탭에 맞춰 회의실을 찾거나 차량을 찾습니다.

```
9월 20일부터 27일 사이 8시부터 12시까지 10명
내일 오후에 회의실 아무거나
다음 주 화요일 2시간짜리 서울 회의실
내일 오후 2시부터 3시간 쓸 차량
```

Claude 가 조건을 해석해 날짜를 하루씩 조회하고, 조건에 맞는 빈 시간대를 목록으로 보여줍니다.
**항목을 누르면 그 탭·날짜·지역으로 옮겨 해당 칸이 선택**되므로 회의주제(차량은 행선지)만
적고 예약하면 됩니다. 다른 탭에서 찾은 것을 눌러도 그 탭으로 돌아가고, 접어 둔 회의실이
걸리면 저절로 펼쳐집니다.

차량에는 좌석 정보도 지역도 없어 **인원·지역 조건은 무시**하고, 뺐다는 것을 결과 줄에 적어 줍니다.

해석은 세 단계로 내려갑니다. 결과에 어느 것을 썼는지 `[로컬 CLI]` 처럼 표시됩니다.

1. **로컬 Claude Code CLI** — API 키가 필요 없습니다. 이미 로그인된 `claude` 를 그대로 씁니다.
2. **Anthropic API 키** — `설정 및 연결` 에 넣으면 씁니다(이 브라우저에만 저장).
3. **규칙 해석** — 위 둘 중 하나가 붙어 있는데 호출이 실패하면 흔한 문장은 규칙으로 처리합니다.

### 입력 명세 (`input.yaml`) — 말은 구조로 바뀐 뒤에만 실행 쪽으로 간다

Claude 가 말을 읽어 돌려주는 것은 세 가지입니다 — 회의실·차량 **조회 조건**(`parse`), 근태 **폼 조각**(`attend`),
예약 실패 **원인 설명**(`diagnose`). 각각 어떤 칸을 어떤 형으로 내야 하는지, 어떤 규칙으로 읽는지가
저장소 루트의 **`input.yaml` 한 곳**에 적혀 있습니다.

```
사용자 말 → 로컬 CLI · API 키 · 규칙 해석 → input.yaml 의 구조 → 관문(검증·정규화) → 받는 코드
```

- **지시문과 스키마를 여기서 만듭니다.** 로컬 CLI 다리(`native/host.mjs`)와 API(`src/ai.js`)가 같은 지시문을 씁니다.
  예전에는 같은 규칙이 영문·국문 두 벌로 따로 있었습니다.
- **어느 길로 온 답이든 관문을 지납니다**(`src/input.js` 의 `structure`). 필수 칸이 없거나 틀리면, 또는 끝이 시작보다
  앞서면 그 답을 버리고 다음 길로 내려갑니다. 필수가 아닌 칸이 틀리면 그 칸만 비우고 **무엇을 뺐는지 결과 줄에 적습니다.**
  명세에 없는 키는 버립니다 — Claude 가 정하는 것은 칸의 값뿐이고, 어느 종류·어느 함수로 갈지는 화면이 정합니다.
- 구조가 곧 실행은 아닙니다. 조회 조건은 빈 시간을 찾을 뿐이고 예약은 후보를 고른 뒤에, 근태 조각은 폼에 얹힐 뿐이고
  HR 에는 폼을 확인해 누른 뒤에 나갑니다. 명세의 `consumer`(구조를 받는 코드)와 `next`(그 뒤의 길)가 이것을 적어 둡니다.

확장은 YAML 을 읽지 못하므로 `input.yaml` 을 고친 뒤에는 생성물을 다시 만듭니다. 둘이 어긋나면 테스트가 잡습니다.

```
node tools/gen-input.mjs          # input.yaml → src/inputspec.js
node tools/gen-input.mjs --check  # 쓰지 않고 어긋났는지만 본다
```

### 여비 규칙·KTX 운임표 (`travel-rules.yaml` · `ktx-fares.yaml`)

여비계산서(사전정산)를 자동으로 지을 때 따르는 것은 저장소 루트의 세 문서입니다.

| 문서 | 내용 |
|---|---|
| `travel-rules.yaml` | 출장기간 구분(당일 → 당일출장(주재국), 1박 이상 → 일반출장) · 일비 · **식수 규칙**(아침 07시 이하 출발, 저녁 20시 이상 도착, 점심은 늘) · 교통편(여럿을 함께 고름, 기차만 고르면 자동) · 기차 좌석 등급(일반석·특실) |
| `ktx-fares.yaml` | **KTX 운임을 손으로 고치는 파일** — 고치거나 더할 구간만 적는다(여기 적은 구간이 공식 표를 이긴다) · 주말로 치는 요일 · 출장지에서 탈 역을 찾는 길잡이 · 항공권의 공항이 어느 도시 쪽인지 가리는 길잡이 · **구간의 대략 소요 시간**(`times`) |
| `ktx-fares-official.yaml` | **코레일 공식 KTX 운임표**에서 가져온 542개 구간(일반실 · 특실, 어른 편도 정가). 생성물이라 손대지 않는다 — `tools/import-ktx-fares.py` 가 다시 쓴다 |
| `air-mileage.yaml` | **항공 마일리지 표** — 사후정산의 신규 마일리지를 여기서 찾는다. 항공사마다 국내선 구간 마일(일반석 편도, 100%)과 좌석 등급별 적립률(일반석 · 특실/비즈니스) · 항공권의 글에서 공항을 찾는 길잡이 |

확장은 YAML 을 읽지 못하므로 고친 뒤에는 생성물을 다시 만듭니다. 둘이 어긋나면 테스트가 잡습니다.

```bash
node tools/gen-travel.mjs          # 네 YAML → src/travelspec.js
node tools/gen-travel.mjs --check  # 쓰지 않고 어긋났는지만 본다
uv run --with xlrd tools/import-ktx-fares.py <코레일 KTX 운임표 xls>   # 공식 운임표 → ktx-fares-official.yaml (그 뒤 gen-travel)
```

**KTX 요금을 고치려면** `ktx-fares.yaml` 의 `routes` 에 그 구간을 한 줄 적고 `node tools/gen-travel.mjs` 를 돌립니다 —
`- { a: 서울, b: 부산, standard: 54400, first: 78900 }`. 방향은 가리지 않고, 공식 표에 없는 구간(KTX-이음 노선 등)도 같은 모양으로 더합니다.
공식 표를 다시 가져와도 여기 적은 것은 지워지지 않습니다.

**구간의 대략 소요 시간**은 생성기가 구간마다 운임 옆에 `hours`(시간 단위)로 붙입니다 — 여비계산서 교통편 줄의 출발·도착 시각이 됩니다.
넉넉히 올려 잡은 값입니다: 서울↔부산처럼 KTX 가 2시간 30분 ~ 3시간 20분이면 4시간, 가장 짧아도 1시간.
`ktx-fares.yaml` 의 `times` 에서 셈합니다 — 이웃한 역 사이의 분(`links`)을 이어 두 역 사이의 분을 얻고, `margin_minutes`(10분)를 더해
시간 단위로 올립니다(분은 정차역마다 서는 열차를 어림한 값이지 시간표가 아닙니다).

| 구간 | 시간 | 구간 | 시간 |
|---|---|---|---|
| 부산↔서울 · 수서 · 행신 | 4 | 서울↔대전 | 2 |
| 부산↔광명 · 천안아산 · 오송 | 3 | 서울↔동대구 · 용산↔광주송정 · 목포 | 3 |
| 부산↔대전 · 김천구미 · 동대구 | 2 | 용산↔여수엑스포 · 서울↔진주 | 4 |
| 부산↔울산 · 경주 · 밀양 | 1 | 서울↔광명 · 천안아산 · 오송 | 1 |

**한 구간의 시간만 바꾸려면** `times.routes` 에 한 줄 적고 생성기를 돌립니다 — `- { a: 부산, b: 대전, hours: 3 }`.
전체를 더 넉넉하게(또는 빠듯하게) 잡으려면 `margin_minutes` 를 바꿉니다.

운임표에 대해 알아 둘 것(자세한 것은 `ktx-fares.yaml` 머리말):

- **코레일 공식 KTX 운임표**(2026-09-01 KTX·SRT 통합 운임, 코레일 홈페이지에 올려 둔 엑셀 — 예매 조회가 아니라 공개 문서)에서 가져온 값입니다.
  2026-10-03 에 내려받아 542개 구간(역 46곳)의 **일반실과 특실 정가**를 `ktx-fares-official.yaml` 에 넣었습니다(서울↔부산 54,400 / 78,900원). 코레일이 새 표를 올리면 위 명령으로 다시 가져옵니다.
- **같은 두 역도 경유하는 길마다 운임이 다릅니다**(서울↔부산: 경주 경유 54,400 · 서대구 경유 54,000 · 구포 경유 48,900 · 수원 경유 48,000원).
  운임표에는 **가장 큰 값**(고속선을 곧장 가는 길)을 정가로 적습니다 — 다른 길로 가는 열차를 탔으면 사후정산 때 바로잡습니다.
- 특실은 일반실의 1.45 배쯤입니다(운임 + 특실 요금). 셈하지 않고 공식 표의 값을 그대로 씁니다.
- **특실이 있는 노선만 있습니다.** KTX-이음이 다니는 강릉·중앙·중부내륙·동해선은 특실이 없고 운임이 두 벌이라 넣지 않았습니다 — 그쪽 역은 운임표에 없는 구간으로 다룹니다.
- 요일(평일·주말) 차등은 공식 표에 없습니다. 그래도 구간마다 `weekend` 를 적을 수 있고, 적으면 금·토·일에는 그 값을 씁니다.
- 출장지·근무지에 적은 글에 역 이름이 여럿 들어 있으면 **먼저 나오는 것**을 씁니다("서울 영등포구" → 서울역).

**항공 마일리지 표**(`air-mileage.yaml`)는 사후정산 "항공 마일리지"의 `신규 마일리지`를 채웁니다 — 항공권 문서에 적립 마일리지가 적혀 있지 않을 때만 씁니다.

- 지금은 **대한항공 국내선** 19개 구간입니다(김포·인천↔김해 215 · 김포·인천↔제주 276 · 제주↔김해 186마일 …). 적립률은 **일반석 100% · 특실/비즈니스(프레스티지석) 125%** 이고
  마일 미만은 반올림합니다(김포↔김해 특실 269마일).
- **값은 대한항공 홈페이지를 직접 읽어 확인한 것이 아닙니다**(자동 접근이 막혀 있습니다) — 검색에 잡힌 스카이패스 안내의 내용과 그것을 옮긴 다른 글이 같아 그대로 적었습니다.
  실제 적립과 다르면 표에서 고칩니다. 적립률은 정확히는 예약 등급(영문 한 글자)마다 달라, 할인 등급이면 표의 값과 다를 수 있습니다.
- **고치거나 더하려면** 그 항공사의 `routes` 에 한 줄 적고(`- { a: 김포, b: 김해, miles: 215 }`, 공항 이름은 `airports` 의 것) `node tools/gen-travel.mjs` 를 돌립니다.
  다른 항공사는 `airlines` 에 같은 모양으로 더합니다. 표에 없는 항공사·구간은 채우지 않습니다(짐작하지 않습니다).

여비계산서 화면(eclass `/BusinessTrip`)은 2026-10-02 에 실제 화면 소스로 확인했습니다 — 목록 `Home/List`, 작성 `Write`(저장은 그 폼을
`Write/Save` 로 제출), 요금표 `TrafficFee/Select`. **저장 요청은 아직 실제로 보내 본 적이 없습니다**(실제 계산서가 생기는 일이라 시험하지 않았습니다).
사후정산은 2026-10-03 에 확인했습니다 — 계산서 `CalPrint?seq&trseq`(출장자마다 trseq), 입력 `AfterTrip?seq&trseq`(저장은 그 폼을 `AfterTrip/Save` 로
multipart 제출 — 숙박 `lodge_*` · 교통 `tr_*` · 항공 `air_*` · 식비 `meal_*`, 숙박비 상한은 `Api/CalMaxLodge`), 업무 항공마일리지 `PublicMileage`.
입력 화면은 포털 껍데기의 iframe(`#content-iframe`) 안에서 열리고, 숙박 줄의 `ETC국가명`·`첨부` 칸은 CSS 로 숨겨져 있습니다(`#lodgeTbl .lodge-etc, .lodge-file { display: none }`).
사후정산 저장은 2026-10-03 에 실제로 나갔습니다(계산서 143884 에 숙박 줄이 생겼습니다 — 같이 보낸 첨부는 남지 않았습니다). 숙박 줄 지우기(`tripAfterLodgeDelete`)는 아직 실제로 보내 본 적이 없습니다.

**둘 다 없으면 입력칸이 잠깁니다** — 플레이스홀더에 `claude가 연결되지 않았습니다` 라고 적히고
버튼도 눌리지 않습니다. 여기서 말하는 "연결" 은 **확장이 claude 에 닿을 수 있는가**이지
PC 에 claude 가 깔려 있는가가 아닙니다. 아래 `로컬 CLI 연결` 등록을 하거나 API 키를 넣으면 풀립니다.

이때 말 칸 두 곳(회의실·차량의 말로 찾기, 근태의 말로 채우기) 아래에 **연결 지침 복사** 버튼이 나옵니다.
누르면 이 PC 의 Claude Code·Codex 같은 코딩 에이전트에 그대로 붙여 넣을 글이 클립보드에 담깁니다 —
확장 폴더, 확장 ID, 브라우저가 댄 까닭, 여섯 조건, 돌릴 명령이 들어 있습니다(`src/bridgeguide.js`).
같은 버튼이 `설정 및 연결 → 로컬 Claude CLI` 에도 있고, 이쪽은 API 키로 쓰는 중에도 CLI 가 없으면 남습니다.
확장은 자기 폴더의 경로를 알 수 없어서 `install.ps1` 이 써 둔 `native\com.krs.meetingroom.json` 에서 읽습니다.
한 번도 등록한 적이 없는 PC 에서는 경로 대신 찾는 법(`chrome://extensions` 의 "로드 위치")을 적어 줍니다.

한 번 검색할 때 날짜 수만큼 사이트를 조회하므로 최대 14일까지만 봅니다.
현황을 확신할 수 없는 날은 결과에서 빼고 몇 일이 빠졌는지 알려줍니다.

### 로컬 CLI 연결 (권장, 키 불필요)

브라우저 확장은 로컬 프로그램을 직접 실행할 수 없어 네이티브 메시징 다리를 씁니다.
**이 등록은 선택이 아니라 필수입니다** — PC 에 `claude` 가 깔려 있고 로그인까지 돼 있어도,
등록하지 않으면 확장은 거기에 닿지 못합니다. 배지가 `없음` 으로 뜨고 말로 찾기 칸도 잠깁니다.

새 PC 에 설치할 것은 둘입니다.

1. **Node.js** — `node` 가 PATH 에 있어야 합니다. 다리(`native\host.mjs`)가 node 로 돕니다.
2. **Claude Code CLI** — `claude` 가 PATH 에 있고 `claude login` 으로 로그인돼 있어야 합니다. 구독 계정(Pro/Max)이면 됩니다.

그 다음 등록과 재시작입니다.

3. 브라우저에 확장을 올린 뒤 `/bridge install`. 또는 `chrome://extensions`(엣지는 `edge://extensions`)에서
   이 확장의 **ID** 를 복사해 `powershell -ExecutionPolicy Bypass -File native\install.ps1 -ExtensionId <ID>`.
   크롬·엣지 키에 한 번에 들어갑니다.
4. 브라우저 완전 재시작. 엣지는 창을 닫아도 남으니 `/bridge restart edge` 로 마무리합니다.
5. 패널 `설정 및 연결` 에 `로컬 Claude CLI: 연결됨` 확인. 막히면 `/bridge` 가 여섯 항목을 짚어 줍니다.

`install.ps1` 은 크롬 키(`HKCU\Software\Google\Chrome\NativeMessagingHosts`)와
엣지 키(`HKCU\Software\Microsoft\Edge\NativeMessagingHosts`)에 같은 매니페스트를 한 번에 겁니다.
두 브라우저 모두 origin 이 `chrome-extension://<ID>/` 이고 같은 폴더면 ID 도 같아 매니페스트 하나로 됩니다.
설치되지 않은 쪽 키는 놀 뿐 해가 없습니다.

**엣지는 창을 다 닫아도 끝나지 않습니다.** "시작 부스트" 와 "Microsoft Edge 가 닫혀 있을 때도 백그라운드 확장 및 앱
계속 실행" 이 기본으로 켜져 있어 `msedge.exe` 가 남고, 창을 다시 열면 그 프로세스가 그대로 쓰여 새 등록을 읽지 못합니다.
작업 관리자에서 `msedge.exe` 를 전부 끝내거나 `edge://settings/system` 에서 두 설정을 끈 뒤 다시 여세요.
`/bridge` 는 브라우저 본체가 등록보다 먼저 떴는지 시각을 비교해 재시작이 정말 필요한지 말해 주고,
창이 하나도 없을 때는 `/bridge restart edge` 가 남은 본체를 끝내고 다시 띄워 줍니다(창이 있으면 끊지 않습니다).

이 절차와 점검은 `/bridge` 스킬이 대신합니다 — `/bridge` 로 여섯 항목을 한 번에 보고,
`/bridge install` 로 ID 계산·등록·왕복 확인까지 합니다(`.claude/skills/bridge`).

ID 는 **불러온 폴더 경로에서 나옵니다.** 폴더를 옮기면 ID 가 바뀌니 다시 등록해야 합니다.
브라우저를 `--user-data-dir` 로 따로 띄워 써도 등록은 `HKCU` 에 들어가므로 프로필과 무관하게 먹습니다.

확장이 임의의 명령을 실행할 수는 없습니다. `claude` 를 부르는 작업은 `parse` 와 `diagnose` 둘뿐이고
(그 밖에는 연결 확인 `ping` 과 호출 기록 읽기 `logs`),
시스템 프롬프트도 호스트 파일에 고정돼 있어, 확장이 보내는 것은 입력 텍스트뿐입니다.
접근은 등록한 확장 ID 로만 제한됩니다.

기본 에이전트 프롬프트를 빼서(`--exclude-dynamic-system-prompt-sections`)
호출당 캐시 토큰이 38K → 4.2K, 비용이 $0.078 → $0.012 로 줄었습니다.
해제는 `native\uninstall.ps1` 입니다(크롬·엣지 키 둘 다 지웁니다).

다리는 `claude` 를 부를 때마다 `native\logs\<날짜>.jsonl` 에 한 줄 남깁니다(입력·결과·비용·걸린 시간,
실패면 종료 코드와 stderr). 14일이 지난 파일은 지웁니다. `/bridge log` 로 최근 기록을 볼 수 있습니다.

## 활동 로그

패널 아래 `활동 로그` 칸에 예약·취소·수정·이어붙이기, 말로 찾기, 조회·훑기 실패, 캡처,
다리 연결 상태, 미회람 문서 열람 결과가 남습니다. 이 브라우저(`chrome.storage`)에 최근 500건까지 둡니다.
같은 일이 이어지면 새 줄 대신 횟수만 올립니다(자동 갱신이 같은 실패로 목록을 채우지 않게).

- **로그 복사** — 확장 기록 전부에 다리 기록(최근 30건)과 환경(버전·탭·다리·API 키 유무)을 붙여
  클립보드에 넣습니다. 문제가 생기면 이것을 그대로 붙여 넣으면 됩니다.
- **파일로 저장** — 같은 내용을 다운로드 폴더에 `krs-log-<시각>.txt` 로 저장합니다.
- **비우기** — 두 번 눌러야 지웁니다. 이 브라우저 기록만 지우고 `native\logs` 는 그대로 둡니다.

예약이 실패하면 응답에서 **보낸 값과 응답에 남은 값의 차이**만 추린 요약(`src/diagnose.js`)을
그 기록에 같이 남깁니다. 예전에 다운로드 폴더에 따로 쓰던 `meetingroom-save-response.txt` 는 이것으로 대신합니다.
기록에는 회의 주제·이름·입력한 문장이 들어 있고, API 키는 남기지 않습니다.

### 로그인이 풀렸을 때

로그인이 안 되어 있으면 안내와 함께 **eclass 다시 로그인** 링크가 뜹니다. eclass 는 로그인한 뒤 18시간쯤
지나면 당일 쿠키가 한꺼번에 풀리고, 포털을 계속 써도 연장되지 않습니다(2026-09-27 확인 — 홈을 다시 불러도
쿠키를 다시 발급하지 않습니다). 회의실·차량 화면은 그 순간부터 "You must sign in" 만 돌려줍니다.
사이트가 세션을 이어 주는 장치를 두지 않았으므로 확장도 비밀번호를 저장하거나 대신 로그인하지 않습니다.
대신 이렇게 합니다.

- 앱이 "sign in" 을 돌려주면 포털 홈을 **리다이렉트를 따라가지 않는 요청**으로 확인해, 포털까지 풀린 것인지
  (만료 → "다시 로그인하면 자동으로 이어집니다") 앱만 못 받은 것인지(살아 있음 → 한 번 더 시도한 뒤 안내)
  가려 말합니다. 홈을 따라가며 부르면 이미 끝난 세션의 남은 쿠키를 지워 버리므로 확인만 합니다.
- 링크는 회의실 껍데기 대신 **포털 홈**을 엽니다. 로그아웃 상태의 껍데기는 로그인 폼이 아니라 gate 로
  튕기기 때문입니다. 로그인 폼은 끝나면 홈으로 돌아옵니다.
- eclass 탭이 다 읽히는 순간(로그인 뒤 홈으로 돌아온 순간)과 패널이 다시 보이는 순간, 로그인이 풀린 상태였다면
  ↻ 를 누르지 않아도 스스로 다시 조회하고 한 달 훑기도 이어서 합니다. 현황 탭도 마찬가지입니다.
- 네트워크가 막힌 것은 로그인 문제로 적지 않습니다. 예전에는 직접 요청이 실패하고 eclass 탭이 없으면
  "열려 있는 eclass 탭이 없습니다" 로 나왔는데, 그것은 로그인과 무관한 안내였습니다.
- 홈의 WORKSPACE 카드도 포털이 풀린 것이면 **eclass 다시 로그인** 링크를 답니다(밤새 열어 둔 홈 탭은 겉만 로그인 상태입니다).

### 실제 크롬·엣지에서 (CDP)

jsdom 이 흉내 낼 수 없는 것 — 확장이 정말 로드되는지, 사이드패널이 JS 오류 없이 뜨는지,

엣지도 같은 하네스로 봅니다. `msedge.exe` 에 같은 인자를 주면 되고, 다른 포트를 쓰면 `CDP_PORT` 로 알려줍니다.
2026-09-16 엣지 153 에서 확장 ID 가 크롬과 같게 나오고 사이드패널 검사 11건이 통과한 것을 확인했습니다.

**크롬 136+ 는 기본 프로필에 디버그 포트를 붙여주지 않습니다.** 반드시 따로 `--user-data-dir`
을 줘야 하고, 그러면 쿠키 항아리가 달라져 **그 창에서 eclass 에 한 번 로그인**해야 합니다.
로그인해야 되는 검사는 로그인이 없으면 `skip` 으로 찍고 이유를 말합니다 — 조용히 통과시키면

**크롬 137+ 는 명령줄 `--load-extension` 을 무시합니다.** 그래서 하네스가 CDP 의
`Extensions.loadUnpacked` 로 직접 올립니다(경로는 역슬래시를 받지 않고 슬래시여야 합니다).

사이트에 **쓰지는 않습니다.** 신청 폼을 열어 구조를 읽을 뿐 저장 버튼은 누르지 않습니다.
로그인돼 있으면 홈도 열어 **WORKSPACE 카드가 붙고 훑기가 끝나는지**까지 봅니다(서른 날이라 몇 분 걸릴 수 있습니다).

파서를 고칠 때 추측 대신 이 파일로 확인할 수 있습니다.

## 사이트 구조 (2026-09-16 캡처 기준)

조회 화면은 **Telerik RadGrid**(`RG_MAIN_ctl00`)이고 헤더 행이 `display:none` 에 `&nbsp;` 뿐이라
헤더 이름으로는 컬럼을 찾을 수 없습니다. `colgroup` 으로 위치가 고정돼 있어 인덱스로 읽습니다.

| 위치 | 내용 |
|---|---|
| 2 | 지역 (부산/서울) |
| 3 | 회의실명 (`미팅룸1(1층)-8석`) |
| 4 | 시간 (`09:00~18:00`) |
| 5 | 승인 상태 |
| 다음 행 | 중첩 표에 회의주제·예약자(부서) |

**회의실 목록은 지역별로 따로 내려옵니다.** `DDL_REGION` 을 바꾸면 포스트백으로
`DDL_ROOMNAME` 이 그 지역 것으로 다시 채워집니다(부산 14곳 / 서울 3곳).
그래서 패널에 지역 선택기가 있고, 지역을 바꾸면 다시 조회합니다.

좌석 수와 층은 회의실 이름에서 뽑습니다 (`-8석` → 8석 배지, `(11층)` → 11층).

예약 폼은 같은 페이지 안의 숨겨진 `div_write` 입니다. 인원 입력칸은 **없습니다**.

| 필드 | 이름 |
|---|---|
| 지역 / 회의실 | `DDL_REGION` / `DDL_ROOMNAME` |
| 날짜 | `DP_ROOMDATE`, `DP_ROOMDATE$dateInput` + **ClientState**(아래) |
| 시작 / 종료 | `DDL_ROOMSHOUR`+`DDL_ROOMSMINUTE` / `DDL_ROOMEHOUR`+`DDL_ROOMEMINUTE` |
| 반복 | `RB_REPEAT` (N = 설정 안 함) |
| 회의주제 | `TXT_TITLE` |
| 저장 | `BTN_SAVE` (이미지 버튼 → `.x`/`.y` 로 제출) |

분은 10분 단위만, 종료는 23:50 까지만 받습니다.

차량 취소는 **회의실과 경로가 다릅니다.** 회의실은 `lbDelete` 를 누릅니다. 차량은 내가 넣은
건의 행 끝에 **취소 submit 버튼**이 붙습니다(2026-09-30 실제 화면에서 확인).

```html
<input type="submit" name="RG_MAIN$ctl00$ctl06$Detail10$ctl04$BTN_DEL"
       value="취소" onclick="return fnDelete();">
```

`fnDelete()` 는 확인창일 뿐이라, **그 이름을 얹어 포스트백하면 취소 버튼을 누른 것과 같습니다.**
버튼이 그 건의 행 안에 있으니 어느 건을 지우는지 헷갈릴 수도 없습니다.

페이지에는 `fn_del(idx, group)`(→ `HF_DEL_YN`/`HF_IDX`/`HF_GROUP_IDX` + `__doPostBack`)도
남아 있지만 **실제 화면이 쓰는 길이 아닙니다.** 그 인자만 찾다가 못 찾아서 한동안 차량 취소가
통째로 막혀 있었습니다(`del = null` → 취소 버튼 비활성). 지금은 submit 버튼을 먼저 보고,
없을 때만 옛 길로 내려갑니다. 이 버튼은 **본인 건에만** 붙으므로 "내 예약" 판정에도 씁니다.

### 월 달력은 이웃 달 칸에 건수를 찍지 않는다

목록 왼쪽의 월 달력(`CAL_MAIN`, Telerik RadCalendar)은 날짜 칸마다 `<font>17건</font>` 으로
그날 예약 건수를 찍어 주고, 파서는 이걸 표와 대조합니다. 그런데 달력은 앞뒤 줄을 채우려고
이웃 달 며칠을 같이 그립니다(9월 화면에 8/30~31, 10/1~10). 그 칸은 `class="rcOtherMonth"` 이고
**건수가 없습니다.** 0건이 아니라 모르는 것입니다.

어느 달을 펼칠지는 숨은 칸 `CAL_MAIN_AD` = `[[최소일],[최대일],[초점일]]` 의 초점일이 정합니다
(캡처: `[[1980,1,1],[2099,12,30],[2026,9,16]]`). 선택일(`CAL_MAIN_SD`)만 바꿔 보내면 목록은
그 날짜로 가지만 달력은 원래 달에 머뭅니다. 그래서 날짜를 옮기는 포스트백에 초점일을 함께
얹습니다(`src/parse.js` 의 `dateMoveCandidates`). **2026-09-25 실제 사이트에서 확인**: 초점일을 얹으면
10월 달력이 따라 내려와 10월 1일이 건수 대조까지 정상으로 조회됩니다. 받아 주지 않는 화면을 만나면
예전 방식으로 내려가고, 어느 쪽이든 성공은 `LB_DATE` 로 판정합니다.

### 날짜 칸은 글자만 채우면 안 먹는다

예약 폼의 날짜는 Telerik `RadDatePicker` 입니다. `DP_ROOMDATE` 와 `DP_ROOMDATE$dateInput`
두 글자 칸에 날짜를 넣어 보내도 **서버가 무시하고 ViewState 에 있던 날짜(보통 오늘)를 씁니다.**
값은 숨은 `DP_ROOMDATE_dateInput_ClientState` 의 JSON 에서 읽기 때문입니다.

```
{"enabled":true,"emptyMessage":"","validationText":"2026-09-19-00-00-00",
 "valueAsString":"2026-09-19-00-00-00","lastSetTextBoxValue":"2026-09-19"}
```

게다가 목록 날짜(`LB_DATE`)를 옮겨도 예약 폼 날짜는 따라오지 않습니다. 목록은 달력의
`CAL_MAIN_SD` 로 옮기는데, 그러면 서버의 선택 변경 처리기가 돌지 않아 폼 날짜가 그대로입니다.
사이트의 `예약하기` 버튼(`fn_write()`)도 그냥 `div_write` 를 펼치기만 할 뿐 날짜를 넣지 않습니다.

그래서 `src/parse.js` 의 `telerikDateFields()` 가 글자 칸과 ClientState,
달력 선택일(`DP_ROOMDATE_calendar_SD`)을 한꺼번에 만들고,
`reserve()` 는 **저장 직전에 폼 날짜가 정말 요청한 날짜인지 확인한 뒤에만 제출합니다.**
다르면 제출하지 않고 멈춥니다 — 조용히 오늘 날짜로 예약되는 것보다 낫기 때문입니다.

### 차량 신청 폼 (2026-09-16 캡처 기준)

`Admin_View_New.aspx?CARIDX=<차량>&SDATE=<날짜>` 팝업. `test/fixtures/rentcar-form-2026-09-16.html`
이 실제 캡처입니다. 여기 오기 전까지 필드 이름은 전부 추측이었고, **그 추측은 대부분 틀렸습니다** —
목록 페이지의 죽은 `fnSave()` 는 `TXT_TITLE`/`TXT_PLACE`/`TXT_DRIVER` 라고 했지만
진짜 폼은 `txtTitle`/`txtPlace`/`txtDriver` 입니다. `DDL_CARNAME` 하나만 맞았습니다.

| 필드 | 이름 |
|---|---|
| 차량 / 지역 | `DDL_CARNAME` / `DDL_REGION` (둘 다 옵션 1개 — 차량은 주소가 정한다) |
| 시작일 / 종료일 | `txtSdate` / `txtEdate` (Telerik, **표기가 회의실 폼과 다르다** — 아래) |
| 시작 시/분 | `ddlStimeH` + `ddlStimeM` |
| 종료 시/분 | `ddlEtimeH` + `ddlEtimeM` |
| 사용자 / 부서 / 사번 | `txtDriver` / `txtDriverDeptName` / `hidDriverID` (사이트가 채워서 내려준다) |
| 동승자 / 행선지 / 사용목적 | `txtPassenger` / `txtPlace` / `txtTitle` |

시 값은 `9` 이지 `09` 가 아니고, 분은 `0`/`10`/…/`50` 입니다. 0 을 채워 보내면 서버가
조용히 첫 항목을 씁니다. 그래서 `src/carform.js` 는 **드롭다운이 실제로 가진 옵션 값**을 씁니다.

#### 날짜 칸 표기는 폼마다 다르다 (HTTP 500 의 원인이었음)

같은 Telerik 날짜 피커인데 **글자 칸 표기가 다릅니다.**

| | `$dateInput` 값 |
|---|---|
| 회의실 예약 폼 `DP_ROOMDATE` | `2026-09-16` |
| 차량 신청 폼 `txtSdate` | `2026-09-16-00-00-00` |

회의실 표기를 차량 폼에 밀어 넣으면 저장이 통째로 터집니다 — 사이트가 이렇게 답합니다.

```
HTTP 500  Text property cannot be set. 문자열이 유효한 DateTime으로 인식되지 않습니다.
```

브라우저가 실제로 보내는 본문을 CDP 로 가로채 대조해서 찾았습니다. 브라우저는 그 칸을
`2026-09-16-00-00-00` 로 보내고, `_dateInput_ClientState` 와 `_calendar_SD` 는 **비운 채**
보냅니다. 그래서 `telerikDateFields()` 는 **그 칸이 지금 들고 있는 생김새를 지키고 날짜만**
바꾸며, 폼이 이미 그 날짜면(신청 폼은 `?SDATE=` 로 여니 대부분 그렇습니다) 아예 건드리지 않습니다.

`test/fixtures/rentcar-save-500.html` 이 그때 받은 실제 오류 화면입니다(스택 추적은 잘라냄).
`src/net.js` 의 `describeErrorPage()` 가 여기서 한 줄을 뽑아, 이제 `HTTP 500` 대신
**사이트가 말한 이유**가 화면에 뜹니다.

`fnSaveCheck()` 가 막는 것: 시작일 ≤ 종료일, 같은 날이면 시작시 ≤ 종료시, 사용자·부서 필수,
행선지 필수. 사용목적은 **검사하지 않습니다.**

이름을 여기 박아두지 않고 `src/carform.js` 가 **문서를 보고 찾아냅니다**(`src/grid.js` 가 컬럼을
찾는 것과 같은 방식). 시·분은 옵션이 0~23 인지 10분 단위인지로, 글자 칸은 옆 라벨 글자로 가립니다.
못 찾으면 **제출하지 않고** 무엇을 못 찾았는지 말합니다. 실제로 이 설계 덕분에 추측한 이름이
전부 틀렸는데도 진짜 폼에서 모든 칸을 정확히 찾아냈습니다.

### 사이트가 로그인한 사람을 알려주는 유일한 자리

"사이트는 로그인한 사람이 누구인지 화면 어디에도 적어주지 않는다"는 건 조회 화면 이야기입니다.
**차량 신청 폼은 이름·부서·사번을 채워서 내려줍니다**(`txtDriver`, `txtDriverDeptName`,
`hidDriverID`). 차량을 한 번 신청하면 이름이 저절로 채워지고, 회의실 격자의 내 예약 밑줄도
같이 정확해집니다.

## "예약된 건지 어떻게 아느냐"

이 확장은 **모를 때 모른다고 말합니다.** 칸 상태는 세 가지입니다.

| 표시 | 뜻 |
|---|---|
| 연한 초록 | 예약 가능 (현황을 정확히 읽었고 비어 있음) |
| 회색 | 사용 중 |
| **노란 빗금** | **확인 불가** — 예약 여부를 읽지 못함. 선택되지 않음 |

읽기 결과를 그냥 믿지 않고 **독립적인 근거와 대조**합니다.

- 월 달력에 날짜별 예약 건수가 찍혀 있습니다. 표에서 읽은 건수가 달력 건수와
  다르면 파싱을 놓친 것이므로 **확인 불가**로 처리합니다. 건수는 달력이 펼친 달의 칸에만 있어서
  이웃 달 칸(9월 화면의 10/1~10)은 0건이 아니라 "모름"으로 두고, 날짜를 옮길 때 달력의 달도
  같이 옮겨 건수를 받아 옵니다. 2026-09-24 에 이 칸을 0건으로 읽어 10월 1일 예약 10건이
  "달력은 0건인데 표에서 10건"으로 확인 불가가 됐던 적이 있습니다.
- 화면의 `LB_DATE` 가 요청한 날짜와 같은지 확인합니다. 날짜를 못 옮겼으면 확인 불가입니다.
- 회의실 목록이나 지역을 못 가져와도 확인 불가입니다.

읽기 실패를 "예약 없음"으로 착각해 빈 방이라고 잘못 안내하는 일을 막기 위해서입니다.

예약도 마찬가지입니다. 사이트가 돌려주는 alert 문구를 믿지 않고,
제출 후 **다시 조회해서 그 시간에 예약이 실제로 잡혔는지 확인한 뒤에만** "예약 확인됨"으로 표시합니다.
확인이 안 되면 `⚠ 제출은 됐지만 예약을 확인하지 못했습니다` 로 경고합니다(중복 예약 주의).

**실패하면 이유도 자동으로 확인합니다.** API 키가 있으면 저장 응답에서 제출 전과 달라진 부분만
추려(보통 300바이트 남짓) Claude 에게 보내고, 사이트가 거부한 것인지 / 저장은 됐는데 목록에
안 뜨는 것인지 / 알 수 없는지를 원인과 함께 화면에 보여줍니다.
**예약 여부 판정은 재조회가 하고, 모델은 이유만 설명합니다** — 모델 판단이 결정적 검증을
덮어쓰면 신뢰도가 떨어지기 때문입니다. 키도 CLI 도 없으면 대신 **보낸 값과 응답에 남은 값을
나란히 적은 요약**을 `meetingroom-save-response.txt` 로 저장합니다(예전에는 응답 HTML 을
통째로 100KB 넘게 적었는데, 실제로 원인을 가리키는 건 이 값 대조뿐이라 요약만 남깁니다).

저장 전에 회의실 선택이 실제로 반영됐는지도 확인하고, 다르면 제출을 중단합니다.

## 아직 확인이 필요한 것

**근태 신청을 실제로 올려 본 적은 없습니다(2026-10-02).** 값을 넣고, 사이트의 검증 함수(`chkValidation`)를
통과하고, 임시저장 문서를 열어 고치고, 취소신청 표에 줄을 넣는 데까지는 실제 HR 화면에서 확인했습니다.
그 다음 한 걸음 — 사이트의 저장·결재요청·회수 함수를 부르는 것과 문서함 삭제 요청 — 은 실제 문서와 결재 알림이
생기는 일이라 시험으로 보내지 않았습니다. 처음에는 **임시저장만** 으로 올려 신청 내역에 뜨는지 본 뒤
**삭제** 로 지워 보는 것이 가장 안전한 확인 순서입니다. 실패하면 누르기 전에 멈췄는지(`올리지 않았습니다`)
사이트가 거절했는지(`HR 이 받지 않았습니다`)를 가려 말하고, HR 이 한 말은 활동 로그에 남습니다.

후보를 차례로 시도하고 `LB_DATE` 로 성공을 판정합니다. 오늘 날짜는 기본값이라 항상 동작하고,
다른 날짜는 `◀ ▶` 를 눌러봐야 확인됩니다. 실패하면 조용히 틀리지 않고 **확인 불가**로 표시됩니다.
