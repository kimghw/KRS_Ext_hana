# rnd-kr-history — KR(한국선급) 과제 예산·참여연구원·과제목표 변경이력 관리

한국선급(KR) 연구개발 과제의 **예산·참여연구원·과제목표**가 개정(협약변경·연차변경 등)될 때, **rnd-kr-extract 가 만든 KR-only 구조화 스냅샷(`KR_{과제이름}.yaml`)**을 입력으로 받아 **개정(rev) 단위 변경이력**을 적재한다. `rnd-kr-extract`(발췌·구조화)와 짝을 이루는 **이력 전담** 스킬이다.

> **분리 구도**: [`/rnd-kr-extract`](../rnd-kr-extract/SKILL.md) 는 KR 업무를 발췌·구조화(`KR_{과제}.yaml` 스냅샷 = 해당 시점 현재값 전량)까지만. **`rnd-kr-history` 는 그 스냅샷을 받아** 직전 현재값과 diff → rev 적재 → 뷰 생성. 즉 **스냅샷(현재 상태) → 이력(델타 누적)**.
>
> **역방향(재생성)**: 반대로 **과제이름·폴더경로**만 주면(스냅샷 `.yaml` 이 아님) `snapshot` 모드로 **이력 최신 rev 를 원본 스냅샷에 덮어** 현행 스냅샷 `KR_{과제}_r{N}.yaml` 을 만든다. researcher 전용 모드에선 원본 스냅샷이 r0 로 고정돼(변경 미반영) 노후화되므로, 이 재생성으로 **최신값이 반영된 정본급 스냅샷**을 얻는다. 즉 **이력(델타 누적) → 스냅샷(현행 재구성)**.

## 핵심 원칙

- **KR-only**: 추적 대상은 한국선급 항목뿐이다. 입력 스냅샷이 이미 KR-only(`rnd-kr-extract` 가 KR 행/블록만 구조화)이지만, 방어적으로 **KR 외 기관 항목은 무시**한다(스냅샷에 섞여 들어와도 적재 금지). 이력 파일·뷰에 타 기관 값이 들어가지 않는다.
- **두 시간축 분리**: `단계`>`연차`(계획축, 같은 개정본 안의 배분)와 `rev`(이력축, 협약변경으로 값이 바뀜)를 **절대 섞지 않는다**. `연평균참여율`(연봉기준 인건비 비율)·`참여기간참여율`(계상률)·`월별참여율`·`참여기간`은 도메인 값이지 이력축이 아니다(월별참여율의 "월"은 도메인 시간, `rev`(이력축)와 무관).
- **sparse hybrid**: 항목별 **현재값은 최상위에 펼쳐 두고**, **한 번이라도 바뀐 항목만** 그 자리에 `history:` 리스트를 단다. 안 바뀐 항목은 한 줄. `history` 유무 = 변경 여부 플래그.
- **append-only(준)**: `history` 리스트엔 **추가만**. 과거 항목 수정·삭제 금지. 변경 시 최상위 현재값·`rev` 만 갱신. `rev` 는 `revisions.yaml` 외래키.
- **자동 감지 + 수동 사유**: 직전 현재값과 자동 diff 하되, 변경·삭제의 **사유는 사용자에게** 받는다.
- **스냅샷이 정본의 출처**: 변경된 값의 정본은 `rnd-kr-extract` 의 발췌본·구조화본이다. 이력은 그 델타 기록 — 추적만 하고 스냅샷을 옛 상태로 두지 않는다(값을 직접 고칠 일이 생기면 스냅샷도 함께 갱신하도록 안내).

## 입력 · 전제

> **입력이 3종이다(오랜만에 보면 헷갈림 주의)**: ⓐ 구조화 **스냅샷** `KR_<과제>.yaml`(rnd-kr-extract 산출), ⓑ **참여연구자 변경비교** `참여연구자인건비_<연차>_변경<NN>.yaml`(rnd-manpower-change 산출), ⓒ **비목 변경비교** `연구개발비비목_<연차>_변경<NN>.yaml`(rnd-budget-change 산출). **예산·인건비 변경(changes)을 이력에 반영**하려면 스냅샷이 아니라 **ⓑ·ⓒ 변경비교 파일**을 인자로 준다. 예:
> `/rnd-kr-history RND_PROJECT\MW급_10kV_고전압_직류_시스템용_반도체_차단기_개발\1차년도\budget_change\변경01_2026-07-15\연구개발비비목_1차년도_변경01.yaml`
> 변경비교 적재는 **기본으로 재생성까지 자동 실행**해 `KR_<과제>_r<N>.yaml` 까지 한 번에 만든다(이력만 원하면 `--no-snapshot`).

- **현재 스냅샷**: `RND_PROJECT\<과제이름>\KR_<과제이름>.yaml` **또는** 연차 하위폴더 `RND_PROJECT\<과제이름>\<연차>\KR_<과제이름>.yaml`(`/rnd-kr-extract --format structured` 산출 — 차년도 폴더 분리 구조). 경로 직접 지정 또는 `--project <과제이름>` 로 자동 탐색(과제폴더 직하 → 연차 하위폴더 순, 여럿이면 §AskUserQuestion).
- **(대안 입력) 변경비교 YAML (researchers)**: `rnd-manpower-change` 가 만든 `참여연구자인건비_<연차>_변경<NN>.yaml`(최상위 키 `참여연구자인건비_변경비교`)을 입력으로 줄 수 있다 — **researchers 전용 모드**. **참여자 `전`→r0(변경 전 기준선)·`후`→r1(이번 변경)** 로 직접 적재한다 — **스냅샷 불필요**(전/후가 곧 baseline+delta). 이후 변경은 다음 변경비교 YAML 로 누적(첫 회만 r0 시드, 그다음부터 직전 현재값에 쌓음). researchers 전용 — 예산·과제목표는 이 YAML에 없어 미추적(현재값은 스냅샷 `KR_*.yaml`). 단계는 같은 연차 스냅샷 `meta.단계` 있으면 참조, 없으면 §AskUserQuestion·기본 `1단계`. 상세 → §변경비교 YAML 입력 모드 (researchers 전용).
- **(대안 입력) 변경비교 YAML (budget)**: `rnd-budget-change` 가 만든 `연구개발비비목_<연차>_변경<NN>.yaml`(최상위 키 `연구개발비비목_변경비교`)을 입력으로 줄 수 있다 — **budget 전용 모드**(researchers 모드와 대칭). **비목별 `전`→r0(변경 전 기준선)·`후`→새 rev(이번 변경)** 로 직접 적재한다 — **스냅샷 불필요**(전/후가 곧 baseline+delta). ⚠ 비교 YAML 의 표시명(`연구시설·장비비`)을 이력 item 키(`직접비/연구시설장비비`, 가운뎃점 없음)로 **정규화**해 snapshot-mode init 과 같은 키로 맞춘다(안 맞추면 전부 신규로 오인). researchers·과제목표는 이 YAML에 없어 미추적. 단계는 같은 연차 스냅샷 `meta.단계` 있으면 참조, 없으면 §AskUserQuestion·기본 `1단계`. 상세 → §변경비교 YAML 입력 모드 (budget).
- **직전 현재값**: 이력 파일(`<entity>_history.yaml`)의 **최상위 현재값**이 "직전 상태"의 단일 출처다. 별도 옛 스냅샷 파일이 없어도 된다(r0 면 직전 상태 없음 → 전량 신규). 옛 스냅샷을 보관하고 싶으면 `KR_<과제이름>.<rev>.yaml` 로 아카이브(선택).
- **이력 위치**: `RND_PROJECT\<과제이름>\<연차>\history\`(**연차별 격리 — 연차마다 자기 `history\`**. 스냅샷·`manpower_change` 와 같은 연차 폴더 안. **rev 도 연차별 독립**(1차년도 r0/r1…, 2차년도는 따로 r0부터). 한 history 파일엔 그 연차 항목만). 없으면 `${CLAUDE_SKILL_DIR}/templates/history/` 4개 파일로 스캐폴딩.

## 인자 분기 (`$ARGUMENTS`)

> **인자 자동판별(적재 ↔ 재생성)**: 위치 인자가 **`.yaml` 파일**이면 **적재**(스냅샷/변경비교 → 이력, 아래 §0~§8). **`.yaml` 이 아닌 과제이름·디렉터리 경로**면 **재생성**(`snapshot` 모드 — 이력 → 최신 `KR_<과제>_r<N>.yaml`, §스냅샷 재생성 모드). `--project`(적재용 스냅샷 자동탐색)와 헷갈리지 말 것 — `--project` 는 적재, 위치 인자 과제이름/폴더는 재생성. 명시하려면 `snapshot <과제|폴더>` 로도 강제 가능.

|:---|:---|
| (없음) | `AskUserQuestion` 으로 적재/재생성 중 무엇인지, 스냅샷/과제·rev·type·source 를 수집한 뒤 진행. |
| `<스냅샷.yaml>` | (적재) 그 스냅샷으로 이력 갱신. history 폴더는 **같은 연차 폴더의 `history\`**(스냅샷이 든 `<연차>\history\`). |
| `<변경비교.yaml>` (researchers) | (적재) `rnd-manpower-change` 산출 `참여연구자인건비_…_변경<NN>.yaml`(최상위 `참여연구자인건비_변경비교`). **researchers 전용 모드** — 전→r0(기준선)·후→r1(변경) 자동 매핑. history 폴더는 **경로의 연차 폴더 `history\`**(예: `…\1차년도\history\`). §변경비교 YAML 입력 모드 (researchers 전용) 참조. |

| `--project <과제이름>` | (적재) 스냅샷 = `RND_PROJECT\<과제이름>\KR_<과제이름>.yaml`, 없으면 연차 하위폴더 `RND_PROJECT\<과제이름>\<연차>\KR_<과제이름>.yaml`(여럿이면 §AskUserQuestion). 이력 폴더 = **그 스냅샷의 연차 폴더 `<연차>\history\`**(연차별 격리, rev 도 연차별 독립). |

| `--source <문서>` | 근거 문서명(협약변경 PDF 등). 미지정 시 질의. |
| `--품의서 <경로>` | **품의서(결재문서) 파일**(PDF·이미지·HWP). LLM 이 Read 로 직독해 **시행일(효력발생일)** 을 추출, rev `date`(**발효일**) 기준으로 사용(발효일=시행일). 폴더명 날짜·질의보다 우선. 파일명은 `source` 로도 기록 가능. |
| `--no-views` | `current_*.md`·`changelog.md` 뷰 재생성을 건너뜀. |
| `--no-snapshot` | **변경비교 모드**에서 적재 직후 **자동 재생성**(`KR_<과제>_r<N>.yaml`)을 건너뜀(이력만 갱신). 미지정이면 기본으로 재생성까지 자동(base 스냅샷 있을 때). |
| `init` | **초기화** — `hist_dir` 없으면 스캐폴딩 + **현재 스냅샷을 r0(최초)로 전량 시드**(변경 전 기준선 확보). 이미 있으면 "이미 초기화됨" 보고 후 종료. §init·undo 참조. |
| `undo` | **되돌리기** — 가장 최근 rev **1건**을 롤백(revisions 최신 rev 제거 + 항목 현재값을 직전으로 복원, 그 rev 신규항목 삭제, 제외→활성 복구). 실행 전 §AskUserQuestion 확인. §init·undo 참조. |
| `show` / `show-current` | 현재 이력 요약(엔티티별 항목 수·최신 rev·변경 건수)을 출력하고 종료. |
| `help` / `-h` | 본 문서 요약을 출력하고 종료. |

## 절차

> **경로 약어**: `proj_dir` = `RND_PROJECT\<과제이름>` · `year_dir` = `proj_dir\<연차>` · 스냅샷 = `proj_dir\KR_<과제이름>.yaml` **또는** `year_dir\KR_<과제이름>.yaml` · `hist_dir` = `year_dir\history`(**연차별 격리 — 연차마다 한 곳, rev 도 연차별 독립**).

### 0. 입력 확정

1. `$ARGUMENTS` 해석(`show`/`help` 면 출력 후 종료). **위치 인자 자동판별**: (a) `init`/`undo`/`show`/`help` → 해당 절차. (b) **`.yaml` 파일** → 적재(아래). **최상위 키로 분기**: `참여연구자인건비_변경비교` 면 **§변경비교 YAML 입력 모드 (researchers 전용)** (§0.2~§8 대신), `연구개발비비목_변경비교` 면 **§변경비교 YAML 입력 모드 (budget)**, 둘 다 아니면 스냅샷 적재. (c) **`.yaml` 이 아닌 과제이름·디렉터리 경로**(또는 `snapshot <…>`) → **§스냅샷 재생성 모드로 분기**(적재 절차 미수행). `--project` 는 (b) 적재용이므로 재생성으로 오인 금지.
2. **스냅샷 결정**: `<스냅샷.yaml>` 직접 지정값, 없으면 `--project` → `proj_dir\KR_<과제이름>.yaml`, 그래도 없으면 연차 하위폴더 `proj_dir\<연차>\KR_<과제이름>.yaml`(재귀 glob `proj_dir/**/KR_*.yaml`). 둘 이상이면 §AskUserQuestion 으로 고른다(보통 최신 연차). 과제 미지정이면 `RND_PROJECT\**\KR_*.yaml` 후보를 찾아 질의. `test -f` 로 존재 확인. **없으면**: 먼저 `/rnd-kr-extract <입력> --format structured` 로 스냅샷을 만들라고 안내.
3. **스냅샷 로드·검증**: YAML 파싱(파싱 실패 시 중단·보고). `meta.수행기관` 이 한국선급(KR)인지 확인(아니면 KR-only 위반 — 보고 후 중단). `meta.단계`·`meta.연차범위`·`예산.단위` 확보.

### 1. 이력 폴더 스캐폴딩

- `hist_dir` 없으면 생성하고 `${CLAUDE_SKILL_DIR}/templates/history/`의 `revisions.yaml`·`budget_history.yaml`·`researchers_history.yaml`·`objectives_history.yaml` 복사. `revisions.yaml.project` 에 과제 약어 기록.
- 있으면 4개 파일 로드(현재값 = 직전 상태).

### 2. rev 결정

- `--rev` 값 사용. 비면 — `revisions.yaml` 이 비었으면 `r0`(최초), 아니면 `직전+1`(예: `r2`)을 §AskUserQuestion 으로 제안·확인.
- `type`(최초협약/협약변경/연차변경/계획수정)·`source`(근거문서)·`date`(발효일)를 수집(인자 없으면 질의). **`date`(발효일) 우선순위 = 품의서 시행일 > 폴더명 날짜(있으면) > 질의** — `--품의서 <경로>`가 있으면 그 파일을 **Read 로 직독**(PDF·이미지)해 **시행일(효력발생일)** 을 뽑아 발효일로 쓴다(발효일=시행일; 문서에 시행일 없으면 결재일→기안일 순 대체하고 보고).

### 3. 스냅샷 파싱 (KR-only) → 엔티티 items

- `history.track` 각 엔티티에 대해 §추적 엔티티 표·`references/history_schema.md` 매핑대로 스냅샷을 item 리스트로 변환.
  - `budget`: `예산.비목별[]` 의 연차별 비목(직접비/인건비, 직접비/연구활동비, 직접비/연구수당, 간접비, 연구개발비총액) + `예산.외주용역[]` → (단계, 연차, 비목, 금액). 단계 = `meta.단계`.
  - `researchers`: `예산.참여연구자인건비[].참여자[]` → (성명, 단계, 연차, 직급, **연평균참여율**, **참여기간참여율**=계상률, **월별참여율**, **급여총액**=급여총액, 인건비=계상인건비, …). 참여율은 **세 값**으로 따로 적재한다(급여총액은 재생성·정합 분모로 함께 적재):
    - **연평균참여율** = 연봉(12개월) 기준 인건비 비율(%) = `계상인건비 / 급여총액 × 100` = `round(Σ월별참여율 / 12, 2)`. 헤드라인(연봉 대비 실제 인건비 비중).
    - **참여기간참여율** = 참여기간 중(참여한 달 기준) 참여율(%) = **계상률** = `round(Σ월별참여율 / 참여개월, 2)`. 스냅샷 `참여자[].계상률` 그대로(구 `참여율` ≡ 참여기간참여율; 하위호환으로 옛 `참여율` 키는 참여기간참여율로 읽음).
    - **월별참여율** = 참여기간 각 월의 참여율 맵 `{YYYY-MM: %}`(매월 참여율). **스냅샷에 `참여자[].월별참여율` 이 있으면 그 표를 정본으로 그대로 쓰고**(`/rnd-kr-extract` `options.monthly_rate` 로 원문 월별 표를 추출한 경우), 없으면 `참여시작~참여종료` 각 월에 참여기간참여율을 **평탄(flat)** 으로 채운다(비참여월은 키 없음). 월별 표가 있거나(스냅샷·사용자 입력) **연차 중간 협약변경 등으로 월별 상이**하면 그 값으로 위 두 평균(참여기간참여율·연평균참여율)을 역산한다.
    - 정합(둘 다 성립): 계상인건비 = `(급여총액/12) × 참여개월 × (참여기간참여율/100)` = `급여총액 × (연평균참여율/100)`. 즉 **연평균참여율 = 참여기간참여율 × 참여개월/12**. 어긋나면 보고(수동 보완 대상).
  - `objectives`: `연구개발내용.성능목표[]` → (단계, 연차[목표치 키], 목표항목=평가항목, 목표치, 단위, 평가방법).
- **KR 외 항목 방어**: 스냅샷에 (있을 리 없지만) 타 기관 표기가 섞이면 그 item 은 버린다. 파싱 불가 셀은 보고하고 수동 보완 대상으로 남긴다.

### 4. 자동 diff (직전 현재값 ↔ 새 스냅샷)

- item key 로 매칭해 **신규**(이력 파일에 없던 key) / **변경**(현재값이 달라진 key, 전→후) / **삭제**(스냅샷에서 빠진 key)를 산출.
- `r0`(최초)면 전량 **신규**. 변경 0건인 항목은 그대로 둔다(건드리지 않음).
- **researchers 세 값은 한 묶음**: 계상률(참여기간참여율)·급여총액·계상인건비 중 하나라도 바뀌면 `연평균참여율`·`참여기간참여율`·`월별참여율` **셋을 모두 재계산해** 비교한다(하나만 비교/갱신 금지 — 셋은 연동값).

### 5. 변경사유 수집

- 변경·삭제가 있으면 §AskUserQuestion 으로 행별 사유를 받는다(일괄 입력 허용). `revisions.yaml` 에 이번 rev 레코드를 append(rev·date·type·reason·source·status).

### 6. 적재 (sparse hybrid)

- **신규**: 펼친 한 줄로 추가(`rev` = 이번 rev).
- **변경·삭제만**: 그 항목에 `history:` 1건 append + 최상위 현재값·`rev` 갱신. **첫 변경이면 직전 현재값을 history 첫 항목으로 함께** 적재. 삭제/하차는 최상위 `status: 삭제`(연구원 `제외`) + history 기록.
- **기존 `history` 항목은 수정·삭제 금지.** 안 바뀐 항목은 한 줄 유지(중첩하지 않음).
- **researchers 는 참여율 3값 + 급여총액을 함께 적재**: 신규·변경 모두 최상위 현재값과 그 `history` 항목에 `연평균참여율`·`참여기간참여율`·`급여총액`을 **함께**(월별이 평탄과 다르면 `월별참여율`도) 쓴다. 계상률·급여·월별 중 하나가 바뀌면 `참여기간참여율=Σ월별/참여개월`·`연평균참여율=참여기간×참여개월/12=계상인건비/급여총액` 를 재계산해 **셋·급여총액·인건비를 동시에** 갱신한다(한 값만 고쳐 정합 깨뜨리지 말 것). `급여총액`은 스냅샷/변경비교 YAML 값 그대로 적재(재생성 시 역산 불필요·무손실). 옛 `참여율` 단일 키만 있던 항목을 갱신할 땐 그 값을 `참여기간참여율`로 승계하고 나머지 두 값과 급여총액을 채운다.

### 7. 뷰 생성 (`emit_views`, `--no-views` 면 생략)

- `current_<entity>.md`(최신 rev pivot 표) + `changelog.md`(rev별 전→후 diff) 재생성.
- `current_researchers.md` 와 `changelog.md` 의 researchers 행엔 **세 값(연평균참여율·참여기간참여율·월별참여율 요약)** 을 함께 싣는다 — 한 값만 보이면 정합 확인이 안 됨.

### 8. 검증·보고

- YAML 파싱 유효성, item key 중복 없음, `rev` 가 `revisions.yaml` 에 존재하는지 확인.
- 이번 rev 의 **신규/변경/삭제 건수**, 파싱 실패 셀(수동 보완 필요), KR 외로 버린 항목(있으면)을 보고.
- 최종 보고: 과제 폴더 · 사용 스냅샷 · rev(type/source) · 엔티티별 신규/변경/삭제 · 뷰 갱신 여부.

## 변경비교 YAML 입력 모드 (researchers 전용)

> **두 변경비교 모드**: 최상위 키 `참여연구자인건비_변경비교` → **이 절(researchers)**, `연구개발비비목_변경비교` → **다음 절 §변경비교 YAML 입력 모드 (budget)**. 둘은 대칭 — 전/후가 baseline+delta 라 스냅샷 없이 `전→r0·후→새 rev` 로 직접 적재. 한 파일엔 한 엔티티만 담기므로 다른 엔티티는 그 모드에서 미추적(현재값은 스냅샷).

`rnd-manpower-change` 산출 `참여연구자인건비_<연차>_변경<NN>.yaml`(최상위 `참여연구자인건비_변경비교`)을 입력으로 받을 때. 참여자별 `전`/`후` 가 곧 **baseline+delta** 라 **스냅샷 없이** `전→r0·후→r1` 로 적재한다(researchers 전용). 첫 회만 `전`으로 r0 시드, 이후 변경은 다음 변경비교 YAML 의 `후` 로 직전 현재값에 누적. 예산·과제목표는 이 YAML에 없어 미추적(현재값은 스냅샷). 스냅샷은 필수 아님(단계 참조·`전` 검증에만).

> **입력(반드시 이 파일) — `rnd-manpower-change` 의 changes 산출물**: 스냅샷 `KR_*.yaml` 이 아니라 **참여연구자 변경비교 YAML** 을 인자로 준다. 예:
> `/rnd-kr-history RND_PROJECT\<과제>\<연차>\manpower_change\변경<NN>_<날짜>\참여연구자인건비_<연차>_변경<NN>.yaml`
> (실제 예: `…\MW급_…_차단기_개발\1차년도\manpower_change\변경01_2026-06-29\참여연구자인건비_1차년도_변경01.yaml`)
>
> **처리 순서**: 이 적재로 이력에 **새 rev(r1)가 생기고**, 이어서 **기본으로 재생성까지 자동 실행**해 `KR_<과제>_r<N>.yaml` 을 만든다(한 번 호출로 이력+스냅샷 완성). `--no-snapshot` 이면 이력만, base 스냅샷 없으면 재생성만 건너뛴다(이력은 정상 적재).

### 0'. 경로·메타 해석
- `proj_dir` = 입력 경로에서 `RND_PROJECT\<과제>`, `year_dir` = `proj_dir\<연차>`(경로가 `…\<과제>\<연차>\manpower_change\변경<NN>_<날짜>\` 라 연차가 경로에 있음). **`hist_dir = year_dir\history`**(연차별, rev 도 연차별 독립). 스냅샷(`year_dir\KR_*.yaml`)은 **선택적**(`단계` 참조·`전` 일치 검증용 — 없어도 동작). r0 기준선은 비교 YAML `전` 에서.
- `연차` = YAML `연차`. `단위` = YAML `단위`(천원). **`단계` = 같은 과제 스냅샷 `KR_<과제>.yaml` 의 `meta.단계`**(스냅샷 없거나 키 없으면 §AskUserQuestion·기본 `1단계`). `meta.수행기관`=KR 확인(스냅샷 있을 때).
- `source` 기본값 = 같은 폴더 `변경안_<연차>_변경<NN>.pdf`(없으면 `.md`). **`date`(발효일) 우선순위 = 품의서 시행일(`--품의서` 있으면 Read 로 직독·시행일 추출) > 폴더명 `변경<NN>_<날짜>` 의 날짜 > 질의**. (rnd-manpower-change 가 품의서 시행일로 회차 폴더를 만들었으면 폴더명 날짜가 곧 시행일 — 자동 일치.)

### 3'. 전/후 → researchers items (참여율 3값 — rerp 기준)
각 `참여자[]` 의 `전`/`후` 블록(`계상률`·`계상인건비`·`참여기간_개월`·`참여기간`)에서 r0(전)·r1(후) 값을 만든다:
- `참여기간참여율` = `계상률`(비교 YAML 값 그대로 — **rerp 최종 계상률** = 계상인건비/총 지급한도(월급여×개월)×100 의 소수 3자리 올림. 재계산하지 않는다)
- `연평균참여율` = `round(계상인건비 / 급여총액 × 100, 2)`(정의식 — 금액 기준. rerp 절삭·올림 때문에 `계상률×개월/12` 와는 근사(±0.05)로만 일치 — 어긋나도 정상, 정의식이 정본)
- `월별참여율`(**실측 우선**) = **`후` 는 참여자 `월별인건비[]` 의 `{월: 참여율}` 을 그대로**(rerp 실측 — 구간 변경·마지막 달 잔액로 월별 상이) 적재. 월별인건비가 없는 블록(`전` 등)만 `참여기간` 각 월에 `계상률` **평탄** fallback(완전 제외(개월 0)=빈 맵).
- `급여총액` = 참여자 `급여총액`(전·후 공통, YAML 값 그대로) · `월급여` = YAML `월급여`(급여총액/12 천원 절삭 — 있으면 함께 적재, 재생성·rerp 검산용)
- `인건비` = `계상인건비` · `status` = 블록 `status`(전=활성, 후=활성|제외) · `직급` = YAML `직위`
- 분류 매핑: `제외`→삭제(status 제외) · `변경`/`조정`→변경 · `추가`→신규. 참여자 `변경_적용기간`(언제부터~언제까지)은 history 항목에 `적용기간` 으로 함께 남긴다(있으면).
- 정합 확인(후, rerp): ① `참여기간참여율 == ceil2(인건비/(월급여×개월)×100)`(총 지급한도 대비 비율) ② `연평균참여율 == round(인건비/급여총액×100, 2)` ③ 월별 금액 합 = 계상인건비(비교 YAML `검증.월별합_일치` 참조). 어긋나면 보고. ⚠ 구식 `(급여총액/12)×개월×률` 재계산 대조는 rerp(절삭·잔액 배분)와 어긋날 수 있으므로 **정합 실패로 취급하지 않는다**(참고 표기만).

### 6'. 적재 (rev) — **전→r0, 후→r1 (researchers, 스냅샷 불필요)**
- **history 비어있음(`revisions` empty)**: 한 실행에 **r0(전)+r1(후)** — 첫 회만 `전`으로 r0 시드.
  - `r0`(기준선): 각 참여자 `전` 블록을 §3' 매핑으로 한 줄 신규 시드(`rev: r0`, history 없음, `status: 활성`). type=`최초협약`, reason="최초 기준선(변경 전)". date·source 는 알면 채우고(같은 폴더 변경안 PDF·스냅샷 있으면 `meta.협약일`), 모르면 §AskUserQuestion·빈값.
  - `r1`(변경): 각 참여자 `후` 블록으로 변경 반영 — 제외=최상위 `status:제외`+history, 변경/조정=history append+현재값 갱신, 추가=신규 한 줄. **각 항목 history 첫 항목에 `전`(r0) 값을 함께** 적재. 후 정합: `계상인건비 ≈ 급여총액(후) × 연평균참여율/100`. type/source/reason 은 §AskUserQuestion(아래).
- **history 이미 있음(직전 존재)**: r0·과거는 건드리지 않고 `후` 만 직전 현재값과 diff → 다음 rev append. **연쇄 무결성 검증(필수)**: 이번 비교 YAML 의 `전`(계상률·계상인건비·개월, 있으면 `월별인건비` 로 복원되는 전 월별)이 **이력의 직전 현재값과 일치하는지 대조** — 불일치면 **적재를 중단하고 보고**한다(직전 rev 누락·소급 재계산·다른 입력 사용 등 원인 확인 후 재시도. rnd-manpower-change `--extract-prev` 승계본이면 자동 일치). 즉 **이후엔 변경비교 YAML 로 계속 누적**(스냅샷 재참조 없음).
- `revisions.yaml` 에 rev 레코드 append(`적재: [researchers]`). **이 모드(researchers)에선 budget·objectives 는 미추적** — 예산 비목 변경은 짝 스킬 `rnd-budget-change` 의 비교 YAML(`연구개발비비목_변경비교`)을 §변경비교 YAML 입력 모드 (budget) 로 별도 적재(`적재: [budget]`)한다.
- **스냅샷은 필수 아님**: 있으면 `단계`(`meta.단계`)·`전` 일치 검증에만 쓰고, 없어도 동작(단계 기본 `1단계`/질의).

### 7'·(자동 재생성)·8'. 뷰·재생성·검증
- §7 뷰(`current_researchers.md`·`changelog.md`, researchers 행에 3값) 재생성.
- **자동 재생성(기본 on, `--no-snapshot` 이면 생략)**: 방금 적재한 최신 rev 를 **§스냅샷 재생성 모드(S1~S4)** 로 원본 스냅샷에 덮어 `year_dir\KR_<과제>_r<N>.yaml` 을 **바로 생성**한다(한 번 호출로 이력+현행 스냅샷 완성). base 스냅샷(`year_dir\KR_<과제>.yaml`)이 없으면 **재생성만 건너뛰고**(이력은 정상) "base 없어 재생성 생략 — `/rnd-kr-extract --format structured` 후 `/rnd-kr-history <과제이름>` 로 재생성" 안내.
- §8 검증·보고(신규/변경/삭제 건수, 미적재 엔티티 명시, **재생성 산출 경로·정합 결과**).

> **AskUserQuestion(이 모드)**: ① 단계 미확정 시 단계, ② r1 개정 유형(`연차변경`/`협약변경`/`계획수정`), ③ 변경·삭제 사유(행별, 일괄 허용). r0 메타는 스냅샷에서 자동(없으면 질의). **r1 발효일(`date`)** 은 품의서 시행일(`--품의서` Read 직독) > 폴더명 날짜 > 질의 순으로 확정.

## 변경비교 YAML 입력 모드 (budget)

`rnd-budget-change` 산출 `연구개발비비목_<연차>_변경<NN>.yaml`(최상위 `연구개발비비목_변경비교`)을 입력으로 받을 때. **researchers 모드와 완전 대칭** — 비목별 `전`/`후` 가 곧 **baseline+delta** 라 **스냅샷 없이** `전→r0(기준선)·후→새 rev(이번 변경)` 로 적재한다(budget 전용). 첫 회만 `전`으로 r0 시드, 이후 변경은 다음 변경비교 YAML 의 `후` 로 직전 현재값에 누적. 참여연구원·과제목표는 이 YAML에 없어 미추적(현재값은 스냅샷). 스냅샷은 필수 아님(단계 참조·`전` 검증에만).

> **입력(반드시 이 파일) — `rnd-budget-change` 의 changes 산출물**: 스냅샷 `KR_*.yaml` 이 아니라 **연구개발비 비목 변경비교 YAML** 을 인자로 준다. 예:
> `/rnd-kr-history RND_PROJECT\<과제>\<연차>\budget_change\변경<NN>_<날짜>\연구개발비비목_<연차>_변경<NN>.yaml`
> (실제 예: `…\MW급_10kV_고전압_직류_시스템용_반도체_차단기_개발\1차년도\budget_change\변경01_2026-07-15\연구개발비비목_1차년도_변경01.yaml`)
>
> **처리 순서(중요)**: 이 적재로 이력에 **새 rev(예: r2)가 먼저 생기고**, 이어서 **기본으로 재생성까지 자동 실행**해 `KR_<과제>_r<N>.yaml` 을 만든다(한 번 호출로 이력+현행 스냅샷 완성). `--no-snapshot` 이면 이력만 갱신하고, base 스냅샷(`KR_<과제>.yaml`)이 없으면 재생성만 건너뛴다(이력은 정상 적재). `_r<N>.yaml` 은 이력의 **결과물**이지 선행조건이 아니다(researchers 모드가 `_r1.yaml` 을 만든 방식과 동일).

### 0''. 경로·메타 해석
- `proj_dir` = 입력 경로에서 `RND_PROJECT\<과제>`, `year_dir` = `proj_dir\<연차>`(경로가 `…\<과제>\<연차>\budget_change\변경<NN>_<날짜>\` 라 연차가 경로에 있음). **`hist_dir = year_dir\history`**(연차별, rev 도 연차별 독립). 스냅샷(`year_dir\KR_*.yaml`)은 **선택적**(`단계` 참조·`전` 검증용 — 없어도 동작). r0 기준선은 비교 YAML `전` 에서.
- `연차` = YAML `연차`. `단위` = YAML `단위`(천원). **`단계` = 같은 과제 스냅샷 `meta.단계`**(없거나 키 없으면 §AskUserQuestion·기본 `1단계`). `meta.수행기관`=KR 확인(스냅샷 있을 때).
- `source` 기본값 = 같은 폴더 `변경안_<연차>_변경<NN>.pdf`(없으면 `.md`). **`date`(발효일) 우선순위 = 품의서 시행일(`--품의서` Read 직독) > 폴더명 `변경<NN>_<날짜>` 의 날짜 > 질의**.

### 3''. 전/후 → budget items (비목 경로 정규화)
`비목[]` 의 각 `{비목: <표시명>, 값:{전,후,증감}}` 에서 r0(전)·새rev(후) 값을 만든다:
- **비목 경로** = `직접비/` + **표시명→yaml 키 정규화**(`연구시설·장비비`→`연구시설장비비`, 그 외 동일). 즉 `직접비/인건비`·`직접비/연구시설장비비`·`직접비/연구재료비`·`직접비/연구활동비`·`직접비/연구수당`. ⚠ **snapshot-mode init·`예산.비목별` 역매핑과 반드시 같은 키**(가운뎃점 표기를 그대로 쓰면 키 불일치로 baseline 과 매칭 안 돼 전부 신규가 됨).
- **금액** = `전`(r0)·`후`(새rev).
- `간접비`(스칼라)·`총액.전/후` 도 각각 item: 비목 `간접비`·`연구개발비총액`(보통 불변 → r0 한 줄). `직접비/소계` 는 **도출값(=Σ직접비 비목)이라 item 으로 적재 안 함**(snapshot-mode 와 동일).
- **분류**: `증감 ≠ 0` → 변경(history) · `증감 = 0` → 불변(한 줄) · `전=0·후>0` → 도착 비목 신규 계상(전=0 baseline + 후 변경).
- **정합 확인**: Σ직접비 비목(후) = `직접비_소계.후`, `직접비_소계.후 + 간접비 = 총액.후`, Σ증감 = 0. 어긋나면 보고(적재 중단).

### 6''. 적재 (rev) — **전→r0, 후→새 rev (budget, 스냅샷 불필요)**
- **budget items 비어있음(baseline 미시드)**: 한 실행에 **r0(전) + 새 rev(후)**.
  - `r0`(기준선): 각 비목 item 의 `전` 값을 §3'' 매핑으로 한 줄 신규 시드(`rev: r0`, history 없음). **`revisions` 에 r0 가 이미 있으면**(예: researchers 로 먼저 초기화됨) **그 r0 를 재사용**(레코드 신설 금지) 하고 그 r0 레코드의 **`적재` 목록에만 `budget` 추가**(적재는 커버리지 메타라 누적 허용 — date·type 등 다른 필드는 불변). **없으면** r0 레코드 신설(type=`최초협약`, reason="최초 기준선(변경 전)", `적재: [budget]`).
  - `후`(변경): `증감 ≠ 0` 인 비목만 history append + 최상위 현재값·`rev` 갱신(**각 항목 history 첫 항목에 `전`(r0) 값을 함께** 적재). 불변 비목은 r0 한 줄 그대로. 새 rev = `--rev` 또는 **직전 rev + 1**(예: 직전 r1 → **r2**). type/source/reason 은 §AskUserQuestion.
- **budget items 이미 있음(직전 존재)**: r0·과거는 건드리지 않고 `후` 만 직전 현재값과 diff → 다음 rev append(`전` 이 직전 현재값과 다르면 보고). 즉 **이후엔 변경비교 YAML 로 계속 누적**(스냅샷 재참조 없음).
- `revisions.yaml` 에 새 rev 레코드 append(`적재: [budget]`). **researchers·objectives 는 미추적**(현재값은 스냅샷 `KR_*.yaml` 에서).
- **스냅샷은 필수 아님**: 있으면 `단계`(`meta.단계`)·`전` 일치 검증에만 쓰고, 없어도 동작(단계 기본 `1단계`/질의).

### 7''·(자동 재생성)·8''. 뷰·재생성·검증
- §7 뷰(`current_budget.md`·`changelog.md`, 비목별 전→후·증감) 재생성.
- **자동 재생성(기본 on, `--no-snapshot` 이면 생략)**: 방금 적재한 최신 rev 를 **§스냅샷 재생성 모드(S1~S4)** 로 원본 스냅샷에 덮어 `year_dir\KR_<과제>_r<N>.yaml` 을 **바로 생성**한다(한 번 호출로 이력+현행 스냅샷 완성). base 스냅샷(`year_dir\KR_<과제>.yaml`)이 없으면 **재생성만 건너뛰고**(이력은 정상) `/rnd-kr-extract` 후 재생성하라 안내. budget overlay 는 이력 items 가 있으므로 `예산.비목별` 이 최신 rev 값으로 덮인다.
- §8 검증·보고(신규/변경/삭제 건수, Σ증감=0·소계·총액 불변 재확인, rev 정합, 미적재 엔티티 명시, **재생성 산출 경로·정합 결과**).

> **AskUserQuestion(이 모드)**: ① 단계 미확정 시 단계, ② 새 rev 개정 유형(`연차변경`/`협약변경`/`계획수정`), ③ 변경 비목 사유(일괄 허용). r0 메타는 스냅샷/기본. **새 rev 발효일(`date`)** 은 품의서 시행일(`--품의서` Read 직독) > 폴더명 날짜 > 질의 순으로 확정.

## 스냅샷 재생성 모드 (`snapshot` — 이력 → 최신 `KR_<과제>_r<N>.yaml`)

적재의 **역방향**. 위치 인자가 **`.yaml` 이 아닌 과제이름·폴더경로**(또는 `snapshot <…>`)면 이 모드. **최신 rev 이력을 원본 스냅샷에 덮어(base + overlay)** 현행 스냅샷 `KR_<과제>_r<N>.yaml` 을 만든다. 이력은 sparse(추적 엔티티만)라 **원본 스냅샷이 반드시 base** — 이력이 손대지 않는 구조·비추적 블록(연구개발내용·수행일정·세부사용계획 등)·불변 필드(`국적` 등)의 출처다. 이력만으로는 전체 스냅샷을 복원할 수 없다.

> **경로 약어**: §절차와 동일(`proj_dir`·`year_dir`·`hist_dir`·스냅샷). 재생성 결과는 `year_dir\KR_<과제>_r<N>.yaml`(원본 `KR_<과제>.yaml` 은 건드리지 않음).

### S0. 대상 확정
1. 인자 해석: **폴더경로**면 그 폴더가 (a) 연차 폴더(`…\<과제>\<연차>`)면 그 연차, (b) 과제 폴더(`…\<과제>`)면 하위 연차 탐색. **과제이름**이면 `RND_PROJECT\<과제이름>` 로 해석. `--year <차년도>` 있으면 그 연차로 고정.
2. `hist_dir = year_dir\history` 확정. **없거나 `revisions.yaml` 이 비면 중단**("이력 없음 — 먼저 적재하거나 `init` 하라"). 연차가 여럿(각기 `history\`)이고 미지정이면 §AskUserQuestion 으로 고른다.
3. **base 스냅샷** = `year_dir\KR_<과제>.yaml`(없으면 `proj_dir\KR_<과제>.yaml`). **없으면 중단**("base 스냅샷 필요 — `/rnd-kr-extract --format structured` 먼저"). `meta.수행기관`=KR 확인.

### S1. 최신 rev·이력 로드
- `revisions.yaml` 로드 → **최신 rev `rN`**(마지막 레코드). 4개 이력 파일 로드. 각 엔티티의 **최상위 현재값**(= 최신 상태)을 취한다(history 리스트는 재생성에 불필요 — 현재값만 사용).

### S2. base 복사 → overlay
- base 스냅샷을 **깊은 복사**한다. `meta.rev = rN`, 헤더 주석에 `# [재생성 r<N>] 이력 최신값 반영본(materialized) — 정본 발췌본은 /rnd-kr-extract 산출. researchers(+추적 엔티티)만 이력으로 덮음` 을 단다. base 가 **당해 차년도 전용**이므로 재생성본도 그 연차 행만 담는다(타 연차 행을 끌어오지 않음).
- **researchers overlay** → `예산.참여연구자인건비[연차==year].참여자[]`(references/history_schema.md 역매핑표):
  - 각 **활성**(status≠제외) 참여자: `계상률=참여기간참여율`, `계상인건비=인건비`, `급여총액=급여총액`(이력에 있으면 그대로; 없으면 `round(인건비×100/연평균참여율)` 역산 + `⚠역산` 주석), `참여기간_개월=월별참여율 키 개수`(없으면 참여시작~참여종료), `직위=직급`, `구분=구분`. `국적` 은 **base 의 같은 성명 값 유지**(신규 참여자는 기본 `한국` + ⚠).
  - `status:제외` 참여자는 `참여자[]` 에서 **제거**, base 에 없던 **신규(추가)** 는 append. `소계 = Σ 계상인건비`(남은 참여자).
- **budget/objectives overlay**(이력 items 가 있을 때만): `예산.비목별`·`연구개발내용.성능목표` 의 해당 항목을 이력 현재값으로 덮는다. 비면(변경비교 researchers-전용 모드) base 값 유지.

### S3. 정합 검증
- 각 활성 참여자: `연평균참여율 == round(계상인건비/급여총액×100, 2)`(정의식 — 정본 검증) 및 `계상률 == ceil2(계상인건비/(월급여×개월)×100)`(rerp 최종 계상률 — 총 지급한도 대비 비율). ⚠ 구식 `(급여총액/12)×개월×률` 재계산은 rerp(월급여 절삭·잔액 배분·조정 흡수)와 ±수천원 어긋날 수 있어 **참고 표기만**(정합 실패 아님). 어긋나면 ⚠ 보고.
- `참여자 소계 == 예산.비목별[연차].직접비.인건비` 확인. 다르면 ⚠(총 인건비를 바꾼 변경인데 budget 이력이 안 따라옴 — 인건비 비목은 이 스킬(budget 모드)로 옮길 수 없으니 `rnd-manpower-change` 재배분분이 스냅샷/재적재에 반영됐는지 확인). YAML 파싱 유효성 확인.
- 재생성본에 타 연차 행이 없는지 `python .claude/skills/rnd-kr-extract/scripts/year_slice.py <재생성본.yaml> --check`(exit 2 면 ⚠ — base 가 구버전 전 연차 스냅샷이면 먼저 base 를 슬라이스).

### S4. 기록·보고
- `year_dir\KR_<과제>_r<N>.yaml` 로 쓴다. 같은 이름 있으면 재생성(결정론적)임을 알리고 덮어씀(원본 `KR_<과제>.yaml`·`.tpl` 은 절대 덮지 않음).
- 보고: 사용 base·hist rev(`rN`) · overlay 한 엔티티 · base 대비 참여자 변경(제외/추가/율변경) · 정합 검증 결과 · 출력 경로. 역산한 급여총액이 있으면 명시.

> **재생성 vs 적재**: 재생성은 **이력을 읽기만** 한다(rev 를 새로 만들지 않음, `revisions.yaml` 미변경). 값의 정본은 여전히 발췌본이고, 재생성본은 "이력이 말하는 현재 상태의 스냅샷 표현"이다. 이 재생성본을 다시 `/rnd-kr-extract` 정본으로 승격하려면 별도 판단.

## init · undo

> 둘 다 `--project`/스냅샷 으로 `proj_dir`·`year_dir`·`hist_dir`(=`year_dir\history`, 연차별) 를 먼저 확정한다. **init/undo 는 해당 연차 history 한 곳만** 다룬다(rev 도 그 연차 안에서). 엔진 없이 SKILL 절차대로 YAML 을 직접 다룬다(append-only 원칙의 예외인 `undo` 는 **확인 후** 수행).

### `init` — 이력 초기화 (현재 스냅샷 = r0 기준선)

1. `hist_dir` 존재하면 **"이미 초기화됨(최신 rev: …)"** 보고 후 종료(아무것도 안 함).
2. 없으면 `${CLAUDE_SKILL_DIR}/templates/history/` 4개 파일을 `hist_dir` 로 복사.
3. **현재 스냅샷**(`KR_*.yaml`, 변경 전 상태)을 §추적 엔티티 매핑대로 파싱 → `budget`·`researchers`·`objectives` items 를 **전량 신규**(각 항목 한 줄, `rev: r0`, history 없음)로 적재. **연차별 격리** — 그 스냅샷이 속한 `<연차>` 의 `history\` 에 시드한다. 스냅샷은 **당해 차년도 전용**(2026-10-06~, `rnd-kr-extract/scripts/year_slice.py --check` 통과본)이지만, 구버전처럼 타 연차 행이 섞여 있어도 **해당 연차 분만** 그 연차 history 에 넣는다(다른 연차는 그 연차 스냅샷으로 별도 init). **researchers 는 한 줄에 `연평균참여율`·`참여기간참여율`·`급여총액`(+월별 상이 시 `월별참여율`) 을 모두 시드**(계상률→참여기간참여율, 계상인건비÷급여총액→연평균참여율, 평탄→월별참여율, 급여총액→급여총액).
4. `revisions.yaml` 에 `r0` 레코드 append(`type: 최초협약`(또는 `최초`)·`date`·`source`·`status: 적용`). 사유는 "최초 기준선".
5. 뷰 생성(`current_*.md`·`changelog.md`).
6. 보고: 시드된 엔티티별 항목 수 · r0.

> **변경 적재 전에 호출**: history 없는 상태에서 변경(연구원 교체 등)을 적재하면 r0(변경 전)가 사라진다. **반드시 변경 전 스냅샷으로 `init`(r0) 먼저 → 이후 변경 반영 → append(r1)**. `rnd-manpower-change` 는 변경 시작 시 history 없으면 이 `init` 을 먼저 안내·트리거한다.

### `undo` — 가장 최근 rev 1건 되돌리기 (파괴적)

1. `revisions.yaml` 로드 → **최신 rev**(마지막 레코드) 식별. 없으면 "되돌릴 이력 없음" 종료. `r0` 만 있으면 "초기 기준선만 있음 — undo 불가(되돌리려면 history 폴더 삭제)" 안내.
2. **미리보기**: 각 `<entity>_history.yaml` 에서 이번 rev 로 바뀐 항목을 모은다 — (a) `history` 마지막 항목의 `rev == 최신rev` 인 항목, (b) `history` 없이 최상위 `rev == 최신rev` 인 한 줄 항목(그 rev 신규). 목록을 출력.
3. **§AskUserQuestion 확인**(복구 불가): `되돌리기` \| `중단`.
4. 확인 시 각 항목 처리:
   - **그 rev 신규**(history 없고 `rev==최신rev`, 또는 history 첫 항목이 그 rev): **항목 자체 삭제**.
   - **그 rev 에서 변경/삭제**(history 마지막 `rev==최신rev`): `history` 마지막 항목을 **제거(pop)**, 최상위 현재값·`rev`·`status` 를 **직전 history 항목 값으로 복원**(하차 `status:제외`→직전 `활성`). history 가 1건만 남아 그게 r0 시드면 history 키 제거(다시 한 줄). **researchers 는 `연평균참여율`·`참여기간참여율`(+월별참여율)·`급여총액`·인건비 를 모두 직전 값으로 함께 복원**(한 값만 되돌려 정합 깨뜨리지 말 것).
5. `revisions.yaml` 에서 최신 rev 레코드 **제거**.
6. 뷰 재생성. 검증: 남은 최신 rev 가 직전 rev 인지, 모든 항목에 최신rev 흔적이 없는지 확인.
7. 보고: 되돌린 rev · 삭제/복원 항목 수.

> **append-only 예외**: `undo` 는 과거 항목을 건드리는 유일한 동작. 한 번에 **최신 1건만**. 더 과거로 가려면 `undo` 를 반복(매번 확인). 정본 스냅샷은 건드리지 않는다(이력만 되돌림 — 스냅샷이 이미 변경 후라면 별도로 되돌릴 것).

## 구조 (sparse hybrid)

`revisions.yaml`(개정 레지스트리, rev 단일 출처) + 항목별 `<entity>_history.yaml`. 각 item 은 키로 식별, **현재값을 항상 펼침**. 한 번이라도 바뀐 item 만 `history:` 리스트.

```yaml
# budget_history.yaml — item key = (단계,연차,비목) · unit: 천원
items:
  # 변경 없는 항목 — 한 줄. rev = 최초 도입 개정. history 없음
  - {단계: 1단계, 연차: 1차년도, 비목: 직접비/인건비, 금액: 31425, rev: r0}

  # 변경된 항목 — 현재값 펼침 + 그 자리 history 리스트
  - 단계: 1단계
    연차: 1차년도
    비목: 직접비/연구활동비
    금액: 60000            # 현재값(= history 마지막)
    rev: r1
    history:
      - {rev: r0, 금액: 58700}
      - {rev: r1, 금액: 60000, 사유: 외주용역 증액, source: 협약변경_1차.pdf}
```

```yaml
# researchers_history.yaml — key=(성명,단계,연차) · 하차=status: 제외 + history
# 참여율 = 연평균참여율(연봉기준 인건비비율=인건비/급여총액) + 참여기간참여율(계상률=Σ월별/참여개월) + 월별참여율({YYYY-MM:%}). 셋 다 도메인 값(rev 아님)
# 급여총액 = 연봉 기준 연간 총액(천원) — 재생성·정합 분모(함께 적재해야 무손실)
# 연평균참여율 = 참여기간참여율 × 참여개월/12 ;  계상인건비 = 급여총액 × 연평균참여율/100 = (급여총액/12)×참여개월×(참여기간참여율/100)
items:
  # 변경 없는 참여자 — 한 줄(월별이 평탄하면 월별참여율 생략 가능)
  # 문창재: 참여기간참여율 10%, 9/12개월 → 연평균 7.5% (= 5175/69000), 급여총액 69000
  - {성명: 문창재, 단계: 1단계, 연차: 1차년도, 연평균참여율: 7.5, 참여기간참여율: 10, 급여총액: 69000, 인건비: 5175, status: 활성, rev: r0}

  # 참여율이 바뀐 참여자 — 세 값 + 급여총액 함께 펼침 + history (rerp: 월별은 실측, 계상률=월 참여율 평균 올림)
  - 성명: 김거화
    단계: 1단계
    연차: 1차년도
    연평균참여율: 20.58        # 현재값 = round(인건비/급여총액×100, 2) = 20944/101763 (정의식이 정본 — 계상률×개월/12 와는 근사)
    참여기간참여율: 27.45      # rerp 최종 계상률 = ceil2(인건비/(월급여×개월)×100) — 비교 YAML '후.계상률' 그대로
    월별참여율: {2026-04: 27.46, 2026-05: 27.46, 2026-06: 27.46, 2026-07: 27.46, 2026-08: 27.46, 2026-09: 27.46, 2026-10: 27.46, 2026-11: 27.46, 2026-12: 27.36}   # 월별인건비 실측(마지막 달 잔액, 표시용)
    급여총액: 101763          # 실제(계획 100000에서 갱신) — 재생성 시 역산 불필요
    인건비: 20944             # Σ월별 계상(2328×8+2320) — 잔액 흡수(조정)라 공식 재계산과 다를 수 있음(정상)
    status: 활성
    rev: r1
    history:
      - {rev: r0, 연평균참여율: 15, 참여기간참여율: 20, 급여총액: 100000, 인건비: 15000}   # 100000 × 15/100 = 15000 (=20×9/12)
      - {rev: r1, 연평균참여율: 20.58, 참여기간참여율: 27.45, 급여총액: 101763, 인건비: 20944, 적용기간: "2026-04 ~ 2026-12 (9개월)", 사유: 이용우 제외분 흡수(조정)+급여 실제값 반영, source: rev안_1차년도_rev01.pdf}
# objectives_history.yaml  — key=(단계,연차,목표항목)
```

- **현재값** = 최상위 펼친 값(계산 불필요). **이력** = `history` 있으면 그 리스트, 없으면 "`rev` 이후 불변". **삭제/하차** = 최상위 `status` + history 마지막 기록.

### 설계 노트 — 왜 sparse hybrid 인가

- 순수 평면(long-format): diff 쉽지만 안 바뀐 항목까지 rev 행이 늘어 노이즈.
- 순수 중첩: 가독성 좋지만 안 바뀐 항목도 불필요하게 중첩.
- **채택**: 대부분(안 바뀐 항목)은 한 줄, 바뀐 소수만 그 자리에서 전체 이력 → 노이즈 최소 + 현재값 명시 + 이력 가독성. 변경 시 객체 mutate(git diff 가 해당 블록 건드림)이나 변경 항목이 적어 국소적.

## DO

- **KR-only**: 한국선급 항목만 적재한다. 스냅샷에 타 기관 표기가 섞이면 버리고, 이력 파일·뷰에 KR 외 값을 넣지 않는다.
- 입력은 **구조화 스냅샷**(`KR_<과제이름>.yaml`). 없으면 `/rnd-kr-extract --format structured` 를 먼저 안내한다.
- **현재값은 펼쳐 두고 변경분만 `history` 에 추가**(sparse hybrid). 안 바뀐 항목은 한 줄 유지. 키에 `단계`>`연차` 를 둔다.
- 변경·삭제는 **사유를 사용자에게 받아** `revisions.yaml` rev 레코드와 함께 남긴다.
- **품의서가 있으면 그 시행일(효력발생일)을 rev 발효일(`date`) 기준**으로 쓴다(발효일=시행일; `--품의서` 파일을 Read 로 직독·추출). 없으면 폴더명 날짜·질의. 품의서 파일명은 `source` 로도 기록할 수 있다.
- `r0`(최초)면 스냅샷 전량을 신규로 시드한다.
- **researchers 는 `급여총액`을 세 참여율과 함께 적재**한다(스냅샷/변경비교 YAML 값 그대로) — 재생성이 무손실이고 `계상인건비=급여총액×연평균/100` 정합을 직접 검증할 수 있다.
- **변경비교 YAML(researchers·budget)은 스냅샷 없이 전→r0·후→새 rev 로 직접 적재**한다. **budget 은 표시명(`연구시설·장비비`)을 이력 item 키(`직접비/연구시설장비비`)로 정규화**해 snapshot-mode·`예산.비목별` 역매핑과 같은 키로 맞추고, `증감 ≠ 0` 인 비목만 history 를 단다(Σ증감=0·소계·총액 불변 재확인). r0 가 이미 있으면 재사용하고 그 `적재` 목록에만 `budget` 을 더한다.
- **변경비교 적재는 기본으로 재생성까지 한 번에** 한다: 적재로 새 rev 를 만든 직후 자동으로 `KR_<과제>_r<N>.yaml` 을 재생성한다(base 스냅샷 있을 때). 이력만 원하면 `--no-snapshot`, base 스냅샷이 없으면 재생성만 건너뛰고(이력은 정상) `/rnd-kr-extract` 를 안내한다.
- **재생성 모드**(과제이름/폴더 인자)는 이력 최신 rev 를 **원본 스냅샷에 덮어** `KR_<과제>_r<N>.yaml` 만 새로 쓴다(이력·원본 `KR_<과제>.yaml`·`revisions` 는 읽기만). base 스냅샷이 없으면 `/rnd-kr-extract` 를 먼저 안내한다.
- 끝에 신규/변경/삭제 건수와 파싱 실패·KR외 제외 항목을 보고한다(재생성 모드는 base 대비 참여자 변경·정합 검증·출력 경로).

## DON'T

- **타 기관 값을 이력에 섞지 않는다**(KR-only). 변환본 전체에서 직접 파싱하지 않는다(반드시 KR 스냅샷에서).
- 기존 `history` 항목을 수정·삭제하지 않는다(추가만). 안 바뀐 항목을 굳이 중첩으로 만들지 않는다.
- `참여기간`/`연평균참여율`/`참여기간참여율`/`월별참여율`(도메인 값)을 `rev`(이력축)와 섞지 않는다(월별참여율의 "월"은 도메인 시간축). `단계`>`연차`(계획축)를 이력으로 오인하지 않는다.
- **세 참여율을 따로 노는 값으로 두지 않는다**(rerp 정합): `참여기간참여율 = ceil2(인건비/(월급여×개월)×100)`(rerp 최종 계상률 — 총 지급한도 대비 비율), `연평균참여율 = round(인건비/급여총액×100, 2)`(정의식 — 정본). 월별참여율은 표시·대사용 실측(평균이 계상률과 정확히 일치하지 않아도 정상). ⚠ 구식 `참여기간×개월/12 = 연평균` 은 rerp 절삭·올림 탓에 근사(±0.05)로만 성립 — 정합 실패로 취급 금지. 어긋나면 적재 전 보고. 옛 `참여율` 키는 참여기간참여율로 읽음(하위호환).
- 같은 rev 를 중복 적재하지 않는다(레지스트리 확인).
- **budget 변경비교의 표시명을 이력 키에 그대로 쓰지 않는다**: `연구시설·장비비`(가운뎃점)를 키로 넣으면 snapshot 기반 baseline(`직접비/연구시설장비비`)과 매칭 실패 → 전부 신규로 오인. 반드시 yaml 키로 정규화한다. **인건비는 budget 모드로 옮기지 않는다**(개인별 재배분 → `rnd-manpower-change`).
- **이력만 갱신하고 끝내지 않는다**: 값의 정본은 발췌본·스냅샷이다. 값을 직접 고쳐야 하면 `/rnd-kr-extract` 로 스냅샷부터 갱신하도록 안내하고, 이력엔 델타만 남긴다.
- **재생성본(`KR_<과제>_r<N>.yaml`)으로 원본 스냅샷(`KR_<과제>.yaml`)이나 이력을 덮지 않는다**. 재생성은 별도 파일에만 쓴다. 급여총액을 이력에 안 남기고 재생성 시 역산에 의존하지 않는다(반올림 오차 — 있으면 ⚠).

## 흔한 함정

| 증상 | 원인 | 해결 |
|:---|:---|:---|
| 변경이 전부 "신규"로 잡힘 | item key 불일치(연차·비목 표기 차이) | key 정규화(비목 경로·연차 라벨 통일). `references/history_schema.md` 키 규칙 준수 |
| 타 기관 값이 이력에 들어감 | 스냅샷이 아니라 변환본에서 파싱 | 입력은 반드시 KR 스냅샷. `meta.수행기관` 확인, KR 외 item 폐기 |
| diff 가 매번 같은 변경 반복 | `history` 가 아닌 current 만 보고 비교 누락 | 직전 상태 = 이력 파일의 **현재값**. 그 값과 diff |
| `연평균/참여기간/월별참여율`을 rev 로 오해 | 도메인 값과 이력축 혼동 | 참여율 변경은 값 변경(history 기록), 연차 배분은 계획축(별 item), 월별참여율의 월은 도메인 시간 |
| 연평균참여율 ↔ 참여기간참여율 혼동 | 둘은 다른 분모(12개월 vs 참여개월) | 참여기간참여율=계상률(참여한 달 기준), 연평균=인건비/급여총액=참여기간×참여개월/12. 9개월 27.44%면 연평균 20.58% |
| 세 참여율이 따로 놂 | 한 값만 고치고 나머지 미갱신 | `참여기간=Σ월별/참여개월`, `연평균=참여기간×참여개월/12` 로 재계산해 일치(계상인건비=급여총액×연평균/100 과도 정합) |
| 월별참여율이 비어 평균만 있음 | 스냅샷에 월별 표 없음(정상) | 평탄 도출(`참여시작~참여종료` 각 월 = 참여기간참여율). 월별 상이 시에만 사용자 월별 표 입력 |
| 같은 rev 두 번 적재 | rev 재지정 없이 재실행 | 레지스트리에 rev 있으면 다음 rev 제안(§AskUserQuestion) |
| 스냅샷이 없음 | extract 를 structured 로 안 돌림 | `/rnd-kr-extract <입력> --format structured` 먼저 |
| 재생성 급여총액이 실제와 수천원 다름 | 옛 이력에 `급여총액` 없어 `인건비/연평균` 역산(반올림 오차) | 이력에 `급여총액` 직접 적재(무손실). 옛 이력은 역산값에 `⚠역산` 명시 |
| 재생성이 변경 미반영(옛 값) | 원본 스냅샷(`KR_<과제>.yaml`)만 보고 이력 무시 | 재생성은 **이력 최신 rev 현재값**을 base 에 overlay. 과제이름/폴더로 호출(`.yaml` 경로 아님) |
| 재생성 소계 ≠ 비목별 인건비 | 총 인건비 바꾼 변경인데 인건비 재배분이 스냅샷/이력에 안 실림 | ⚠ 보고 후 `rnd-manpower-change` 재배분분이 반영됐는지 확인(인건비는 budget 모드로 못 옮김) |
| budget 변경비교인데 비목이 전부 "신규" | 표시명(`연구시설·장비비`)을 이력 키로 그대로 씀 → baseline(`직접비/연구시설장비비`)과 불일치 | 표시명→yaml 키 정규화(`직접비/`+가운뎃점 제거). §변경비교 YAML 입력 모드 (budget) §3'' |
| budget 적재 후 소계·총액이 바뀐 것처럼 보임 | 비목만 옮겼는데 `간접비`·`연구개발비총액` item 을 안 넣음 | 불변 비목(간접비·총액)도 r0 한 줄로 시드. Σ증감=0·소계·총액 불변 검증 |

## 체크리스트

- [ ] `$ARGUMENTS` 해석(`show`/`help` 는 출력 후 종료).
- [ ] 스냅샷(`KR_<과제>.yaml`) 확정·로드, `meta.수행기관`=KR 확인(KR-only).
- [ ] `hist_dir` 스캐폴딩(없으면 템플릿 복사) + 4개 파일 로드.
- [ ] rev 결정(`--rev`/제안), type·source·date 수집(**품의서 있으면 Read 로 시행일 추출→발효일**, 없으면 폴더명 날짜/질의).
- [ ] 스냅샷 → 엔티티 items 매핑(KR 외 항목 폐기, 파싱 실패 보고).
- [ ] 직전 현재값과 diff → 신규/변경/삭제 산출(r0=전량 신규).
- [ ] 변경·삭제 사유 수집 → `revisions.yaml` rev append.
- [ ] sparse hybrid 적재(신규=한 줄, 변경=history append + 현재값 갱신, 삭제=status). researchers 는 `급여총액`도 함께. 기존 history 항목 미수정.
- [ ] (`emit_views`) `current_*.md`·`changelog.md` 재생성(`--no-views` 면 생략).
- [ ] YAML 유효성·rev 정합성 검증 + 신규/변경/삭제 건수·KR외 제외 보고.

**변경비교 YAML 입력 모드(researchers·budget)일 때:**

- [ ] 최상위 키로 모드 판별(`참여연구자인건비_변경비교`=researchers / `연구개발비비목_변경비교`=budget). `hist_dir=year_dir\history` 확정.
- [ ] 전→r0(기준선)·후→새 rev. history 비면 한 실행에 r0+새 rev, 이미 있으면 후만 diff→append. r0 가 이미 있으면 재사용 + 그 `적재`에 엔티티 추가.
- [ ] **budget**: 표시명→yaml 키 정규화(`직접비/연구시설장비비` 등), `증감≠0` 만 history, `간접비`·`연구개발비총액` 도 item(불변=한 줄). Σ증감=0·소계·총액 불변 검증.
- [ ] `revisions.yaml` 에 새 rev append(`적재:[researchers]` 또는 `[budget]`), 다른 엔티티는 미추적 명시. 발효일=품의서 시행일>폴더명 날짜>질의.
- [ ] 뷰(`current_<entity>.md`·`changelog.md`) 재생성.
- [ ] **(자동 재생성, `--no-snapshot` 아니면)** 방금 만든 rev 로 `KR_<과제>_r<N>.yaml` 생성(base 스냅샷 없으면 건너뛰고 `/rnd-kr-extract` 안내). 신규/변경/삭제 건수 + **재생성 경로·정합** 보고.

**재생성 모드(`snapshot`)일 때:**

- [ ] 인자 자동판별(`.yaml`=적재, 과제이름/폴더=재생성). 대상 `year_dir`·`hist_dir` 확정(연차 여럿·`--year` 미지정이면 §AskUserQuestion).
- [ ] 최신 rev `rN` 식별(`revisions.yaml`), base 스냅샷(`KR_<과제>.yaml`) 로드(없으면 extract 안내·중단).
- [ ] base 복사 → researchers(+budget/objectives items 있으면) 이력 현재값으로 overlay(역매핑표), 제외=제거·추가=append·소계 재계산. 급여총액은 이력값(없으면 역산 ⚠).
- [ ] 정합 검증(계상인건비=급여총액×연평균/100, 소계=비목별 인건비), `meta.rev=rN`·재생성 헤더.
- [ ] `year_dir\KR_<과제>_r<N>.yaml` 쓰기(원본·이력·revisions 미변경). base 대비 변경·정합·경로 보고.
