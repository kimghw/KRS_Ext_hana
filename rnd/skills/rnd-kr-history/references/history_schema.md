# 이력 스키마 · 스냅샷↔엔티티 매칭 (reference)

`rnd-kr-history` 가 **KR 구조화 스냅샷(`KR_<과제이름>.yaml`)**을 받아 이력으로 적재할 때의 **엔티티 item 스키마**와 **스냅샷→엔티티 매핑(매칭)**을 규정한다. 스냅샷 스키마(생산 측)는 `rnd-kr-extract/references/structured_output.md`, 무엇을 추출할지(포함/제외)는 `rnd-kr-extract/references/extract_fields.yaml`.

## 매칭 — profiles(추출) ↔ snapshot ↔ history(추적)

> **이 표가 매칭의 단일 출처다.** 셋이 어긋나면 이력이 비거나(추적 필드 미수집) 잘못된다. `rnd-kr-history` 는 0단계에서 스냅샷이 `track` 의 소스 키를 담고 있는지 검증하고, 없으면 "`extract_fields.yaml` 의 해당 필드를 켜고 `/rnd-kr-extract --format structured` 재실행"을 안내한다.

| history 엔티티 (`track`) | 스냅샷 키 (`KR_<과제>.yaml`) | extract_fields 섹션.필드 (켜져야 함) | 원본 장 |
|:---|:---|:---|:---:|
| `budget` | `예산.비목별[]` (+ `예산.외주용역[]`) | `예산.비목별`, `예산.외주용역` | 08 |
| `researchers` | `예산.참여연구자인건비[].참여자[]` | `예산.참여연구자인건비` | 08 (8-2) |
| `objectives` | `연구개발내용.성능목표[]` | `연구개발내용.성능목표` | 02 (2-1) |

- `meta.단계` = 모든 item 의 `단계`. `meta.수행기관` = 한국선급(KR) 확인용(아니면 중단).
- `track` 에 있는데 스냅샷에 소스 키가 없으면 → **매칭 실패**(보고 후 그 엔티티 건너뜀, extract_fields 보강 안내).
- `extract_fields` 에서 해당 필드를 끄면(예: `참여연구자인건비: false`) → 그 엔티티는 추적 불가. 이력을 쓰려면 켜 둔다.

## 엔티티 item 스키마

### budget — key=(단계, 연차, 비목) · unit: 천원

| 필드 | 의미 | 스냅샷 출처 |
|:---|:---|:---|
| 단계 | 계획축 상위 | `meta.단계` |
| 연차 | 계획축 하위(1~4차년도) | `예산.비목별[].연차` |
| 비목 | 비목 경로(`직접비/인건비` 형태) | `예산.비목별[].직접비.<항목>`·`간접비`·`총액`, `예산.외주용역` → `직접비/연구활동비/외주용역비` |
| 금액 | 현재 금액(천원, 수치) | 해당 값 |
| 비고 | (선택) 외주용역명 등 | `예산.외주용역[].용역명` |

비목 정규화 예: `직접비/인건비`, `직접비/연구시설장비비`, `직접비/연구재료비`, `직접비/연구활동비`, `직접비/연구활동비/외주용역비`, `직접비/연구수당`, `간접비`, `연구개발비총액`. **연구시설·장비비(가운뎃점 표시명)는 yaml 키 `연구시설장비비`로 정규화**해 `직접비/연구시설장비비` 로 쓴다(스냅샷 `예산.비목별[].직접비` 의 yaml 키와 일치 — snapshot-mode·변경비교 budget-mode 모두 같은 키).

### researchers — key=(성명, 단계, 연차)

| 필드 | 의미 | 스냅샷 출처 |
|:---|:---|:---|
| 성명 | 참여자 | `참여자[].성명` |
| 직급/역할 | | `참여자[].직위`(역할은 있으면) |
| 참여시작/참여종료 | 도메인 값(이력축 아님) | 기간 표기 분해(있으면) |
| 연평균참여율 | **연봉(12개월) 기준 인건비 비율(%)** = `계상인건비/급여총액×100` — 헤드라인(연봉 대비 실제 인건비 비중) | `계상인건비 ÷ 급여총액`(도출) |
| 참여기간참여율 | **참여기간 중(참여한 달 기준) 참여율(%)** = 계상률 (구 `참여율`) | `참여자[].계상률` |
| 월별참여율 | 참여기간 각 월의 참여율 맵 `{YYYY-MM: %}`(매월 참여율) | **스냅샷 `참여자[].월별참여율` 있으면 정본**(extract `monthly_rate`), 없으면 참여기간 평탄 도출(또는 사용자 월별 표) |
| 급여총액 | **연봉(12개월) 기준 연간 총액(천원)** — 계상인건비·연평균참여율의 분모(정합·재생성용) | `참여자[].급여총액`(변경비교 YAML `급여총액`) |
| 인건비 | 계상 인건비(천원) | `참여자[].계상인건비` |
| status | 활성/제외(하차) | 기본 활성, 빠지면 제외 |

> **급여총액을 함께 적재하는 이유**: `연평균참여율 = 인건비/급여총액×100` 이 파생값이라 이력에 급여총액이 없으면 스냅샷 **재생성 시 급여총액을 역산**(`round(인건비×100/연평균참여율)`)해야 하고, 연평균참여율이 소수 2자리로 반올림돼 실제와 수천원 어긋날 수 있다(예: 문창재 도출 69,880 vs 실제 69,877). **급여총액을 직접 저장하면 재생성이 무손실**이고 `계상인건비 = 급여총액 × 연평균/100` 정합을 직접 검증할 수 있다. 옛 이력(급여총액 없음)은 하위호환으로 역산(⚠ 표시).

**참여율 3값(연평균·참여기간·월별) 규칙**

- 사용자 정의 — 참여율은 **둘을 따로** 본다: **연평균참여율**(연봉기준 인건비 비율) ↔ **참여기간참여율**(참여한 달 기준 비율, =계상률). 분모가 다르다(12개월 vs 참여개월).
- `참여기간참여율` = 계상률(%) — **rerp 최종 계상률 = ceil2(계상인건비/(월급여×개월)×100)**(총 지급한도 대비 지급금액 비율, 소수 3자리 올림). 참여하는 달의 실제 참여율. (월 참여율 '평균' 방식 아님)
- `연평균참여율` = `round(계상인건비/급여총액×100, 2)` — **정의식(금액 기준)이 정본**. `참여기간참여율 × 참여개월/12` 와는 rerp 절삭·올림 탓에 **근사(±0.05)로만** 일치(어긋나도 정합 실패 아님).
- `월별참여율` = 참여기간(`참여시작~참여종료`) 각 월의 % 맵(매월 참여율). **정본 우선순위: ① 변경비교 YAML `참여자[].월별인건비[].참여율`(rerp 실측 — 구간 변경·마지막 달 잔액로 월별 상이) ② 스냅샷 `참여자[].월별참여율`(extract `monthly_rate`) ③ 평탄 도출**(각 참여월 = 참여기간참여율, 비참여월은 키 없음).
- **정합(rerp)**: ① `참여기간참여율 = ceil2(인건비/(월급여×개월)×100)` ② `연평균참여율 = round(인건비/급여총액×100, 2)` ③ 월별 계상 합 = 계상인건비(변경비교 YAML 쪽 검증). ⚠ 구식 `계상인건비 = (급여총액/12)×참여개월×률` 재계산 대조는 rerp(월급여 천원 절삭·앞월 올림·마지막 달 잔액·조정 잔액 흡수)와 어긋날 수 있어 **참고 표기만**(정합 실패로 취급 금지).
  - 예) 김거화 1차년도(9/12개월, rerp): 월별 계상 2328×8+2320=20944 → 참여기간참여율 = ceil2(20944/76320×100=27.4423) = **27.45%**, 연평균 = 20944/101763 = **20.58%** (월 참여율 표시 27.46×8·27.36).
- **하위호환**: 기존 이력의 `참여율` 키는 `참여기간참여율`로 읽는다(`참여율` ≡ `참여기간참여율` = 계상률). 새로 적재할 땐 `연평균참여율`·`참여기간참여율`(+ 필요 시 `월별참여율`)을 쓴다.
- **이력 추적**: 세 값 모두 도메인 값(`rev` 아님). 변경 시 `history` 항목에 `연평균참여율`·`참여기간참여율`(+ 바뀐 경우 `월별참여율`)을 함께 남긴다. 월별참여율의 "월"을 `rev`(이력축)와 혼동 금지.

### 변경비교 YAML → researchers (rnd-manpower-change 연계)

`참여연구자인건비_변경비교`(rnd-manpower-change 산출, `참여연구자인건비_<연차>_변경<NN>.yaml`)를 입력으로 받는 **researchers 전용** 경로. 참여자 `전`/`후` 가 곧 baseline+delta → **`전`→r0·`후`→r1** (스냅샷 불필요). 첫 회만 `전`으로 r0 시드, 이후 변경은 다음 변경비교 YAML 로 누적. 스냅샷은 `단계` 참조·`전` 검증에만(선택).

| 비교 YAML 필드 | history 필드 |
|:---|:---|
| `참여자[].성명`·`직위`·`구분` | 성명·직급·(구분) |
| `참여자[].급여총액` | 급여총액 (전·후 공통, 재생성·정합용) |
| `전`/`후`.`계상률` | 참여기간참여율 (rerp 최종 계상률 — 재계산 없이 그대로) |
| `round(계상인건비/급여총액×100, 2)` | 연평균참여율 (정의식 — 금액 기준) |
| **`후`: `참여자[].월별인건비[].{월: 참여율}` 실측** · `전`(월별 없음): `참여기간` 평탄 | 월별참여율 (완전 제외=빈 맵) |
| `전`/`후`.`계상인건비` | 인건비 |
| `전`/`후`.`status` | status(활성/제외) |
| `참여자[].분류` | 제외→삭제 · 변경/조정→변경 · 추가→신규 |
| `참여자[].변경_적용기간` | history 항목 `적용기간`(언제부터~언제까지, 있으면) |
| `참여자[].월급여` | 월급여(급여총액/12 천원 절삭 — 있으면 함께, rerp 검산용) |

- `단계` = 같은 과제 스냅샷 `meta.단계`(없으면 질의·기본 `1단계`), `과제`·`연차` = 경로·YAML. **예산·과제목표는 이 YAML에 없음**(스냅샷 경로 또는 budget 변경비교로 별도 적재).
- 정합(후, rerp): `참여기간참여율 == ceil2(인건비/(월급여×개월)×100)` · `연평균참여율 == round(인건비/급여총액×100, 2)`. 세부 절차는 SKILL.md "변경비교 YAML 입력 모드 (researchers 전용)".
- **연쇄(직전 이력 존재) 적재 시**: 비교 YAML `전` 이 이력의 직전 현재값과 일치해야 한다(불일치=적재 중단·보고 — 소급 재계산·rev 누락 의심).

### 변경비교 YAML → budget (rnd-budget-change 연계)

`연구개발비비목_변경비교`(rnd-budget-change 산출, `연구개발비비목_<연차>_변경<NN>.yaml`)를 입력으로 받는 **budget 전용** 경로. 비목 `전`/`후` 가 곧 baseline+delta → **`전`→r0·`후`→새 rev**(스냅샷 불필요). researchers 모드와 대칭. 첫 회만 `전`으로 r0 시드, 이후 변경은 다음 변경비교 YAML 로 누적. 스냅샷은 `단계` 참조·`전` 검증에만(선택).

| 비교 YAML 필드 | history 필드 |
|:---|:---|
| `비목[].비목`(표시명 `연구시설·장비비` 등) | 비목 = `직접비/` + **yaml 키 정규화**(`연구시설·장비비`→`연구시설장비비`) → `직접비/연구시설장비비` |
| `비목[].값.전` | 금액 (r0 기준선) |
| `비목[].값.후` | 금액 (새 rev) |
| `비목[].값.증감` | `≠0`→변경(history) · `=0`→불변(한 줄) · `전=0·후>0`→도착 비목 신규 계상 |
| `간접비`(스칼라) | item `간접비`(보통 불변 → r0 한 줄) |
| `총액.전`/`총액.후` | item `연구개발비총액`(보통 불변 → r0 한 줄) |
| `직접비_소계` | **item 아님**(도출값 = Σ직접비 비목) |
| `이동[]`(from/to/금액) | 변경 사유·요약에 반영(예: "연구활동비→연구시설·장비비 15,000 재배분") |

- `단계` = 같은 과제 스냅샷 `meta.단계`(없으면 질의·기본 `1단계`), `과제`·`연차` = 경로·YAML. **참여연구원·과제목표는 이 YAML에 없음**(스냅샷/researchers 변경비교로 별도).
- **비목 키는 표시명이 아니라 yaml 키로 정규화**해야 snapshot-mode init 의 baseline(`직접비/연구시설장비비`)과 매칭된다(가운뎃점 그대로면 전부 신규로 오인). ⚠ **인건비는 budget 모드로 이동 불가**(개인별 재배분 → rnd-manpower-change).
- 검증(후): Σ직접비 비목 = `직접비_소계.후`, `직접비_소계.후 + 간접비 = 총액.후`, Σ증감 = 0. 세부 절차는 SKILL.md "변경비교 YAML 입력 모드 (budget)".

| status | 활성/삭제(폐기) | 기본 활성 |

## sparse hybrid 구조 (재확인)

- 항목별 **현재값 최상위 펼침** + **바뀐 항목만** `history:` 리스트. 안 바뀐 항목은 한 줄.
- `history` 항목은 **추가만**(과거 수정·삭제 금지). 변경 시 최상위 현재값·`rev` 만 갱신. 첫 변경이면 직전 현재값을 history 첫 항목으로 함께.
- 삭제/하차 = 최상위 `status: 삭제`(연구원 `제외`) + history 마지막 기록.
- `rev` = `revisions.yaml` 외래키. 두 시간축(`단계`>`연차` 계획축 / `rev` 이력축) 분리.

## r0 (최초) — 스냅샷 시드

레지스트리가 비어 있으면 이번 rev=`r0`, 스냅샷 전량을 **신규**로 적재(history 없음, 각 item `rev: r0`). 이는 과거 `rnd-kr-extract` 가 인라인으로 하던 "history 시드"를 `rnd-kr-history` 가 이어받은 것이다.

## 재생성(materialize) — 이력 → 최신 스냅샷 역매핑

`snapshot`(스냅샷 재생성) 모드는 적재의 **역방향**이다: 최신 rev 의 이력 현재값을 **원본 스냅샷(base)에 덮어(overlay)** `KR_<과제>_r<N>.yaml` 을 만든다. 이력은 sparse(추적 엔티티만)이라 **원본 스냅샷이 반드시 base**(구조·비추적 블록·`국적` 등 불변 필드의 출처)다.

**researchers → `예산.참여연구자인건비[연차].참여자[]` 역매핑**

| 스냅샷 참여자 필드 | 이력 현재값에서 |
|:---|:---|
| 성명·구분 | 성명·구분 그대로 |
| 직위 | 직급 |
| 급여총액 | 급여총액(이력에 있으면 그대로; 없으면 `round(인건비×100/연평균참여율)` 역산 ⚠) |
| 참여기간_개월 | 월별참여율 키 개수(없으면 `참여시작~참여종료` 개월) |
| 계상률 | 참여기간참여율 |
| 계상인건비 | 인건비 |
| 국적 | **base 스냅샷의 같은 성명 값 유지**(신규 참여자는 기본 `한국` ⚠) |

- `status: 제외` 참여자는 `참여자[]` 에서 **제외**, 신규(추가)는 base 에 없으니 **추가**. `소계` = 남은 참여자 계상인건비 합.
- 정합 재검증(각 활성 참여자): `계상인건비 == round((급여총액/12)×참여개월×(계상률/100))` **및** `== round(급여총액×연평균/100)`. 어긋나면 ⚠ 보고.
- **budget/objectives 는 이력에 items 가 있을 때만** `예산.비목별`·`연구개발내용.성능목표` 를 덮는다. 비면(변경비교 모드 등) base 값 유지. 단 `소계(참여자합)`≠`비목별.직접비.인건비` 면 ⚠(총 인건비를 바꾼 변경인데 budget 미추적).
