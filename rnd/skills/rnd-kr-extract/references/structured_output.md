# 구조화 추출(YAML/JSON) 스키마 — KR 연구개발 내용 + 예산

`/rnd-kr-extract --format structured` 가 만드는 결과물의 **모양(스키마)·예시**다.
무엇을 넣고 뺄지(섹션·필드 on/off, include/exclude)는 [extract_fields.yaml](extract_fields.yaml) 에서만 정한다. 이 문서는 그 정책으로 뽑은 값이 **어떤 키 구조**로 들어가는지를 규정한다.

> 원칙
>
> - **무손실 값**: 금액·목표치·기간은 원문 그대로(요약·반올림·합계 신규생성 금지). 단위는 `예산.단위`(기본 천원)로 통일.
> - **당해 차년도만(2026-10-06 개정)**: 연차 폴더 `<차년도>\` 의 스냅샷은 **그 차년도 행만** 담는다. 연차(`연차: N차년도`·`목표치: {N차년도: …}`)는 이력의 "변경"이 아니라 **계획 배분**이라 키로는 남기되, 값은 당해 1개 연차뿐이다. 타 연차 계획값은 그 연차 폴더의 스냅샷(없으면 발췌본 `<과제>_KR/NN_*.md`·전체 변환본 `original/`)에서 본다. 집행·검증은 `scripts/year_slice.py`(§차년도 슬라이스).
> - **KR 만**: 타 기관 행·블록은 넣지 않는다.
> - **추적성**: 모든 값은 장별 KR 발췌본(`<과제이름>_KR/NN_*.md`)의 셀로 역추적되어야 한다. 발췌본 = 무손실 정본, 구조화본 = 파생 데이터.

## 파일

| 파일 | 조건 | 비고 |
|:---|:---|:---|
| `KR_<과제이름>.yaml` | `structured.format: yaml`(기본) | 구조화 결합본(정본) |
| `KR_<과제이름>.json` | `structured.format: json` 또는 `both` | 동일 데이터의 JSON 사본(연동용) |

위치: 연차 폴더 `RND_PROJECT/<과제이름>/<차년도>/`(마크다운 결합본·발췌본 `<과제이름>_KR/`·`history/` 와 같은 곳). **연차 폴더 하나 = 그 차년도 행만**(§차년도 슬라이스).

## 최상위 스키마

```yaml
# [<차년도> 최초]                  # ★파일 첫 줄★ — 연차 최초(r0) 기준선 마커 (차년도=meta.차년도/output.stage, 예: [1차년도 최초])
# KR(한국선급) 연구개발 내용·예산 구조화 스냅샷   # 기존 헤더 주석(설명)은 마커 아래
meta:
  과제명: <문서 표지 과제명>
  수행기관: 한국선급(KR)
  단계: 1단계
  차년도: 1차년도                 # 당해 차년도(= 연차 폴더명). 이 파일엔 이 연차 행만 들어간다(year_only)
  연차범위: [1차년도, 2차년도, 3차년도, 4차년도]   # 과제 식별정보 — 전 연차 유지(슬라이스 대상 아님)
  기간: "2026-04 ~ 2029-12"      # 판독 가능 시
  연차별기간:                     # 표지 연차별 연구개발기간 표(판독 가능 시, 전 연차 유지) — 당해 연차 판정·기간 표기에 사용
    1차년도: "2026-04-01 ~ 2026-12-31"
    2차년도: "2027-01-01 ~ 2027-12-31"
  source: <원본 파일명>           # 예: 연구계획서.pdf
  rev: r0                         # history 연계 개정 id(있으면)
  표지:                           # 원본 00장(표지·요약문·목차) 식별정보 — 전 기관 공통(KR-only 예외)
    중앙행정기관: 산업통상부
    전문기관: 한국산업기술기획평가원
    사업명: {세부: 조선해양산업기술개발사업, 내역: 친환경선박전주기핵심기술개발}
    연구개발과제번호: RS-2026-25547199
    주관연구개발기관: {기관명: 인텍전기전자, 기관유형: 중소기업}
    총연구개발비:                 # 표지 연구개발비 표 합계행(전 기관 합산, 천원)
      정부지원_현금: 10000000
      기관부담_현금: 277000
      기관부담_현물: 3003250
      합계: 13280250
    KR:                          # 공동연구개발기관 표의 '한국선급' 행
      역할: 공동
      기관유형: 기타비영리
      책임자: 김거화             # 원문 오타(김거하)는 무손실 주석으로 표기
      직위: 수석연구원

연구개발내용:                     # extract_fields.sections.연구개발내용 (02장)
  목표: [...]                     # fields.목표
  성능목표: [...]                 # fields.성능목표
  성과지표: [...]                 # fields.성과지표
  수행일정: [...]                 # fields.수행일정
  주요결과물: [...]               # fields.주요결과물

예산:                             # extract_fields.sections.예산 (08장)
  단위: 천원
  지원부담: [...]                 # fields.지원부담 (8-1)
  비목별: [...]                   # fields.비목별 (8-2 총괄표)
  참여연구자인건비: [...]         # fields.참여연구자인건비 (8-2 현황표)
  외주용역: [...]                 # fields.외주용역 (8-3 (3))
  세부사용계획: [...]             # fields.세부사용계획 (8-3 (3-1))
  간접비세부: [...]               # fields.간접비세부 (8-3 (4))
  연구실안전관리비: {...}         # fields.연구실안전관리비 (06장 계상근거·용도 + 08장 간접비세부 금액)
```

`fields.<키>: false` 인 블록은 키 자체를 생략한다(빈 리스트로 두지 않는다).

> **meta.표지(과제 식별정보)**: 원본 **00장(표지·요약문·목차)** 의 첫 장에서 과제 식별 필드를 담는 블록이다(`extract_fields.yaml` 의 `meta.표지.enable: true` 일 때만; false 면 키 생략). 다른 섹션과 달리 **KR-only 예외** — 과제 식별을 위해 `중앙행정기관`·`전문기관`·`사업명`·`연구개발과제번호`·`주관연구개발기관`·`총연구개발비` 등 **전 기관 공통 필드**를 넣는다. 단 공동기관 상세는 **KR 행(`표지.KR`)만**. 출처는 **KR 발췌본이 아니라 전체 변환본** `original/00_표지_요약문_목차.md` 이므로, 구조화 시 이 00장 변환본을 직접 읽어 채운다. **`총연구개발비.합계` 는 전 기관 합산**이라 `예산.지원부담`(KR 한정 정부지원·기관부담)과 **다른 값**이다(혼동 주의 — 서로 합산·대체하지 않는다). 책임자 성명이 원문 오타로 이메일 등과 불일치하면 무손실 주석으로 보존(예: 원문 `김거하` → `김거화`).

> **연차 최초 마커(첫 줄)**: 구조화본 파일의 **맨 첫 줄**에 `# [<차년도> 최초]` 주석을 둔다(차년도 = `meta.차년도`/`output.stage`). 이 스냅샷이 해당 **연차의 최초(r0) 기준선**임을 한눈에 표시하는 마커다. YAML 주석이라 파싱엔 영향 없음(다운스트림 `/rnd-kr-history`·`rnd-manpower-change` 는 무시). **JSON 사본엔 주석이 없으므로 마커는 YAML 정본에만** 남는다. `/rnd-kr-extract` 산출은 늘 그 연차 baseline 이라 마커는 `최초` 로 고정(변경 이력은 `/rnd-kr-history`).

## 연구개발내용 — 블록별 모양

```yaml
목표:                             # 연차별 ① 개발목표 + ② 개발내용·범위(R&R)
  - 연차: 1차년도
    개발목표:
      - 선급규정·국제표준 간 규정 공백 분석 및 평가 기준 도출
      - 규정·표준 도메인 분석 및 용어 분류 체계 설계
    개발내용:                     # ② 개발내용 및 범위 (항목 → 세부 R&R)
      - 항목: 선급규정·국제표준 간 규정 공백 분석 및 평가 기준 도출
        세부:
          - 선급규정 및 국제표준 비교·분석을 통한 규정 공백 도출
          - MVDC 적용 시 시험기준 도출 및 평가항목 정립
      - 항목: 규정·표준 도메인 분석 및 용어 분류 체계 설계
        세부: ["...", "..."]

성능목표:                         # 2-1 정량 성능목표 (KR 행만)
  - 평가항목: SSCB 규정 공백 분석
    단위: 건
    목표치: {1차년도: 1}          # 목표 연차만 키로
    평가방법: 외부 전문가 평가
    인증기준: null                # 없으면 null

성과지표:                         # 2-1 KPI (KR 표) — 당해 차년도 키만(원문의 `계`·타 연차 열은 year_slice 가 제거). 당해 배정이 없으면 `[]`
  - 지표: 논문(비SCI)
    목표: {1차년도: 1}
    가중치: "0.38%"

수행일정:                         # 2-3 연차별 일정
  - 연차: 1차년도
    기간개월: 9
    항목:
      - 개발내용: 선급규정·국제표준 간 규정 공백 분석 및 평가 기준 도출
        기간주: 32
        착수월: 5                 # 판독 가능 시(간트 ● 시작/끝)
        종료월: 12

주요결과물:                       # 2-3 연차별 결과물
  - 연차: 1차년도
    결과물:
      - 선급규정·국제표준 간 규정 공백 분석 및 평가 기준 도출
      - 규정·표준 도메인 분석 및 용어 분류체계 설계
```

```yaml
  합계: null                      # 원문에 안전관리비 합계 행이 있을 때만 그대로; 없으면 null(임의 합산 금지)
```

> `연구실안전관리비` 는 금액의 정본이 08장 간접비세부(`간접비세부` 의 `세부내용: 연구실 안전관리비` 행)와 동일하다 — 같은 돈을 06장 계상근거(용도)와 묶어 한 곳에서 보게 한 파생 뷰다. 합계는 원문에 합계 행이 있을 때만 옮기고, 없으면 `null`(직접 더하지 않는다). 06장에 KR 안전관리비 금액 표가 따로 없고 용도만 서술돼 있으면 `연차별금액` 은 08장에서, `용도`·`계상기준` 은 06장에서 채운다.

## 차년도 슬라이스 — 당해 차년도 전용 (`scripts/year_slice.py`, 2026-10-06~)

연차 폴더 `<차년도>/` 의 스냅샷에는 **그 차년도 행만** 둔다. 구조화 에이전트가 당해 연차만 채우더라도 결정론 슬라이서로 한 번 더 자르고 `--check` 로 검증한다.

| 대상 | 규칙 |
|:--|:--|
| `연차` 키를 가진 리스트 항목(목표·수행일정·주요결과물·지원부담·비목별·참여연구자인건비·외주용역·세부사용계획·간접비세부·연구실안전관리비.연차별금액) | 당해 차년도 항목만 남김(블록·한 줄 항목 모두) |
| 성능목표 `목표치`·성과지표 `목표` 의 `{N차년도: 값}` 맵 | 당해 키 없는 항목 삭제, 있는 항목은 당해 키만(타 연차·`계` 제거). 연차 키가 없는 맵(과제 통합표 `{계: 5}`)은 그대로 |
| `meta` | 슬라이스 대상 아님(`연차범위`·`연차별기간`·`기간`·`표지` 유지). `meta.차년도` 보장 |
| 전부 타 연차였던 리스트 | `키: []` + 주석. 당해 연차분이 원문에 없는 블록(후속 연차 개인별 인건비 등)은 **명시적 빈 블록**(`- 연차: N차년도`·`참여자: []`·`소계: null`) |

| 검증 | 텍스트 슬라이스 == PyYAML 데이터 필터(불일치면 쓰지 않음). `--check`: 타 연차 잔존 시 exit 2 |

```text
python .claude/skills/rnd-kr-extract/scripts/year_slice.py <KR_과제.yaml> [--year N차년도] [-o 출력] [--dry-run]
```

타 연차 계획값은 그 연차 폴더의 스냅샷(없으면 발췌본 `<과제이름>_KR/NN_*.md`·전체 변환본 `original/`)에서 본다. `/rnd-project-publish` 는 연차 폴더별 스냅샷을 연차 순으로 병합하고, 폴더가 없는 연차는 "미추출"로 표기한다.

## 입력 포맷 노트 (PDF / HWP)

구조화 추출도 **변환→발췌→구조화** 순서다. 변환만 포맷별로 다르다.

| 입력 | 변환 경로 |
|:---|:---|
| PDF(사업계획서·연구계획서) | `/pdf2md_by_read` (아웃라인→목차→20p 폴백). 장별 1파일 |
| **HWP(한글)** | ① **한컴오피스(설치 시) COM 으로 HWP→PDF** 후 위 PDF 경로 재사용(권장, 표 보존 우수) ② 또는 `pip install pyhwp` → `hwp5html`(표 유지)/`hwp5txt` 로 직접 추출 ③ 폴백: `hwp5txt` 텍스트만(표 깨질 수 있음 → 원본 대조) |
| HWPX | zip(OOXML 계열) → `hwpx` 파서 또는 한컴 COM 으로 PDF 변환 |
| 공문/DOCX | `pandoc <file>.docx -t gfm` (표 GFM 유지) |
| 엑셀(.xlsx) | 시트별 마크다운 표(머지셀 펼침) |

> HWP→PDF (한컴 COM, PowerShell) 예:
>
> ```powershell
> $h = New-Object -ComObject HWPFrame.HwpObject
> $h.RegisterModule("FilePathCheckDLL","SecurityModule")  # 보안 승인 모듈(설치본에 따라)
> $h.Open("C:\path\연구계획서.hwp")
> $h.SaveAs("C:\path\연구계획서.pdf","PDF")
> $h.Quit()
> ```
>
> 한컴 미설치·COM 차단 시: `pip install pyhwp` 후 `hwp5html --output out_dir 연구계획서.hwp`(표는 HTML 표로 보존) → HTML→md.

## 포맷(YAML/JSON) 노트

- 기본은 **YAML**(주석·한글 가독성·git diff). `structured.format: json` 이면 동일 데이터를 JSON 으로, `both` 면 둘 다 생성.
- JSON 생성은 YAML 정본을 파싱해 변환(`python -c "import yaml,json; json.dump(yaml.safe_load(open('KR_x.yaml',encoding='utf-8')), open('KR_x.json','w',encoding='utf-8'), ensure_ascii=False, indent=2)"`). 손으로 두 번 쓰지 않는다(정본=YAML).
- 숫자(금액·목표치·기간[주])는 **수치 타입**으로(쉼표·`천원` 단위표기 제거, 0 은 0). 판독 불가·해당없음은 `null`.
