# rnd-manpower-change — KR 과제 참여연구원 변경 인건비 재배분

한국선급(KR) 연구개발 과제에서 **참여연구원이 바뀔 때**(하차·신규투입·교체, 또는 참여기간·참여율 변경) **해당 연차의 총 인건비를 그대로 유지**하면서, 변경되지 않은 참여연구원의 계상률·계상인건비를 재배분해 **총액을 정확히 맞추는** 계산 스킬이다. 결과는 **변경안 문서**와 **새 참여연구자인건비 YAML 조각**으로만 떨어진다 — 스냅샷·이력은 건드리지 않는다.

> **분리 구도**: [`/rnd-kr-extract`](../rnd-kr-extract/SKILL.md)(발췌·스냅샷) → **`rnd-manpower-change`(참여연구원 변경 재배분안 계산)** → [`/rnd-kr-history`](../rnd-kr-history/SKILL.md)(이력 적재). 이 스킬은 변경안만 만든다. 확정되면 사용자가 스냅샷에 반영(extract)하고 이력으로 적재(history)한다.

## 핵심 원칙

- **총 인건비 고정(또는 명시적 변경)**: 변경 후 연차 인건비 합계 = 목표 총인건비. 목표는 (a) 인건비 변경 없음 → 현재 `예산.비목별[].직접비.인건비`, (b) 인건비 변경 있음 → 사용자가 준 새 값. **이 둘을 가장 먼저 AskUserQuestion 으로 가른다.**
- **12개월 환산**: 계상인건비 = `(급여총액/12) × 참여기간_개월 × (계상률/100)`(천원). 하차·신규투입의 부분기간을 개월수로 정확히 반영한다(스냅샷 8-2 주석과 동일 공식).
- **조정은 변경되지 않은 연구원이 흡수**: 삭제/추가/변경분으로 생긴 차액(끝수 포함)은 **변경되지 않은 참여연구원 1~2명**이 계상률 조정으로 흡수한다. 몇 명을 쓸지·누구인지 AskUserQuestion 으로 받는다.
- **정수·소수점 회피**: 계상인건비는 **천원 단위 정수**. 배분에서 생기는 **끝수(잔차)는 조정연구원 1명에게 가산**해 총액을 정확히 맞춘다. 계상률은 역산값(소수 허용).
- **rerp(회사 연구개발 관리 시스템) 계산 규칙 준수**: ① **월급여 = 급여총액/12 천원 절삭**(평균급여 — 단축근무·단기휴가 시에만 참여자별 `월급여` override) ② **월 참여율 = 월 인건비/월급여×100, 소수점 3자리에서 0 초과 시 올림**(소수 2자리, 표시용) ③ **최종 계상률(공문 표기) = 계상인건비/총 지급한도(월급여×개월)×100, 소수점 3자리에서 올림**(월 참여율 평균 방식 아님) ④ **참여율→인건비는 천원 절삭 후, 최종 계상률이 사용자가 요청한 참여율을 넘지 않도록 −1천원 보정**(요청률 초과 금지) ⑤ **월별 인건비 = 계상인건비를 참여기간으로 나눠 앞월 천단위 올림, 마지막 월 잔액**(월별 합 = 계상인건비 정확 일치) ⑥ 중도 변경은 `변경적용월`(YYYY-MM) — 그 월 이전은 전 월별 금액 유지, **나머지 개월만** 신규 계상률로 계산.
- **산출 정보 2종**: **① 공문용 = 참여율 정보**(전→후 계상률·변경 적용기간 — 변경안 .md/.pdf 와 YAML `공문용_참여율` 블록) · **② rerp용 = 월별인건비**(참여자별 월별 전/후 + `월별_소계` — rerp 월별 지급 관리·대사값, 비교 YAML 에만). **참여연구자별 변경 적용기간(언제부터~언제까지)** 을 월별 전/후 차이에서 도출해 문서·YAML 에 기록한다.
- **참여율 하한 10%**: 조정·신규·변경 후 어떤 참여연구원도 계상률 10% 미만이 되지 않게 한다(기본값, `--floor` 로 변경). 위반하면 `ok=false` — 조정 인원을 늘리거나 변경안을 고치도록 재질의한다.
- **계산은 결정론 스크립트**: 산술은 `scripts/manpower_calc.py` 가 전담(LLM 암산 금지). LLM 은 입력 수집·JSON 구성·결과 서술만 한다.

## 입력 · 전제

- **현재 스냅샷**: `RND_PROJECT\<과제이름>\<연차>\KR_<과제이름>.yaml`(`/rnd-kr-extract --format structured` 산출). 여기서 **현재 참여자**(`예산.참여연구자인건비[].참여자[]`: 성명·급여총액·참여기간_개월·계상률·계상인건비)와 **목표 인건비**(`예산.비목별[].직접비.인건비`)를 읽는다.
- 스냅샷이 없으면 먼저 `/rnd-kr-extract <입력> --format structured` 로 만들라고 안내한다.
- 한 연차를 대상으로 한다(보통 당해연도=참여자 표가 작성된 연차). 다연차는 연차별로 반복.
- **품의서(선택)**: 이 변경의 결재·승인 문서(품의서, PDF·이미지·HWP)가 있으면 `--품의서 <경로>` 로 준다. 그 문서를 **Read 로 직독**해 **시행일(효력발생일)** 을 뽑아 **작성일 기준일**로 쓴다(폴더명 `rev<NN>_<시행일>`·문서·JSON meta 가 시행일로 통일). 여러 날짜(기안일·결재일·시행일) 중 **시행일**을 취한다(문서에 시행일 없으면 결재일→기안일 순 대체하고 보고). PDF·이미지는 Read 직독, HWP 등은 텍스트/PDF 변환 후. 품의서 없으면 종전대로 오늘 날짜.

## 절차

> **경로 약어**: `proj_dir` = `RND_PROJECT\<과제이름>` · `year_dir` = `proj_dir\<연차>` · 스냅샷 = `year_dir\KR_<과제이름>.yaml` · `chg_base` = `year_dir\manpower_change` · `out_dir` = `chg_base\rev<NN>_<작성일>`(회차·날짜별 폴더, 이번 실행의 산출물 폴더) · `pend_root` = `RND_PROJECT\_pending`(전역 검토 큐) · `pend_dir` = `pend_root\<과제이름>\<연차>_인건비_rev<NN>_<작성일>`(out_dir 사본, 회차 폴더 통째).

> **흐름(3단계)**: **①현재 데이터 추출(스냅샷→scaffold)** → **②변경사항 반영(scaffold 편집)** → **③계산·문서·PDF 추출**. 각 단계가 단방향이라 ①(또는 입력 JSON)만 바꿔 다시 돌리면 ②③이 일관되게 갱신된다.

### 0. 입력 확정 · 회차/작성일 → out_dir

1. `$ARGUMENTS` 해석(`show`/`help` 면 출력 후 종료).
2. **스냅샷 결정**: 직접 경로 → `--project` → `RND_PROJECT\` 하위 `KR_*.yaml` 탐색(여럿이면 §AskUserQuestion). `test -f` 로 확인, 없으면 `/rnd-kr-extract` 안내.
3. **연차 결정**: `--year`, 없으면 `예산.참여연구자인건비[]` 에 `참여자` 가 있는 연차(보통 1개). 여럿이면 질의.
4. **회차·작성일 결정 → out_dir 확정**: **작성일 기준일 우선순위 = 품의서 시행일 > `--date` > `date +%Y-%m-%d`(오늘)**. `--품의서 <경로>`(또는 §0 질의로 받은 품의서 파일)가 있으면 그 파일을 **Read 로 직독**(PDF·이미지)해 **시행일(효력발생일)** 을 뽑아 작성일로 쓴다(기안일·결재일과 구분 — **시행일** 채택; 문서에 시행일 명시가 없으면 결재일→기안일 순 대체하고 그 사실을 보고). 품의서 없으면 `--date` 또는 오늘. 회차 = `--seq`, 없으면 `chg_base` 의 기존 `rev[0-9][0-9]_*` 폴더 수 + 1 을 2자리(`01`,`02`…)로. `out_dir = chg_base\rev<NN>_<작성일>` 를 만든다(`mkdir -p`) — 품의서가 있으면 폴더·문서·JSON meta 의 작성일이 모두 그 **시행일**로 통일된다.

### 1. ① 현재 데이터 추출 (스냅샷 → scaffold)

- 엔진이 스냅샷에서 해당 연차 **현재 참여자·목표인건비를 자동 추출**한다(손으로 옮겨적지 않음 — 오타 방지):
  ```bash
  python "${CLAUDE_SKILL_DIR}/scripts/manpower_calc.py" --extract "<스냅샷>" \
    --year "<연차>" --seq "<NN>" --date "<작성일>" \
    -o "<out_dir>/manpower_input_<연차>_rev<NN>.json"
  ```
  - 산출 scaffold: 참여자 전원(현재 급여총액·참여기간_개월·계상률·계상인건비·참여시작/종료) + 분류 모두 `고정`, 메타(과제·연차·목표_총인건비·회차·작성일) 자동 기입.
  - 참여자 `소계`·`비목별.직접비.인건비` 정합은 스냅샷 기준(불일치 시 보고). 추출된 현재값을 사용자에게 보여준 뒤 §2~§4 변경을 받는다.
- **history 부재 감지 → r0 초기화 트리거**: `<과제>\history\` 가 없으면, **변경안을 만들기 전에** `/rnd-kr-history init --project <과제>` 로 변경 *전* 스냅샷을 **r0 기준선**으로 먼저 초기화하도록 안내·실행한다(지금 스냅샷이 곧 변경 전 상태). 그래야 나중에 변경 후를 r1 으로 diff 할 수 있다.

### 2. ② 변경사항 — 인건비 변경 여부

- §AskUserQuestion: **이번 변경에 인건비(연차 총액)가 바뀌나?**
  - **변경 없음** → 목표_총인건비 = 추출된 현재 비목별 인건비(예: 1차년도 31425).
  - **변경 있음** → 새 총 인건비를 받는다(Other 직접 입력). scaffold 의 `목표_총인건비`·`인건비_변경` 을 갱신.

### 3. ② 변경사항 — 참여연구원 변경

- §AskUserQuestion(자유입력 위주)로 **누가 어떻게** 바뀌는지 받아 scaffold 참여자의 `분류`·`신규_*` 를 고친다. 핵심 3종:
  - **제외(하차)**: `분류:제외` + `신규_참여기간_개월`(단축 개월, 완전 하차면 0).
  - **추가(신규투입)**: 새 참여자 추가 — `분류:추가` + `신규_참여기간_개월` + **급여총액** + `신규_계상률`(≥하한) + `신규_참여시작`.
  - **변경(기간/참여율)**: `분류:변경` + 바뀐 `신규_참여기간_개월`/`신규_계상률`.
- 실제 급여총액(연봉+4대보험 기관부담+퇴직충당금 = 합계 A+B+C)이 스냅샷 계획값과 다르면 해당 참여자 `급여총액` 도 실제값으로 고친다.

### 4. ② 변경사항 — 조정 대상 선정

- §AskUserQuestion: **변경되지 않은 참여연구원 중 차액을 흡수할 인원**을 받는다 — **1명** 또는 **2명**(또는 직접 지정). 그 사람들의 `분류` 를 `조정` 으로.
- 나머지 변경되지 않은 연구원은 **고정**(현재값 유지). 조정 대상만 계상률이 바뀐다.

### 5. ③ 계산 (manpower_calc.py) — 금액은 한 번 더 계산(재검산)

1. §1 추출 scaffold(`out_dir\manpower_input_<연차>_rev<NN>.json`)에 §2~§4 변경(분류·신규_*·실제 급여·목표_총인건비)을 반영해 입력 JSON 을 완성한다(미변경자는 `고정` 유지). 분류 = 고정/조정/추가/**제외**/변경.
2. 실행 — **`--yaml-out`(전/후 비교 데이터) + `--md-out`(변경안 문서)을 한 번에** 생성(둘 다 같은 계산 결과에서 나와 100% 일치):
   ```bash
   python "${CLAUDE_SKILL_DIR}/scripts/manpower_calc.py" \
     "<out_dir>/manpower_input_<연차>_rev<NN>.json" \
     --yaml-out "<out_dir>/참여연구자인건비_<연차>_rev<NN>.yaml" \
     --md-out  "<out_dir>/rev안_<연차>_rev<NN>.md"
   ```
   - stdout = 결과 JSON(전/후 계상률·계상인건비·월계상액·참여기간·검증·경고). exit 0=ok, 2=검증 실패.
   - **금액 한 번 더 계산(2-pass 재검산)**: 엔진이 내부적으로 합계를 재합산하고 공식 구동 행(고정/추가/변경/제외)을 `(급여총액/12)×개월×계상률` 로 **재계산해 저장값과 대조**한다 → `검증.재검산_일치`. `false` 면 `ok=false`. **반드시 `검증.재검산_일치=true` 인지 확인 후** 산출물을 확정한다(불일치면 입력·로직 점검).
3. **검증 실패(`ok=false`)** 처리:
   - `총액_일치` / `재검산_일치 = false`: 합계·재합산이 목표와 다름 — 입력 점검 후 재실행.
   - `조정목표_음수아님=false`: 변경/고정 합이 목표 초과 — 변경안(추가 계상률·기간) 재검토.
   - `계상률_하한충족=false`: 조정 후 누군가 <10% — **조정 인원을 늘리거나**(§3 재질의) 추가연구원 계상률/기간을 낮춰 재실행.

### 6. ③ 산출물 — PDF 변환

> 변경안 .md 는 **엔진이 `--md-out` 으로 직접 생성**한다(YAML 과 동일 계산 데이터 기반 — 손으로 표를 쓰지 않는다). 제목은 `참여연구원 변경 현황`(1회만), 구성은 **① 개요(과제·연차·목표총인건비·인건비변경·참여율하한 — 작성일·조정대상·변경회차 행 없음) ② 변경 요약 ③ 변경 내역(전→후, 참여기간 = `YYYY-MM ~ YYYY-MM (N개월)`, 합계행)** 3절뿐 — 급여기준자료·월환산·검증·후속조치는 PDF 에 싣지 않는다. 표는 모두 가운데 정렬.

- **변경안 문서** `out_dir\rev안_<연차>_rev<NN>.md`: §4 의 `--md-out` 산출(편집 불필요).
- **변경안 PDF** `out_dir\rev안_<연차>_rev<NN>.pdf`(`--no-pdf` 면 생략):
   ```bash
   python "${CLAUDE_SKILL_DIR}/scripts/md2pdf.py" \
     "<out_dir>/rev안_<연차>_rev<NN>.md" --title "참여연구원 변경 현황"
   ```
   - 경로: pandoc(md→HTML, 한글 CSS) → 헤드리스 Edge/Chrome(HTML→PDF, 격리 프로필+타임아웃). 전제: pandoc·Edge/Chrome 설치(없으면 안내하고 .md 까지만).
- **참여연구자인건비 변경 전/후 비교 YAML** `out_dir\참여연구자인건비_<연차>_rev<NN>.yaml`: `--yaml-out` 산출. 머리에 **과제명·과제책임자**(헤더 주석 + `참여연구자인건비_변경비교.과제`/`.과제책임자`)·연차·단위·목표_총인건비, 소계 `{전, 후}` + **정보 2종** — **① 공문용 `공문용_참여율`**(참여자별 전→후 계상률·참여기간·**변경_적용기간**) · **② rerp용 월별인건비**(참여자별 `월별인건비: [{월, 계상, 참여율}]` — **변경 후 기준**(전/후 비교는 전/후 블록이 담당), **이번 회차에 금액이 바뀐 월엔 `# rev<NN> 변경` 주석**으로 몇 번째 변경에서 바뀌었는지 표시, 계상 합=계상인건비, 참여율=월 참여율 소수 3자리 올림 + 최하단 `월별_소계: [{월, 계상}]`). 머리에 `회차`·`작성일` 명기. 참여자별로 **역할**(`과제책임자`/`연구원`)·**급여총액(연봉)·월급여(급여총액/12 천원 절삭)** + **전/후 블록 함께**(참여기간_개월·계상률·계상인건비) + **참여기간 `YYYY-MM ~ YYYY-MM (N개월)`** + **`변경_적용기간`**(월별 전/후 금액이 달라진 언제부터~언제까지). 스냅샷 반영 시 **'후' 값** 사용, `status:제외` 제거.
- **계산 입력 JSON** `out_dir\manpower_input_<연차>_rev<NN>.json`: 재현·재계산용.

### 6.5 ③ 산출물 — pending 검토 큐 복사

- `--no-pending` 이 아니면 방금 만든 회차 폴더(`out_dir`)를 **통째로** 전역 검토 큐 `pend_dir`(= `RND_PROJECT\_pending\<과제>\<연차>_인건비_rev<NN>_<작성일>`)에 복사한다. **원본 `out_dir` 은 그대로 두고 사본만 큐에 올린다**(복사 전용 — 스냅샷·이력과 무관):
  ```bash
  python "${CLAUDE_SKILL_DIR}/scripts/to_pending.py" "<out_dir>"
  ```
  - 경로만으로 과제·연차·종류(인건비)·회차를 도출하므로 추가 인자 불필요. 같은 회차 재실행 시 큐 사본을 새로 만든다(스테일 파일 제거).
  - 검증 실패(`ok=false`)로 `out_dir` 산출물이 없으면 이 단계도 건너뛴다. 큐 위치를 바꾸려면 `--pending-root <경로>`.
  - 목적: 과제 무관하게 **미확정(검토 대기) 변경안**을 한곳(`_pending`)에 모아 훑어보기 위함(`_export` 관례와 짝).

- 결과 JSON 의 `검증`(총액 일치·조정목표·계상률 하한·**재검산 일치**)과 `경고`를 그대로 보고.
- 최종 보고: 과제·연차 · 변경 회차/작성일 · 목표총인건비(변경 여부) · 제외/추가/변경/조정 명단 · 전→후 총액 · 계상률 하한·재검산 충족 · `out_dir` 와 생성 파일(.md/.pdf/.yaml/.json) · **pending 검토 큐 사본 경로**(`pend_dir`, `--no-pending` 시 생략) · **이력 핸드오프 안내**(아래 §rnd-kr-history 연결).

## /rnd-kr-history 연결 (이력 핸드오프)

이 스킬은 **변경안만** 만든다. 스냅샷 반영·변경이력(rev) 적재는 **`/rnd-kr-history`** 가 전담한다. 보고 끝에 아래 절차를 **안내**한다(직접 스냅샷·이력을 고치지 않는다).

1. **(history 폴더 없으면) `/rnd-kr-history init` 먼저** — 변경 *전* 스냅샷을 **r0(기준선)** 로 초기화한다. 이걸 건너뛰고 스냅샷을 먼저 고치면 변경 전 상태가 사라져 diff 가 안 된다. **rnd-manpower-change 는 §1 추출에서 `<과제>\history\` 부재를 감지하면 이 `init` 을 먼저 안내·트리거**(현재 스냅샷=변경 전 상태가 r0 기준선이 됨).
2. **스냅샷 반영** — 변경안 확정 시 `참여연구자인건비_<연차>_rev<NN>.yaml` 을 스냅샷 `예산.참여연구자인건비` 에 반영하고 `/rnd-kr-extract --format structured` 로 재구조화(또는 해당 블록 교체). 인건비 변경이 있었으면 `비목별.직접비.인건비`·소계·간접비·총액도 함께 정합.
3. **r1 적재** — `/rnd-kr-history --project <과제> --type 협약변경|연차변경 --source rev안_<연차>_rev<NN>.pdf` 로 diff → **rev 적재**(추가=신규, 삭제=제외, 조정=참여율/인건비 변경, 변경사유는 history 질의). **품의서 시행일로 회차 폴더(`rev<NN>_<시행일>`)를 만들었으면 그 폴더명 날짜가 `/rnd-kr-history` 변경비교 모드에서 rev 발효일(`date`)로 자동 인식**되어 작성일=발효일=시행일이 일치한다(품의서를 이 단계에서 한 번만 주면 이력까지 계승; 필요 시 history 단계에서 `--품의서` 로 재확인 가능).

> 정본(값)의 출처는 발췌본·스냅샷, 이력(델타)은 `rnd-kr-history`. 회차 폴더(`rev<NN>_<작성일>`)는 변경안 산출물 보관용이지 이력 저장소가 아니다.

- **과제책임자**(선택, top-level 성명): 지정하면 그 참여자의 YAML `역할`이 `과제책임자`, 나머지는 `연구원`. KR-only 표이므로 KR 측 책임자 성명을 넣는다(주관기관 전체 PI 아님). 미지정이면 전원 `연구원`.
- **급여총액·월급여**: `급여총액`=연봉 기준 연간 총액(천원, 입력값). YAML 엔 `월급여`(=`급여총액/12`, **천원 절삭** — rerp 기준)가 함께 출력된다(엔진 자동, 입력 불필요). 단축근무·단기휴가로 평균급여가 달라질 때만 참여자별 `월급여`(천원 정수) override.
- **변경적용월·변경종료월**(선택, `변경`·`조정` 참여자): `"YYYY-MM"` — 중도·구간 참여율 변경. `변경적용월`만 주면 그 월부터 참여기간 끝까지, `변경종료월`도 주면 **[적용월, 종료월] 구간만**(예: 10월~12월) 계산하고 **구간 밖(앞·뒤)은 전 월별 금액 유지/복귀**. `변경` 은 구간을 신규 계상률로 재계산(요청 참여율 초과 금지 보장은 구간에 적용), **`조정` 은 흡수 총액에서 구간 밖 기지급을 뺀 '남은 금액'만 구간에 배분**(음수면 `조정구간_음수아님=false`). 둘 다 미지정 시 전체 기간 재계산/배분.
- **월별**(선택): 전(현재) 상태의 **실제 월별 지급액 리스트**(합=계상인건비, 길이=참여기간_개월). 지정 시 표준 배분 대신 이 실적으로 기지급 월을 보존 — 구간 변경이 누적된 **연쇄 변경**에서 필수(`--extract-prev` 가 자동 기입).
- **분류**: `고정`(미변경·미조정) · `조정`(미변경, 차액 흡수 1~2명) · `추가`(신규) · `제외`(하차/단축, `삭제`도 동일) · `변경`(기간·참여율). 출력엔 `삭제`도 `제외`로 통일 표기.
- `추가`는 `신규_참여기간_개월`·`신규_계상률` 필수. `제외`는 `신규_참여기간_개월`(완전 하차면 0). `변경`은 바뀐 항목만 `신규_*` 지정.
- **참여기간 표기**: `참여시작`·`참여종료`(`YYYY-MM`)를 주면 문서·YAML 의 참여기간이 `2026-04 ~ 2026-12 (9개월)` 처럼 **몇월~몇월** 로 나온다(권장 — 항상 넣기). 추가·후입자는 `신규_참여시작` 으로 후 시작월 지정(없으면 `참여시작`). 종료월 = 시작월 + 개월수 − 1 자동.
- 산식·끝수 처리·역산·검증·재검산·월기간·문서/YAML 산출은 `references/algorithm.md` 참조.

## DO

- **품의서가 있으면 그 시행일(효력발생일)을 작성일 기준**으로 쓴다(폴더 `rev<NN>_<시행일>`·문서·meta). 시행일은 기안일·결재일과 구분해 취하고, 품의서 없을 때만 `--date`/오늘 날짜.
- **인건비 변경 여부를 가장 먼저** 가른다(현재값 vs 새 총액). 그 값이 목표 총인건비.
- 삭제·추가는 **참여기간_개월**로 환산해 부분기간을 정확히 반영한다(12개월 환산).
- **rerp 계산 규칙을 지킨다**: 월급여=급여총액/12 **천원 절삭** · 월 참여율=월 인건비/월급여 **소수점 3자리 올림**(표시용) · **최종 계상률=계상인건비/총 지급한도(월급여×개월)의 소수 3자리 올림** · 참여율→인건비는 천원 절삭 후 **최종 계상률 ≤ 요청 참여율** 보장 · **월별 인건비·월 참여율**(앞월 천단위 올림·마지막 월 잔액, 합=계상인건비)을 YAML 에 기록 · 중도 변경은 `변경적용월`로 **나머지 개월만** 재계산.
- **참여연구자별 변경 적용기간(언제부터~언제까지)** 을 월별 전/후 차이에서 도출해 변경안 문서(§3 표)와 YAML(`변경_적용기간`)에 기록한다.
- 차액·끝수는 **변경되지 않은 연구원 1~2명**이 흡수. 계상인건비는 **천원 정수**, 끝수는 **조정연구원 1명에 가산**해 총액을 정확히 맞춘다.
- 조정·신규·변경 후 **모든 계상률 ≥10%** 인지 검증. 위반이면 조정 인원을 늘리도록 재질의.
- 산술은 **`manpower_calc.py`** 에 맡기고, 결과 JSON 의 `검증`·`경고`를 그대로 보고한다.
- **금액은 한 번 더 계산한다**: `검증.재검산_일치=true`(엔진 2-pass: 재합산 + 공식 재계산 대조)인지 확인한 뒤에만 산출물을 확정한다.
- 변경안 .md 는 **엔진이 `--md-out` 으로 직접 생성**(YAML 과 동일 데이터). 손으로 표를 쓰지 않는다. PDF 는 `md2pdf.py`(`--no-pdf` 면 생략). 문서는 제목 `참여연구원 변경 현황` + **3절(개요·변경요약·변경 내역, 참여기간 몇월~몇월, 표 가운데 정렬)** 만.
- 산출물은 **회차·날짜 폴더**(`rev<NN>_<작성일>`)에 모은다. 제외/하차는 `삭제` 가 아니라 **`제외`** 로 표기.
- 산출물 생성 뒤 **`to_pending.py <out_dir>` 로 회차 폴더를 전역 검토 큐(`_pending`)에 통째 복사**한다(`--no-pending` 면 생략). 원본 out_dir 은 건드리지 않는 **복사 전용** — 스냅샷·이력 반영과는 무관(그건 `/rnd-kr-history` 몫).
- 이력은 직접 적재하지 말고 **`/rnd-kr-history` 로 핸드오프**(r0 시드 → 스냅샷 반영 → r1 적재)를 보고 끝에 안내한다.

## DON'T

- **스냅샷·이력 파일을 직접 수정하지 않는다**(이 스킬은 변경안만 만든다). 정본 반영은 `/rnd-kr-extract`, 이력은 `/rnd-kr-history`.
- **총액을 흐트러뜨리지 않는다**: 후 합계 ≠ 목표면 산출하지 말고 재조정. 소수점 계상인건비를 만들지 않는다.
- **참여율 10% 미만을 방치하지 않는다**(경고만 하고 통과 금지 — `ok=false`).
- LLM 이 직접 암산해 표를 만들지 않는다(반드시 스크립트 결과 사용).
- `참여기간_개월`(도메인 값)을 연차·단계(계획축)와 혼동하지 않는다.

| 신규투입자 인건비가 과대 | 급여총액·개월·계상률 입력 오류 | 입력 JSON 의 `신규_*` 값 재확인(개월=해당 연차 내 실제 참여월) |
| 참여자 소계 ≠ 비목별 인건비 | 스냅샷 자체 불일치 | 먼저 `/rnd-kr-extract` 로 스냅샷 정합화 후 진행 |
| 인건비 변경인데 현재값으로 계산 | 1단계 질의 누락 | 반드시 §1 에서 인건비 변경 여부를 먼저 가른다 |
